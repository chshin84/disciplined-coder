# 읽기 위한 문서

이 파일은 사람이 읽을 문서의 제목 규칙과, 문서를 쓰고 고치는 절차(「마크다운 초안과 퇴고」)다. 조항의 근거는 디시플린코더 저장소의 `docs/domain-discipline.md` 에 조항 ID 로 있다.

사용자가 작업을 파악·정리하려고 마크다운·html·보고서·제안서·발표자료·README 를 만들라고 할 때와, Claude 가 다른 사람에게 보낼 글을 쓸 때 적용하라. 파일로 쓰는 작업 보고도 여기에 든다. 대화 답과 에이전트가 읽을 지시문(spec·plan·스킬·서브에이전트 프롬프트)에는 적용하지 마라. 기존 문서나 템플릿의 형식이 있으면 그 형식을 먼저 따르라.

- **`MD-FIRST`** — 이 파일이 맡는 .pptx·.docx·.hwp(x) 와 보고서·발표자료 .html 은 본문을 마크다운으로 먼저 쓰고 퇴고한 뒤 그 형식으로 옮겨라. 이미 있는 파일을 고칠 때도 고칠 곳을 마크다운으로 옮겨 고친 뒤 원본에 옮겨라. 마크다운 초안도 이 파일이 맡는 문서로 보고, 작업이 끝나면 지워라. 추출과 마커와 확인 절차는 아래 「마크다운 초안과 퇴고」가 정한다. 서식을 입힌 뒤에는 문장 하나를 고치는 비용이 커지기 때문이다.

## `TITLES` — 제목과 계층

문서와 발표자료의 이름을 정할 때 적용하라. 제목의 길이도 기존 문서나 템플릿의 형식을 먼저 따르라. 이 파일의 용어는 다음 뜻으로 쓴다.

| 용어 | 뜻 | 문서에서 | 슬라이드에서 |
|---|---|---|---|
| **목차** | 읽는 사람이 찾아갈 위치를 가리키는 개념 이름 | `#`·`##` 절 제목 | 제목 칸 위에 작게 넣은 절 이름 |
| **본문 제목** | 그 절이나 슬라이드의 결론을 전하는 제목 | 절 제목 바로 아래 첫 문장 | 슬라이드 제목 |
| **라벨** | 항목 하나를 가리키는 이름 | 불릿 라벨·표 머리 | 불릿 라벨·표 머리·차트 축과 범례 |

- **`TITLE-LAYERS`** — 목차는 결론과 수치 없는 개념 명사구로 쓰고 `###` 소제목은 두지 마라. 본문 제목의 형태는 `TITLE-CLAIM` 을 따르라. 한 페이지씩 넘겨 보는 HTML 은 슬라이드로 간주하라. 읽는 사람이 목차에서 찾을 내용을 고르게 하기 위해서다.
- **`TITLE-CLAIM`** — 본문 제목은 결론 하나로 써라. 슬라이드 제목은 수치 없는 명사구로 40자 안에 쓰고(예: '업무 생산효율이 16% 개선되었습니다' 대신 '업무 생산성의 개선'), 수치·기간·비교는 본문에 둬라. 문서의 본문 제목은 주어와 서술어를 갖춘 한 문장으로 써라. 40자를 넘거나 결론이 둘이면 슬라이드나 절을 나눠라. 결론이 없는 슬라이드나 절(절차, 목록, 부록)은 본문 제목을 개념 명사구로 둬라. 읽는 사람이 본문을 다 읽지 않아도 결론을 알게 하기 위해서다.

## 마크다운 초안과 퇴고

`MD-FIRST` 의 절차와, 문서를 쓰고 고칠 때 거치는 단계는 여기가 소유한다.

기계 검사는 금지어 알림 훅이다. 다른 프로젝트의 .md 문서를 Write·Edit 하거나 셸로 쓰면 훅이 금지 표현을 찾아 알리고, 메인 세션은 알림이 가리킨 줄만 고친다. 이 일의 이름은 '경고 수정'이고, '퇴고'는 렌즈 결과를 반영하는 일에만 쓴다.

쓴 모델이 같은 맥락에서 다시 보면 쓸 때 놓친 위반을 대부분 그대로 놓치므로, 무엇을 고칠지는 렌즈가 찾은 지적에서 시작한다. 렌즈를 언제 어느 카테고리로 실행하고 지적을 어떻게 반영하는지는 `lens-review` 「전달 문서」가 정한다.

훅은 .md 파일만 읽으므로 .html·.pptx·.docx·.hwp(x) 는 마크다운 초안에서 검사된다. .xlsx 와 대시보드·도구·앱 화면·랜딩 페이지 HTML, 시험 픽스처는 이 절차의 대상이 아니다.

**처음 만들 때.** 본문을 마크다운으로 임시 폴더에 쓰고 퇴고한 뒤 그 형식으로 옮겨라. 초안은 원본에 반영한 뒤 지워라. 다시 뽑는 비용이 거의 없어서, 남기면 낡은 사본만 생긴다. HTML 은 보고서와 발표자료만 대상이고, 남에게 보낼 HTML 메일 본문도 보고서로 본다.

**고칠 때.** 먼저 문서 전체를 마크다운 형식 그대로 명령으로 `.txt` 파일에 뽑아라(예: `markitdown 원본.pptx > 원본.txt`). 고칠 곳이 정해지지 않았으면 추가 자료의 핵심어와 수치로 이 파일을 검색해 고칠 페이지를 골라라. 추가 자료 때문에 결론이 바뀌면 읽는 범위를 줄이지 말고 전체를 읽어라.

그다음 고칠 페이지나 절만 명령으로 `.md` 파일에 옮겨라. 수정마다 위치를 백틱으로 감싼 마커 줄(예: `` `@슬라이드 3` ``)로 적고, 바꾸기 전 문장은 코드 블록에 두어라. 바꾼 문장은 그 아래에 Edit 로 써라. 백틱과 코드 블록 안은 기계 검사가 보지 않으므로, 바꾼 문장만 검사된다. HTML 주석(`<!-- -->`)은 검사 대상이라 마커로 쓰지 마라.

이어서 바꾼 용어와 수치를 `.txt` 에서 찾아 함께 맞춰라. 고치지 않은 문장의 위반은 고치지 말고 사용자에게 알려라. 마지막으로 마커대로 바꾼 문장만 원본에 옮기고, 원본을 다시 뽑아 처음 추출본과 비교해 의도한 곳만 달라졌는지 확인하라. 확인이 끝나면 임시 파일을 모두 지워라.

**예외.** 변환한 직후 최종본 검진에서 나온 지적도 고칠 때의 절차로 고쳐라. 사용자가 PDF 만 주고 고쳐 달라고 하면 원본(html·docx 등)이 있는지 먼저 묻고, 없으면 PDF 에서 뽑은 마크다운으로 문서를 다시 만들어 새 PDF 를 내라. 차트 라벨, SmartArt, 그림 속 글자, 일부 hwp 요소는 추출되지 않는다. 그런 곳은 직접 고치고 기계 검사를 거치지 않았다고 알려라. hwp 를 원본에 반영할 때 한글 프로그램을 COM 으로 써야 하면 `kw-doc-formats` 의 절차를 따라라.
