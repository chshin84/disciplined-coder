# managing-docs — 문서의 타입·수명·위치

이 스킬은 에이전트원칙에서 옮긴 문서 규칙이다. 조항의 근거는 디시플린코더 저장소의 `docs/domain-discipline.md` 에 조항 ID 로 있다.

## 문서 관리

문서를 만들거나 고칠 때 적용하라. 문서를 만들거나 고치기 전에 그 문서의 타입과 수명을 정하라. spec과 plan을 쓰는 방법은 superpowers가 소유하고, 아래 표는 spec과 plan의 수명과 표시 규칙만 정한다.

- **`DOC-TYPE`** — 문서를 만들거나 고치기 전에 아래 표에서 타입을 정하고, 진행 상태가 들어 있는지, 핸드오프인지, 코드와 인프라에서 도출할 수 있는지, 이 타입의 드리프트 가드(문서와 코드가 서로 다르면 실패하는 검사)가 있는지를 차례로 확인하라. 도출할 수 있으면 문서에 내용을 옮겨 적지 말고 원본인 코드와 인프라를 가리켜라. 가드가 없으면 사용자에게 추가를 권하라. 문서가 수명에 맞게 관리되게 하기 위해서다.
- **`MANAGED-BLOCK`** — 스크립트가 사용자 파일에 쓰는 자동 생성 구간은 BEGIN/END 마커로 감싸고, 몇 번 다시 만들어도 같은 결과가 나오게 그 구간만 다시 써라. 사용자가 쓴 내용은 마커 바깥에 둬라. 재생성이 사용자 내용을 덮지 않게 하기 위해서다.
- **`DOC-PLACE`** — 항상 필요한 규칙은 `CLAUDE.md`에 두고 `@import`로 실어라. 필요할 때만 여는 규칙은 스킬로 만들고, 특정 경로에서만 적용되는 규칙은 rules에 둬라. 규칙이 필요한 때에만 실리게 하기 위해서다.

### 문서 타입과 수명

문서의 보관 방법은 타입마다 다르다. 타입마다 무엇이 그 방법을 강제하는지는 프로젝트가 정한다. 그 프로젝트에 같은 구실을 하는 장치가 있는지 보고, 없으면 없다고 적어라. 기록 파일의 이름과 차수 표기는 `review-docs`가 소유한다.

| 타입 | 포함하는 것 | 노후 방지 방법 |
|---|---|---|
| **상태** (roadmap) | 진행 상태와 다음 단계 | 가능하면 도출하고, 못 하면 한 곳에만 적고 나머지는 링크하라 |
| **절차·계약** (operations·setup·contract) | 수행 방법과 스키마 계약 | 상태를 적지 말고 방법만 적어라 |
| **설계** (spec·plan) | 설계 근거 | spec은 배포된 뒤에도 지우지 말고, 대체된 spec에는 superseded를 표시하라. plan은 실행이 끝나 병합되면 git 보존 태그를 단 뒤 지워라. 과거 것은 보존만 하고 활용하지 마라 |
| **기록** (reviews) | 렌즈 실행 차수의 관찰과 지적 | 기록한 뒤 고치지 마라. 다룬 작업이 병합되면 git 보존 태그를 단 뒤 지우되, 차수 대조에 쓰는 최근 기록은 남겨라. 처분은 차수 사이 대조로 그때그때 도출하라 |
| **핸드오프** (HANDOFF-*) | 1회성 인계 | 소비되면 곧바로 지워라 |
| **맥락** (Claude 메모리) | 세션 간 결정과 맥락 | 그 PC에만 있다. 코드와 상충하면 코드를 따르라 |
| **규범·인덱스** (CLAUDE.md·문서 맵) | 문서의 위치와 작업 방법 | 포인터와 규칙만 적고 상태는 적지 마라 |

### 메모리와 문서 맵

메모리는 그 PC에만 있는 작업맥락 스크래치패드로 쓰고, 이슈와 백로그 트래킹에는 쓰지 마라. 문서 맵은 포인터만 두고 가능하면 도출로 대체하라. 새 문서를 만들기 전에 그 내용을 기존 문서에 넣을 수 있는지 먼저 확인하라.
플러그인과 마켓플레이스를 만들 때의 규칙은 `domain-plugin`이, 문서를 쓰거나 고친 뒤의 검진 절차는 `review-docs`가, README의 동선과 배지 판단은 `domain-readme`가 소유한다.

## 상황별로 더 읽을 파일

쓰는 문서의 종류에 따라 아래 파일을 더 읽어라.

- 사용자가 읽거나 남에게 전달할 문서(보고서·제안서·발표자료·README·.html·.pptx·.docx·.hwp(x), 파일로 쓰는 작업 보고)를 쓰거나 고치면 같은 폴더의 `references/reading-docs.md` 를 읽고 따르라.
- README 를 쓰거나 고치면 `domain-readme` 도 열어라.
- 플러그인·훅·사용자 설정 파일을 고치면 `domain-plugin` 을 열어라.
