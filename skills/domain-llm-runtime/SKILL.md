# domain-llm-runtime — 런타임 LLM 검증 호출자

제품이 **런타임에 LLM을 호출**하는 기능은 단독 콜로 끝내지 말고 **검증 레이어**를 코드에 구현한다.
리뷰어는 Claude Code 에이전트가 아니라 **제품 코드가 구현할 청사진**이다. 공통 방법(PREP → 독립 렌즈 →
메타 집계 → 라우팅)은 `agent-principles.md` 검증 레이어 절을 따른다.

## 리뷰어 선택 (리스크 비례)
리스크 점수는 다음 조건마다 1점을 더해 매긴다 — 외부를 호출하는가, LLM 컴포넌트가 들어가는가,
인터페이스 계약이 바뀌는가, 사람 승인이나 컴플라이언스가 걸리는가, 명세가 세 섹션 이상인가.

| 점수 | 리뷰어 | 메타 |
|---|---|---|
| 0–1 | 리뷰어를 붙이지 않고 비기능 체크리스트만 적용한다. | 리뷰어가 없으므로 집계도 없다. |
| 2–3 | `reviewer-grounding` 하나를 붙인다. | 리뷰어가 하나뿐이라 집계 단계를 두지 않는다. |
| 4–5 | `reviewer-grounding`과 `reviewer-fit`을 함께 붙인다. | 리뷰어가 둘 이상이므로 `meta-aggregate`로 집계한다. |

- `reviewer-grounding`의 "출처"는 여기서 **원래 요청과 제공된 맥락**이다.
- `reviewer-fit`는 다운스트림 계약을 본다. 스키마·형식은 **코드 validator를 먼저** 돌리고 실패 시에만 리뷰 콜(비용 절약).
- `meta-aggregate`는 여기서 **결정론적 파이썬 함수**로 구현한다(LLM 콜 아님).

## 조립
1차 콜을 받은 뒤 리스크에 따라 리뷰어 리뷰 콜을 병렬로 돌리고, `meta-aggregate`가 집계한다. 그다음
제품 코드가 `type` 값으로 행동을 정하는 표를 따라 재생성·폴백·통과를 결정한다. 렌즈는 등급을 매기지
않으므로 라우팅의 근거는 폐쇄 집합인 `type`이고, 그래서 이 결정은 결정론으로 남는다. 비기능 체크리스트는
단계가 아니라 호출 코드 전체가 항상 만족해야 할 속성으로 바깥을 감싼다.

**리뷰어는 한 번씩만 부른다.** 회차 수와 그 까닭은 `domain-docs`의 「한 번만 띄우는 리뷰어의 규율」이
소유하므로 여기서 다시 정하지 않는다.

**리뷰어의 지적을 로그로 남기지 않는다.** 여기서 `reviewer-grounding`의 출처는 사용자 요청과 제공된
맥락이고, 계약은 그 출처를 근거로 인용하라고 요구한다. 그래서 지적을 그대로 남기면 **사용자 입력이 로그로
복제된다.** `SECRETS`가 금지하는 일이다. 리뷰 콜이 무엇을 걸러 냈는지 재려면 개인정보를 뺀 집계값
(어느 `type`이 몇 건 나왔는지 같은 것)만 남긴다.

**렌즈끼리 볼 것을 나눠 주지 않는다.** 여기서는 `grounding`이 외부 사실의 근거를 보고 `fit`이 양식과
계약을 보므로 원래 보는 것이 갈려 있어, 서로의 몫을 빼라고 적어 줘도 빠지는 것이 없다. 두었다가 뺀
경위와 근거는 `domain-spec-review`의 같은 이름 문단이 소유한다.

**리뷰를 반영한 뒤 다시 리뷰하지는 않는다** — 그 반복은 spec·plan 리뷰에만 둔다. 여기서 도는 것은
1차 출력을 다시 만드는 재생성이며 그것과는 다른 일이다.

## 비기능 체크리스트 (런타임 전용 — 코드 설계도)
이건 리뷰어가 아니고 LLM 콜도 아니다. 호출 코드가 갖춰야 할 요건이며, 구현 시 코드 가드와 그것을
검증하는 테스트로 확정한다. 결정론적이라 정적 점검·테스트로 검증한다.

각 항목에 붙은 등급은 **이 문서가 미리 박아 둔 고정값**이지 리뷰어가 매기는 값이 아니다. 그래서
렌즈에서 등급을 걷어낸 것과 무관하게 그대로 둔다 — 고정값에는 부풀림 문제가 없다.
- **외부 호출에는 timeout을 건다** — 걸지 않으면 무한히 대기한다(critical).
- **재시도는 지수 백오프로 한다** — 일시 실패와 레이트리밋에 대비한다(major).
- **빈 응답과 실패 응답에 None 가드를 둔다** — 실제 SDK는 빈 결과에 None을 돌려줄 수 있으므로 `x or {}`로 AttributeError를 막는다(major).
- **에러는 호출자가 처리할 수 있는 구조로 돌려준다** — 문자열 하나로 뭉개지 않는다(major).
- **비용과 토큰에 상한을 둔다** — 입력과 출력 토큰 한도, 그리고 재시도 횟수 상한을 정한다(major).
- **요청과 지연과 토큰과 실패율을 로깅한다** — 재지 않으면 개선할 수 없다(`MEASURE-FIRST`, major).
- **비가역이거나 위험이 큰 액션에는 사람 승인을 건다** — 컴플라이언스 접점이면 critical이고, 아니면 정책에 따른다.
- **프롬프트와 로그에 비밀과 개인정보를 남기지 않는다**(`SECRETS`).

누락 항목은 그 항목에 붙은 등급대로 처리한다(critical은 머지와 배포를 차단한다).

## 비용
리뷰 콜은 추가 비용·지연이다. 리스크에 비례해서만 더한다. 결정론으로 검증 가능한 것(스키마·정규식)은
코드로 먼저 검증한다. 재생성을 강제하는 `type`이 무엇인지는 제품이 자기 도메인에 맞게 정하고, 그 표를
코드에 둔다.
