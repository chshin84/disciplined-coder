# domain-llm-runtime — 런타임 LLM 검증 호출자

제품이 런타임에 LLM을 호출하는 기능은 단독 콜로 끝내지 말고 검증을 코드에 구현한다. 렌즈는 Claude Code 에이전트가 아니라 제품 코드가 구현할 청사진이다. 검증을 더하라는 원칙은 `agent-principles.md`의 「검증」 절에 있고, 방법은 이 문서가 정한다.

## 렌즈 선택
호출 종류로 정한다. 종류마다 걸 렌즈가 아래 표에 고정돼 있고, 회차마다 다시 판단하지 않는다. 점수를 매기면 매기는 사람마다 값이 달라져 같은 호출에 다른 렌즈가 걸린다.

| 호출 종류 | 무엇으로 가리나 | 걸 렌즈 |
|---|---|---|
| 사용자에게 그대로 보이는 출력 | 사람이 읽는 문장이나 답변을 그대로 낸다 | `lens-grounding` |
| 다운스트림이 파싱하는 출력 | 다른 코드가 형식을 믿고 읽는다 | `lens-fit` |
| 둘 다인 출력 | 사람도 읽고 코드도 파싱한다 | `lens-grounding`, `lens-fit` |
| 비밀이나 개인정보가 닿는 출력 | 키·토큰·개인정보가 입력이나 출력에 있다 | `lens-grounding`, `lens-fit` |
| 위 어디에도 안 걸리는 호출 | 그 밖 | 렌즈를 붙이지 않고 비기능 체크리스트만 적용한다 |

렌즈가 둘이면 `meta-aggregate`로 집계하고 하나면 집계 단계를 두지 않는다.

- `lens-grounding`의 "출처"는 여기서 원래 요청과 제공된 맥락이다.
- `lens-fit`는 다운스트림 계약을 본다. 스키마와 형식은 코드 validator를 먼저 돌리고 실패했을 때만 리뷰 콜을 쓴다. 이것이 `domain-docs`의 「판단 앞에 기계를 세운다」가 이 절차에 걸린 꼴이다.

## 조립
1차 콜을 받은 뒤 리스크에 따라 렌즈 리뷰 콜을 병렬로 돌리고, `meta-aggregate`가 집계한다. 그다음 제품 코드가 `type` 값으로 행동을 정하는 표를 따라 재생성·폴백·통과를 결정한다. 렌즈는 등급을 매기지 않으므로 라우팅의 근거는 폐쇄 집합인 `type`이다. 비기능 체크리스트는 단계가 아니라 호출 코드 전체가 항상 만족해야 할 속성이다.

렌즈는 한 번씩만 부른다. 띄우는 횟수는 `domain-docs`의 「한 번만 띄우는 렌즈의 규율」이 소유하므로 여기서 다시 정하지 않는다.

렌즈의 지적을 로그로 남기지 않는다. 지적을 그대로 남기면 사용자 입력이 로그로 복제되며 `SECRETS`가 이를 금지한다. 리뷰 콜이 무엇을 걸러 냈는지 확인하려면 개인정보를 뺀 집계값(어느 `type`이 몇 건 나왔는지)만 남긴다.

렌즈끼리 볼 것을 나눠 주지 않는다. `grounding`이 외부 사실의 근거를 보고 `fit`이 양식과 계약을 보므로 원래 보는 것이 갈려 있다. 근거는 `domain-spec-review`의 같은 이름 문단이 소유한다.

리뷰를 반영한 뒤 다시 리뷰하지는 않는다. 그 반복은 spec·plan 리뷰에만 둔다. 여기서 도는 것은 1차 출력을 다시 만드는 재생성이다.

## 비기능 체크리스트 (런타임 전용 — 코드 설계도)
렌즈가 아니고 LLM 콜도 아니다. 호출 코드가 갖춰야 할 요건이며, 코드 가드와 그것을 검증하는 테스트로 확정한다. 각 항목의 등급은 이 문서가 미리 정한 고정값이지 렌즈가 매기는 값이 아니다.

- 외부 호출에는 timeout을 건다. 걸지 않으면 무한히 대기한다(critical).
- 재시도는 지수 백오프로 한다. 일시 실패와 레이트리밋에 대비한다(major).
- 빈 응답과 실패 응답에 None 가드를 둔다. 실제 SDK는 빈 결과에 None을 돌려줄 수 있으므로 `x or {}`로 AttributeError를 막는다(major).
- 에러는 호출자가 처리할 수 있는 구조로 돌려준다. 문자열 하나로 뭉개지 않는다(major).
- 비용과 토큰에 상한을 둔다. 입력과 출력 토큰 한도, 그리고 재시도 횟수 상한을 정한다(major).
- 요청과 지연과 토큰과 실패율을 로깅한다. 측정하지 않으면 개선할 수 없다(`MEASURE-FIRST`, major).
- 비가역이거나 위험이 큰 액션에는 사람 승인을 건다. 컴플라이언스 접점이면 critical이고, 아니면 정책에 따른다.
- 프롬프트와 로그에 비밀과 개인정보를 남기지 않는다(`SECRETS`).

누락 항목은 그 항목에 붙은 등급대로 처리하며, critical은 머지와 배포를 차단한다.

## 비용
리뷰 콜은 추가 비용과 지연을 낳으므로 리스크에 비례해서만 더한다. 결정론으로 검증할 수 있는 스키마와 정규식은 코드로 먼저 검증한다. 재생성을 강제하는 `type`이 무엇인지는 제품이 자기 도메인에 맞게 정하고 그 표를 코드에 둔다.
