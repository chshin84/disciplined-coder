# nested-orchestration — 3층 병렬 오케스트레이션 (방법 SSOT)

`agent-principles.md`의 「병렬 오케스트레이션」 절이 트리거이고, 여기가 방법의 SSOT다. 기존 스킬을 재구현하지 않고 조합한다.

## 라우팅 — 3층과 2층의 갈림
독립적인 작업 단위가 둘 이상일 때 갈래는 둘이다.

- 각 단위가 자기 계획·리뷰 루프를 갖지 않는 **단일 태스크**이면 `dispatching-parallel-agents`(2층)로 가고 여기서 끝낸다.
- 각 단위가 자기 계획·구현·리뷰 루프를 갖춘 **멀티태스크 플랜**이면 3층을 쓴다. 3층만이 N개 SDD 루프를 각자 격리 컨텍스트에서 동시에 돌린다.

## 흐름 — 파이프라인 세 단계
스펙을 하나씩 잠그고 잠기는 즉시 팬아웃한다.

1. **L1(메인, 사람과 함께)** — 스펙을 하나씩 `brainstorming`으로 잠근다. 잠기는 즉시 워크트리를 만들고(`using-git-worktrees`, 또는 `Agent`의 `isolation:'worktree'`) L2를 백그라운드로 디스패치한다. 그 사이 L1은 다음 스펙을 계속 브레인스토밍한다.
2. **L2(자율 서브오케스트레이터, 사람 대화 불가)** — 잠긴 스펙으로 `writing-plans` 다음 `subagent-driven-development`를 자기 워크트리에서 실행하고, 그 SDD 루프가 L3(구현자·렌즈)를 띄운다. 검증은 세 국면에 나눠 건다. 스펙 국면은 L1이 `domain-spec-review`로 이미 마쳤고, 플랜 국면은 L2가 자율로 `domain-spec-review`를 돌려 발견을 🔴와 고칠 것으로 가르고 고칠 것까지 반영하며, 실행 국면은 SDD 태스크 렌즈와 리스크 비례 `lens-*`가 맡는다. spec·plan 리뷰에는 `accept`나 `regenerate` 같은 결정 값이 없으므로 L2는 그 값을 지어내지 않는다. 셋 가운데 하나라도 나오면 아래 BLOCKED로 L1에 올려 보낸다. 🔴가 나왔을 때, 렌즈끼리 같은 지점을 두고 반대로 판정했을 때, 리스크상 필요한 차원을 아무도 안 봤을 때다.
3. **L1 통합** — L2들의 완료 통지를 받아 리포트를 취합하고, 소유권을 기계로 검증한 뒤 병합하고 최종 브랜치 리뷰를 돌린다. 규모가 크면 통합 자체를 별도 서브에이전트에 위임한다.

## L2 디스패치 템플릿 — 여섯 블록
L2는 자기 부모인 L1 외 누구와도 대화할 수 없으므로 프롬프트는 자기완결이어야 한다. L2는 서브오케스트레이터를, L3는 구현자와 렌즈를 가리킨다.

1. **역할 선언** — "너는 자율 서브오케스트레이터다. 나와 추가 왕복 없이 스펙을 완결하고 브랜치까지 만든다. 너는 격리된 git 워크트리에 있다."
2. **임무** — 스펙 경로가 SSOT임을 밝히고 무엇을 산출할지 열거한다.
3. **구간 소유권(엄수)** — 소유하는 파일과 디렉터리 경로를 적고, 다른 워크스트림이 소유한 파일은 손대지 못하게 명시적으로 금지한다.
4. **방식(TDD + 3층)** — 구현자가 구현하되 같은 파일은 순차로 편집하고, 프로젝트 테스트 규약을 따른다. 읽기 전용 렌즈 서브에이전트가 diff를 읽고 발견을 돌려주면 L2가 고친다. 렌즈에 줄 출처는 그 워크스트림의 스펙과 바뀐 파일과 프로젝트 테스트 규약이다. 리스크에 비례해 렌즈를 고른다. SDD 태스크 렌즈를 쓰고, 필요하면 `lens-grounding`과 `lens-adversarial`을 더한다. 렌즈를 띄우기 전에 `dispatching-lenses`의 「렌즈에게 정본을 알리는 법」을 읽는다.
5. **주입 컨텍스트** — 그 도메인에서 이미 겪은 함정을 함께 넣어 같은 것을 다시 발견하지 않게 한다.
6. **산출 계약(브랜치까지만 — 머지·배포·main push 금지)** — 상세는 리포트 파일에 쓰고(변경 파일과 테스트 최종 결과와 발행 스키마 실제 모양과 스펙 이탈과 브랜치명을 담는다), L1으로 리턴하는 것은 상태와 블로커와 한 줄 요약과 리포트 경로뿐이다. 리포트는 프로젝트 밖 스크래치의 워크스트림별 고유 경로(예: `report-<workstream>.md`)에 쓰고 병합될 브랜치에는 커밋하지 않는다. 고정 경로로 커밋하면 워크스트림끼리 병합 충돌이 난다. 리포트를 프로젝트 밖 스크래치에 두는 이유는 둘이다 — 병합될 브랜치에 섞이지 않고, 프로젝트 안 `.md`에만 뜨는 문서 넛지가 리포트마다 뜨지 않는다.

## 사람 대화 불가 — BLOCKED와 재개
L2가 사람 결정(🔴)에 부딪히면 그 지점에서 조기 종료하고 상태 `BLOCKED`와 질문을 리턴한다. 지금까지의 커밋은 브랜치에 남긴다. 추측으로 지나가지 않는다.

L1이 그 질문을 사용자에게 알린다. 답이 오면 L1은 정지된 L2를 되살리지 않고, 답을 스펙에 접어 넣어 그 워크트리에 새 L2를 재디스패치한다. 재디스패치 프롬프트에는 여섯 블록에 더해 이어받을 브랜치명과 앞선 L2의 리포트 경로를 넣는다.

잔존 위험이 하나 남는다. BLOCKED를 올려 보내라는 것은 프롬프트 넛지이지 하드 컨트롤이 아니다. L2가 🔴를 못 알아채고 추측하면 완결된 브랜치까지 가서야 L1이 본다. 최종 방벽은 L1의 통합검증과 최종 브랜치 리뷰다.

## 가드레일 (FAIL-LOUD)
- **구간 소유권 강제** — L1은 취합 때 각 브랜치의 변경 파일 집합(`git diff --name-only base..branch`)을 구한 뒤 브랜치를 둘씩 짝지어 모든 쌍의 교집합을 확인한다. 모든 쌍이 비어 있으면 병합해도 안전하고, 한 쌍이라도 비어 있지 않으면 병합 전에 멈추고 알린다.
- **크래시와 멈춤에서 되살리기** — L1은 디스패치한 워크스트림을 아직 안 끝난 목록으로 대화 안에 들고 있다가, 완료 통지가 안 오는 L2는 CLI 드릴인으로 생사를 확인하고 죽었으면 마지막 커밋 위에서 재디스패치한다. 타임아웃과 헬스체크 툴링이 없어 L1의 주의에 의존한다.
- **비용** — L2마다 컨텍스트 재확립과 에이전트 팬아웃이 N배 오버헤드다. 얻는 것은 실행 시간 단축과 컨텍스트 격리다. 실측으로 사소한 워크스트림 하나당 약 40k 토큰이 든다.

## 관측성
수동 `Agent` 중첩은 `/workflows` 집계 대시보드에 뜨지 않는다. 대신 CLI가 서브에이전트를 표시하고 더블클릭으로 각 L2의 라이브 세션에 드릴인된다. 집계 대시보드와 메트릭은 볼 수 없고, 어떤 워크트리가 어느 L2에 배정됐는지도 화면에 나오지 않는다.

## 재구현 금지 (SSOT 포인터)
아이디어에서 스펙까지는 `brainstorming`, 계획은 `writing-plans`, 실행 루프는 `subagent-driven-development`, 병렬 디스패치 메커니즘은 `dispatching-parallel-agents`, 워크트리 격리는 `using-git-worktrees`, 리뷰 렌즈는 `lens-*`가 소유한다.

## 한계
3층은 조율 층을 얹으므로 멀티태스크 플랜에만 값을 한다. BLOCKED 정직성과 소유권 강제는 스파이크에서 검증됐으나 크래시 복구와 대형 워크스트림은 아직 미검증이다.

**비목표** — `Workflow` 결정론 버전과 집계 UI 대시보드와 영속되는 오케스트레이션 상태 문서는 만들지 않는다. 인플라이트 상태는 세션 대화 상태로만 든다. 진행 상태를 문서에 적어야 하면 spec 의 「검증 상태」를 쓴다. L4 이상 더 깊은 중첩도 다루지 않는다.
