# 대응표 — domains-index.md

원문의 각 항목이 새 문서 어디로 갔는지, 지웠다면 왜 지웠는지 남긴다.
'지움' 항목과 빈칸이 사람이 검토할 대상이다.

세 번째 칸의 값은 `옮김`, `합침`, `**지움**` 셋 중 하나이며 지움에는 반드시 근거를 붙인다.

| 원문 항목 | 새 문서 위치 | 처리와 근거 |
|---|---|---|
| H1 `# 개발 대상(도메인) 참고서 — 인덱스` | H1 `# Domain Reference Index` | 옮김 — 이 제목이 유일 문자열로 `test_codex_scaffold.sh:133`의 가드가 문다 |
| 서문 — 개발 대상에 따라 "마땅히 그래야 하는 것 / 그랬으면 하는 것"이 있다 | 서문 첫 문장 | 옮김 — 처음엔 뒤쪽 층위("그랬으면 하는 것")를 빠뜨려 필수 한 층위로 뭉갰다. 리뷰가 잡아 `ought to be` / `would like it to be` 두 층위로 복원했다. '사용' 절의 대응 문장도 같이 고쳤다 |
| 서문 — 설계/계획 단계에서 참고서를 확인해 명세에 반영한다(1순위), 못 담으면 개발 단계에서 고려한다(폴백) | 서문 첫 문단 | 옮김 |
| 서문 — 이 파일은 목차일 뿐이고 상세는 각 스킬에 있다(온디맨드) | 서문 첫 문단 끝 | 옮김 |
| 표 헤더 (도메인 · 언제 · 적용 시점 · 참조 스킬) | 표 헤더 (Domain · Trigger · When it applies · Caller skill) | 옮김 |
| 행 — 문서 관리 / 문서 작성·구조화(Claude Code 핵심 — 문서 to 문서) / 설계·개발 / `domain-docs` | 표 첫 행 | 옮김 — 참조 스킬 이름은 파일명이라 그대로 둔다 |
| 행 — 플러그인 관리 / CC 플러그인·마켓플레이스 제작 / 설계·개발 / `domain-plugin` | 표 둘째 행 | 옮김 |
| 행 — LLM 런타임 / 제품이 런타임에 LLM 호출 / **런타임** / `domain-llm-runtime` (+ `reviewer-*`·`meta-aggregate`) | 표 셋째 행 | 옮김 |
| 절 제목 `## 사용` | `## How to use this` | 옮김 |
| 사용 — 설계/계획 시: 대상이 해당 도메인이면 스킬을 열어 명세에 반영한다 | `How to use this` 첫 항목 | 옮김 |
| 사용 — 개발 시: 명세에 없으면 그때 참조한다 | `How to use this` 둘째 항목 | 옮김 |
| 사용 — 통증이 확인된 도메인만 등재한다, 새 도메인은 필요할 때 신설한다(YAGNI·측정 먼저), 빈 스텁을 두지 않는다 | `How to use this` 셋째 항목 | 옮김 — 이 파일 고유 규칙이라 그대로 남겼다 |
