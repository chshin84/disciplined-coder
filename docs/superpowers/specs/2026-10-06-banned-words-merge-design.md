# 금지어 목록 원본을 이 저장소로 옮기기 — 설계

이 설계는 2026-10-06에 썼다. 대상은 금지 표현 목록과 그 근거, 그리고 이 저장소에서 목록의 원본 위치를
가리키는 문서·검사·워크플로다. 원본은 지금 옛 저장소의 JSON 이다. 이 설계는 원본을 이 저장소의 마크다운 두
파일로 옮겨, 목록을 고치는 곳과 목록을 쓰는 곳을 하나로 만든다. 같은 날 렌즈 리뷰
(`docs/superpowers/reviews/2026-10-06-banned-words-merge-review.md`) 뒤에 다시 썼고, 무엇이 왜 바뀌었는지는
「리뷰가 바꾼 것」에 적는다.

## 용어

- **목록 파일:** 저장소 루트의 `korean-banned-words.md` 다. 훅이 파싱하고, `scaffold.sh` 가
  `~/.claude/disciplined-coder/` 에 복사하며, 관리블록이 그 사본을 `@import` 로 싣는다.
- **근거 파일:** 이 설계가 새로 만드는 `skills/lens-readability/banned-words-evidence.md` 다. 세션에 싣지 않는다.
- **편집 규칙 파일:** 이 설계가 새로 만드는 `.claude/rules/banned-words.md` 다. 목록 파일이나 근거 파일을 다룰
  때만 Claude Code 가 싣는다.
- **옛 저장소:** `KiwoomAX/korean-banned-words` 다. 지금의 원본이 있고, 마지막 커밋은 `5b02378` 이다.
- **kw-plugins:** 사내 플러그인 마켓플레이스 저장소 `KiwoomAX/kw-plugins` 다. 그 안의 `kw-control-tower`
  플러그인이 지금 목록 사본을 받아 간다. 이 저장소를 맡은 Claude 세션을 kw-plugins 세션이라 부른다.

## 바꾸는 이유

사용자는 관리 지점을 줄이려고 통합을 정했다(2026-10-05). 지금은 목록 한 항목을 고치면 옛 저장소에 PR 을 열고,
이 저장소의 `banned-words-sync.yml` 이 하루 한 번 생성물을 받아 다시 PR 을 연다. 고치는 PR 이 두 번이고
반영까지 최대 하루가 걸린다.

옛 저장소를 따로 둔 이유는 이 저장소와 kw-control-tower 가 같은 목록을 각자 받아 갔기 때문이다.
kw-plugins 세션은 2026-10-05에 kw-control-tower 가 이 플러그인을 필수 플러그인으로 포함하고 자기 받기
워크플로와 사본을 지운다고 답했다. 그러면 목록을 소비하는 저장소는 이 저장소 하나만 남는다.

같은 답에서 kw-plugins 세션은 kw-plugins 코드가 목록의 형식에 의존하지 않는다고 확인했다. 남은 의존은 옛
공용 블록(`# BEGIN korean-banned-words` 와 `@kw-ax/korean-banned-words.md`)을 지우는 정규식 하나다. 이
저장소는 공용 블록을 만들지 않으므로 그 정규식과 충돌하지 않는다.

## JSON 을 버리는 이유

사용자는 2026-10-06에 원본을 JSON 대신 마크다운으로 두기로 정했다. JSON 과 `render.py`·`validate.py` 가 하던
일은 아래와 같고, 소비자가 하나로 줄면서 각 일이 필요 없어지거나 마크다운 검사로 대신할 수 있다.

| JSON 이 하던 일 | 이 설계에서 |
|---|---|
| 소비자 두 곳에 같은 생성물 배포 | 소비자가 하나라 필요 없다 |
| 어느 사본이 최신인지 가리는 버전 표시 | 필요 없다. 버전 표시를 읽는 `check_banned_words.sh` 44-45행은 지운다 |
| 근거를 세션에 싣지 않고 보관 | 근거 파일이 맡는다 |
| `validate.py` 의 형식·중복·제외어 검사 | 「검사」 절의 행 형식·제외어·중복·적용 대상 검사가 맡는다 |
| `render.py` 가 표와 "꺼 둔 항목" 줄을 함께 생성 | 사람이 둘을 고치고, 「검사」 절의 근거 대응 검사가 불일치를 잡는다 |

2026-10-06에 메인 세션이 측정한 크기는 목록 파일이 5,966자이고, 옮길 근거와 끈 사유가 약 1.06만 자다. 근거를
목록 파일에 함께 두면 세션마다 실리는 분량이 세 배 가까이 된다. 그래서 근거는 별도 파일에 둔다.

마크다운으로 바꾸면 표를 손으로 고치다 형식을 틀릴 수 있다. 훅의 awk 는 칸이 모자란 행을 소리 없이 버리고,
제외 칸 앞의 세로줄이 빠지면 그 행의 제외를 잃는다(`hooks/_banned_words.sh` 35·51행). 제외를 잃은 `판`
행은 `판정` 이 든 정상 문서를 모든 PC 에서 거부하게 만든다. 「검사」 절의 행 형식 검사가 이 실패를 잡는다.

## 설계

### 목록 파일

지금 `korean-banned-words.md` 의 금지 표현 표와 표로 적을 수 없는 규칙과 "꺼 둔 항목" 줄은 그대로 원본이
된다. 첫 줄 `# 한국어 금지어 목록` 도 그대로 둔다. `scripts/test_scaffold.sh` 42행이 그 줄로 사본이 실렸는지
확인하기 때문이다.

머리의 생성물 문장과 HTML 주석 세 줄(원본·다시 만들기·원본 버전)은 아래 안내로 바꾼다. 이 파일은 사본으로
모든 PC 에 실리므로, 사본을 고치지 말라는 표시와 원본 위치를 저장소 이름과 함께 적는다.

> 이 파일의 원본은 `chshin84/disciplined-coder` 저장소 루트의 `korean-banned-words.md` 다.
> `~/.claude/disciplined-coder/` 의 사본은 세션마다 원본으로 덮어쓰므로 사본을 고치지 않는다.
> 항목마다의 근거는 같은 저장소의 `skills/lens-readability/banned-words-evidence.md` 에 있다.

표 설명 문단의 "각 항목의 근거는 https://github.com/KiwoomAX/… 에 있다"는 근거 파일을 가리키게 고친다.
"꺼 둔 항목" 줄의 "왜 껐는지는 원본이 적는다"는 "근거 파일이 적는다"로 고친다.

표의 칸은 금지어·대체어·적용 대상·분류·제외 순서이고 그대로 둔다. 소비자가 위치로 읽는 칸은 아래와 같다.

- **훅:** `hooks/_banned_words.sh` 가 금지어·대체어·적용 대상·제외 칸을 읽는다.
- **측정 스크립트:** `scripts/check_banned_words.sh` 가 적용 대상 칸으로 검사할 행을 고른다.
- **보고서 검사:** writing-html-reports 의 `checks/common.py` 가 금지어·대체어·제외 칸을 읽고, 보이는 칸이 다섯
  미만인 행을 건너뛴다.

파일 위치와 칸 순서가 그대로이므로 훅과 스캐폴드(`_scaffold_common.sh`·`scaffold.sh`)와 `common.py` 는
고치지 않는다.

### 근거 파일

옛 저장소 JSON 의 `entries` 와 `rules` 에서 근거를 옮긴다. 금지어 항목은 항목마다 `##` 절을 하나 두고, 절
제목은 그 항목의 첫 금지어를 백틱으로 감싼 것이다(예: `` ## `재다` ``). 목록 파일의 행과 기계로 대응시키려고
첫 금지어를 제목으로 정했다. 2026-10-06 측정에서 첫 금지어는 항목끼리 겹치지 않는다.

절 본문에는 근거 종류(`user`·`measured`·`reasoned`)와 날짜와 원문 인용이나 측정 기록을 적는다. 끈 항목은 끈
사유와 측정 날짜·건수도 적는다. 사용자 원문 인용은 고쳐 쓰지 않는다.

표로 적을 수 없는 규칙의 근거는 규칙마다 `## 규칙:` 으로 시작하는 절 하나에 둔다. 규칙 불릿에는 기계로 대응시킬
짧은 이름이 없으므로, 규칙 절의 수와 목록 파일의 규칙 불릿 수가 같은지만 검사한다.

변환은 한 번만 한다. 변환 스크립트는 작업 폴더에서 실행하고 커밋하지 않는다.

근거 파일을 `skills/lens-readability/` 에 두는 이유는 `domain-korean.md` 「금지 표현의 근거」 절이 이미 그
디렉터리에서 금지 표현이 왜 생기는지를 다루기 때문이다. 근거 파일은 스킬이 열지 않으므로 세션 컨텍스트에
들어가지 않는다. 문서 타입은 기록이 아니라 설계 근거다. 항목을 고치면 근거 절도 함께 고치고, 그 대응은
「검사」 절이 강제한다.

근거 파일은 사용자 원문을 그대로 인용하므로 금지어와 대구를 포함한다. 그래서 대구 한도 검사
(`test_docs_drift.sh` 의 `ANTI_DOCS`)와 `check_banned_words.sh` 측정 대상에서 목록 파일과 함께 뺀다. 두 곳의
제외 사유 주석은 "생성물이라 고칠 수 없다"에서 "금지어와 대구를 이름이나 인용으로 적는다"로 고친다.

### 편집 규칙 파일

옛 저장소 `CLAUDE.md` 의 편집 규칙은 `.claude/rules/banned-words.md` 로 옮긴다. frontmatter 의 `paths` 에 목록
파일과 근거 파일을 적어, 그 파일을 다룰 때만 실리게 한다. 에이전트원칙 `DOC-PLACE` 가 특정 경로에서만
적용되는 규칙을 rules 에 두라고 정한다. 옮기는 규칙은 아래와 같다.

- **형식 계약:** `### 금지 표현` 제목과 칸 순서를 지키고, 칸은 뒤에만 추가하며, 첫 줄 제목을 바꾸지 않는다.
- **근거 함께 쓰기:** 행을 넣거나 끄거나 첫 금지어를 바꾸면 근거 파일의 절도 같은 커밋에서 고친다.
- **어간 적기:** 한글은 음절이 한 글자이므로 활용형마다 어간을 적고, 어간이 다른 말에 들어가면 제외 칸에 그 말을
  적는다.
- **넣기 전 측정:** 항목을 넣기 전에 실제 빈도와 거짓 검출을 센다.
- **기준선:** 적용 대상별 말뭉치에서 만자당 0.15 미만인 항목은 끈다.
- **user 항목:** 근거 종류가 `user` 인 항목은 빈도 때문에 끄지 않는다.
- **끄는 방법:** 끄는 항목은 표에서 빼 "꺼 둔 항목" 줄로 옮기고 근거 파일에 끈 사유를 적는다.
- **끄는 다른 사유:** 다른 항목과 검출이 겹치는 항목과 검토 뒤 기각한 후보도 같은 방법으로 끈다.
- **커밋 전 검사:** 목록 파일이나 근거 파일을 고치면 커밋 전에 저장소 `CLAUDE.md` 「변경 뒤 실행」 명령을 실행한다.

main 은 보호되지 않았고 플러그인은 main 커밋으로 배포되므로, CI 는 형식이 틀린 표가 배포되기 전에 그것을
멈추지 못한다. 사용자는 2026-10-06에 PR 강제나 브랜치 보호를 두지 않고 커밋 전 로컬 검사로 충분하다고 정했다.

`기대를 걸` 은 `user` 항목인데 `걸` 항목과 겹쳐 꺼져 있다. 위 규칙에서 빈도가 아닌 사유로 끄는 길이 열려 있으므로
이 항목과 규칙이 부딪치지 않는다.

옛 `CLAUDE.md` 의 렌더 순서와 `schema` 규칙은 생성 단계가 없어지므로 옮기지 않는다. 「이 저장소의 문서에도
목록이 적용된다」 절도 옮기지 않는다. 이 저장소의 문서에는 금지 표현 검사를 적용하지 않는다는 사용자
결정(2026-09-22)이 있다.

### 검사

`.github/workflows/banned-words-sync.yml` 을 지운다. `scripts/test_docs_drift.sh` 의 금지 표현 절은 지금 옛
저장소 이름과 받기 워크플로와 "생성물"이라는 말을 확인하는데, 이 확인을 지우고 아래 검사를 둔다. 검사는
`banned_parse` 가 내는 파일과 목록 파일의 원문을 대조한다.

- **행 형식:** 「금지 표현」 절에서 `` | ` `` 로 시작하는 줄 수가 `banned_parse` 의 출력 행 수와 같고, 그 줄마다
  세로줄 수가 머리행과 같다.
- **제외어:** 제외 칸의 낱말마다 같은 행의 금지어 하나 이상을 포함한다.
- **중복:** 한 금지어가 두 행에 나오지 않는다.
- **적용 대상:** 적용 대상 칸이 `답변과 산출물` 이나 `문서와 답변` 이다.
- **근거 대응:** 근거 파일의 백틱 제목 집합이 표의 첫 금지어와 "꺼 둔 항목" 줄 이름의 합집합과 같다.
- **규칙 대응:** 근거 파일의 `## 규칙:` 절 수가 목록 파일의 규칙 불릿 수와 같다.

이 검사는 「변경 뒤 실행」 명령이 로컬에서, `ci.yml` 이 push 와 PR 에서 실행한다.

### 원본 위치를 가리키는 문장

아래 문장이 옛 저장소나 받기 워크플로나 생성물이라는 성격을 전제한다. 각각 목록 파일과 근거 파일을 가리키게
고친다.

- `README.md` 3행의 "사내 저장소를 목록의 원본으로 가리킨다"
- `README.md` 41·80행의 금지 표현 목록 문단
- `skills/lens-readability/domain-korean.md` 「금지 표현의 근거」 첫 문단과 302행과 335행
- `skills/lens-fit/domain-discipline.md` `EDIT-DISCIPLINE` 절의 목록 파일 예시
- `hooks/doc_word_pretooluse.sh` 와 `hooks/_banned_words.sh` 의 머리 주석
- `hooks/_spec_marker.sh` 65-66행 `path_in_own_repo` 주석의 "표를 외부 저장소가 소유하고 하루 한 번 동기화"
- `scripts/check_banned_words.sh` 37행 주석과 44-45행 버전 표시 출력
- `scripts/test_docs_drift.sh` 855행 대구 한도 제외 주석

`EDIT-DISCIPLINE` 예시는 지우지 않고 사본 이야기로 바꾼다. 목록 파일은 여전히 머리에서 수정 방식을
선언하기 때문이다. `path_in_own_repo` 의 제외 결정은 유지한다. 이유 문장에서 동기화 이야기만 빼고, "표와
근거를 적는 문서는 그 말을 이름으로 불러야 한다"는 이유는 남긴다.

구현할 때 `grep -rn "KiwoomAX/korean-banned-words\|banned-words-sync\|생성물\|원본 저장소\|외부 저장소"` 로
이 목록을 다시 뽑아 빠진 줄을 더한다. `docs/superpowers/` 아래 설계·계획·리뷰 기록은 고치지 않는다.

### 옮기지 않는 파일

`render.py`·`validate.py`·`.github/workflows/validate.yml` 은 생성 단계가 없어지므로 옮기지 않는다.

`import-protocol.md` 도 옮기지 않는다. 옛 저장소 README 는 이 문서를 "아직 채택 전"인 공용 import 규약이라고
적는다. 이 저장소의 `scaffold.sh` 는 공용 블록을 지우고 자기 관리블록에서 목록을 싣는다. 그래서 메인 세션은 이

이력은 옮기지 않는다. 이전 커밋의 메시지에 옛 저장소와 `5b02378` 을 적는다.

### 이 저장소 밖의 일

사용자는 2026-10-06에 옛 저장소를 삭제하기로 정했고, 삭제는 사용자 지시에 따라 kw-plugins 세션이 맡는다.
삭제는 이 저장소의 이전 커밋이 main 에 들어간 뒤에 한다. 먼저 지우면 「확인 방법」의 이전 시점 확인을 할 수
없다. 이 저장소는 병합 뒤 커밋 해시를 kw-plugins 세션에 알리고, 그 알림이 삭제를 진행해도 된다는 신호다.

삭제하면 옛 저장소의 커밋 이력과 GitHub 의 URL 이 사라진다. 이 저장소의 리뷰 기록과 설계 문서에 남은 옛
저장소 링크는 깨지지만, 기록은 고치지 않는다. 항목마다의 근거는 근거 파일로 옮겨지므로 남는다.
`D:\projects\Structure\korean-banned-words` 의 로컬 복제본은 이 PC 에만 남는다.

writing-html-reports 의 `checks/common.py` 는 `~/.claude/kw-ax/korean-banned-words.md` 를 대체 경로로 읽는다.
kw-control-tower 가 사본을 지우면 이 경로는 쓰이지 않는다. 이 저장소는 그 경로를 고치지 않고 writing-html-reports
세션에 알린다.

이 PC의 Claude 메모리 `dc-banned-words-check-off` 는 결정의 이유로 "외부 저장소가 목록을 소유한다"를 든다.
결정 자체는 유지되므로, 이유 문장만 원본이 이 저장소로 옮겨졌다는 사실에 맞게 고친다.

## 확인 방법

- **이전 시점:** 병합 직전에 옛 저장소 HEAD 가 `5b02378` 이고, 그 `dist/korean-banned-words.md` 가 이전 전
  목록 파일과 같다.
- **표 불변:** 이전 전과 뒤의 목록 파일을 `git diff` 하면 머리 안내와 근거 위치 문장과 "꺼 둔 항목" 줄의 문구만
  바뀐다.
- **훅 파싱:** `banned_parse` 가 이전 전과 같은 행 수를 낸다.
- **근거 보존:** 근거 파일의 백틱 제목 수가 옛 JSON 의 항목 수와 같고, `## 규칙:` 절 수가 옛 JSON 의 규칙 수와
  같다.
- **남은 참조:** 위 grep 의 결과가 `docs/superpowers/` 기록과 근거 파일의 인용에만 남는다.
- **메모리:** `dc-banned-words-check-off` 의 이유 문장이 외부 저장소를 말하지 않는다.
- **계약 테스트:** 저장소 `CLAUDE.md` 「변경 뒤 실행」 명령이 `ALL PASS` 를 내고, `claude plugin validate ./`
  가 `version` 경고만 낸다.

## 리뷰가 바꾼 것

처음 문안은 파싱 검사 하나로 형식 오류를 잡는다고 적었다. lens-consistency 와 lens-adversarial 은 `banned_parse`
가 틀린 행을 소리 없이 버리므로 그 검사가 실패할 수 없다고 지적했고, 그래서 행 형식 검사를 원문 대조로 바꿨다.
`validate.py` 가 보던 제외어·중복·적용 대상 검사도 lens-adversarial 지적으로 옮겼다.

처음 문안은 편집 규칙을 근거 파일에 두었다. lens-fit 은 지시와 근거가 섞인다고, lens-adversarial 은 그 규칙이
세션에 실리지 않는다고 지적했다. 그래서 `DOC-PLACE` 대로 경로 한정 rules 파일로 옮겼다. 같은 자리에서
lens-consistency 지적대로 끄는 다른 사유와 어간·측정 규칙을 보탰다.

처음 문안은 버전 표시를 읽는 코드가 없다고 적었으나 `check_banned_words.sh` 가 읽고 있었다(렌즈 셋이 함께 지적).
생성물 문장을 지우기만 하던 안은 사본을 고치지 말라는 표시를 잃는다는 지적에 따라 원본 위치 안내로 바꿨다.
고칠 문장 목록, 근거 대응의 방향, 근거 파일의 검사 제외, 크기 수치의 단위도 렌즈 지적으로 고쳤다.
