# 정본과 스킬 영문 재작성 설계

## 배경 — 왜 지금 하는가

이 플러그인의 정본과 스킬은 한국어로 쓰여 있다. 한국어는 같은 내용을 담는 데 영어보다 서너 배의 토큰을
쓴다. 그리고 Anthropic이 Claude 5 세대용으로 Claude Code 시스템 프롬프트의 80% 이상을 제거하면서 코딩
평가에 측정 가능한 손실이 없었다고 밝혔다. 삭제 대상으로 명시적으로 지목한 것 중 하나가 "여러 곳에
중복으로 나타나는 반복된 규칙"이다. 출처는 Anthropic 블로그의 "The new rules of context engineering for
Claude 5 generation models"(`https://claude.com/blog/the-new-rules-of-context-engineering-for-claude-5-generation-models`)다.
**이 인용은 리뷰 단계에서 재확인되지 않았다** — 리뷰어 환경에 네트워크 접근이 없어 슬러그 실재와 수치를
검증하지 못했다. 이 스펙의 유일한 외부 근거이므로 미확인 상태임을 밝혀 둔다.

앞선 작업(상시 로드 레일 정리)이 같은 내용을 두 번 싣던 중복을 없앴다. 남은 지렛대는 내용 자체의 밀도다.

### 측정치 (2026-07-27, 문자 수 기준)

문자 수는 UTF-8 바이트가 아니라 JavaScript `String.length`(UTF-16 코드 단위)로 쟀다. frontmatter는
`---` 두 줄 사이의 내용 전체(`name`·`description` 키 포함)를 세었고, 본문은 그 뒤 전부다.

| 대상 | 문자수 | 언제 실리나 |
|---|---|---|
| `agent-principles.md` | 7,506 | 매 세션 |
| 스킬 열 개와 커맨드 다섯 개의 frontmatter | 2,276 | 매 세션 |
| `domains-index.md` | 659 | 매 세션 |
| 상시 로드 소계 | 10,441 | |
| 스킬 열 개와 커맨드 다섯 개의 본문 | 20,856 | 그 파일을 열 때만 |
| 전체 | 31,297 | |

상시 로드 소계에서 정본이 차지하는 비중은 71.9%다.

### 범위를 전체로 잡은 이유

초안은 상시 로드되는 것만 하려 했다. 토큰 이득이 거기 집중되기 때문이다. 그러나 그렇게 하면 **정본은
영어, 스킬 frontmatter는 영어, 스킬 본문은 한국어, 그 본문 안의 정본 참조는 영어인 네 겹 혼합**이 남는다.
스킬 본문의 영문화 이득은 토큰이 아니라 지시 준수율이지만, 혼합 상태를 오래 끄는 비용이 그보다 크다고
판단했다.

전체를 한 번에 하면 참조 수정도 대부분 재작성에 흡수된다. 아래 '참조를 함께 고친다'에서 세는 24곳 중
열 곳이 스킬 본문 안에 있는데, 그 파일들을 어차피 다시 쓰므로 별도 치환 작업이 아니게 된다.

## 이 스펙이 다루지 않는 것

- **`README.md`와 훅이 CLI에 띄우는 메시지**는 한국어로 유지한다. 사람이 읽는 문서다. 정본 인용이 있으면
  새 문장에 맞추되 언어는 바꾸지 않는다.
- **스펙과 계획 문서**(`docs/superpowers/`)도 한국어로 유지한다. 온디맨드라 토큰 이득이 없고, 사용자가
  읽고 승인하는 문서라 한국어가 승인 게이트의 정확도를 높인다.
- **커맨드 다섯 개의 본문**은 한국어로 유지한다. 본문이 곧 사용자에게 보이는 출력을 규정하는 지시문이라
  위 두 항목과 같은 부류다. frontmatter만 영문화한다. 이것은 시한부 유예가 아니라 항구 결정이다.
- **PC 전역 오답노트**(`~/.claude/disciplined-coder/solved_problems.md`)는 건드리지 않는다. 아래
  '오답노트 규약을 고친다'에서 근거를 밝힌다.

## 결정 (요구사항)

### 번역하지 않고 다시 쓴다

한국어 원문을 참고하되 문장 단위로 옮기지 않는다. 옮길 때마다 "이 문장이 필요한가"를 묻고 필요 없으면
버린다. 특히 Opus 5가 이미 기본으로 하는 것을 다시 지시하는 문장은 버린다.

**어떤 문장이 기본 거동과 겹치는지는 판단이며 근거가 공개돼 있지 않다.** 기본 시스템 프롬프트는 문서화되지
않고 버전마다 바뀐다. 그래서 이 판단의 안전장치는 아래 '대응표를 산출물로 남긴다'가 전담한다. 겹친다고
확신하지 못하면 남긴다.

원칙 ID(`CLEAR-COMM`·`EXPLICIT` 등)는 그대로 둔다. 이미 영문이고 다른 문서들이 그 ID로 참조한다.

### 대응표를 산출물로 남긴다

재작성의 진짜 검토 관문은 결과물 통독이 아니다. 10,441자를 diff 없이 처음부터 읽어 승인하는 것은
현실적이지 않고, 초안이 스킬 본문을 뺀 근거("사람이 검토할 수 없는 분량")와 같은 잣대를 자신에게 적용하지
않은 것이었다.

대신 파일마다 **대응표**를 산출한다. 원문의 각 문단이나 규칙이 새 문서의 어디로 갔는지, 또는 지웠다면
무엇을 왜 지웠는지를 한 줄씩 적는다. 사람이 검토할 것은 그 표의 **'지움' 항목과 빈칸**뿐이라 분량이
훨씬 작다. 의도적으로 지운 것은 근거와 함께 드러나고, 주의가 흩어져 조용히 빠진 문장은 빈칸으로 드러난다.

대응표는 `docs/superpowers/rewrite-map/<파일명>.md`에 남긴다. 이것은 작업 기록이므로 아카이브이며 상시
로드되지 않는다.

### 한글 원본을 남기지 않는다

영문 하나만 둔다. 두 벌을 두면 한쪽을 고치고 다른 쪽을 안 고치는 일이 반드시 생긴다(`SSOT`).

**되돌리기 비용을 정직하게 적는다.** git 히스토리는 '한국어 정본 전체로 되돌아가기'만 가능하게 하고,
실제로 필요한 복구인 '빠진 문장 하나 되살리기'는 재작성이라 diff로 도출되지 않는다. 그 복구를 가능하게
하는 것이 위의 대응표다. 대응표 없이는 이 결정이 사실상 단방향 문이다.

### 문체 규범은 한글로 유지한다

`CLEAR-COMM`이 다루는 대상이 한국어 산문이기 때문이다. 서술형 어미('~한다/~이다'), '미배선'·'확정?' 같은
명사 조각으로 끝맺는 습관, 'A vs B' 나열, 화살표로 문장을 대신하기 — 전부 한국어 문장에서만 판정할 수
있다. 영어로 옮기면 규칙이 가리키는 대상이 사라져 무력해진다.

**규칙 설명도, 좋은 예와 나쁜 예도 한국어로 쓴다.** 영문 문서 안에 한국어 블록이 인용으로 들어가는
형태가 된다. 이 비대칭을 그 자리에 한 줄로 밝힌다(`EXPLICIT`).

그 고지 자체가 다음 재작성에 똑같이 취약하다는 점은 인정한다. 아래 테스트가 규칙 설명 문장과 예시 문자열을
**둘 다** 확인해 부분 번역도 잡게 한다.

### 응답 언어를 명시한다

지금은 정본이 한국어라 응답 언어가 암묵적으로 정해진다. 영문이 되면 그 신호가 사라지므로 **"사용자에게는
한국어로 답한다"를 `CLEAR-COMM`에 명시한다.**

**이 지시가 이긴다는 보장은 없다.** 상시 로드 표면의 대부분이 영어가 되는데 한국어 지시는 한 줄과 문체
규범 블록뿐이다. 테스트는 그 문장이 정본에 있는지만 증명하고 응답이 실제로 한국어인지는 증명하지 못한다.
드리프트가 나면 사용자가 영어 답변을 받아 보고서야 드러난다. 이 한계를 안고 간다 — 자동 검증 수단을
만들지 않는다.

### 절차 절을 이름으로 부른다

정본의 절차 절이 `가`·`나`·`다`·`라`·`마`로 붙어 있고 다른 파일들이 `§가`·`§다`처럼 참조한다. 이는
`CLEAR-COMM`에 이미 들어간 "항목을 번호로 부르지 않는다"를 정본 스스로가 어기는 것이다.

| 지금 | 새 이름 |
|---|---|
| `가. 검증 레이어` | Verification Layer |
| `나. 설계 입력` | Design Inputs |
| `다. 오답노트` | Solved Log |
| `라. 문서·상태 위생` | Document Hygiene |
| `마. 병렬 오케스트레이션` | Parallel Orchestration |

이 변경이 영문화와 필연적으로 묶이지는 않는다. 다만 **범위를 전체로 잡으면서 비용이 거의 사라졌다** —
참조 24곳 중 열 곳이 어차피 다시 쓰는 스킬 본문 안에 있다. 남는 것은 재작성 대상이 아닌 파일들뿐이다.

### 참조를 함께 고친다

절 이름을 바꾸면 `§가`류 참조가 끊긴다. **git이 추적하는 파일 중 `docs/superpowers/`를 제외한 소재는
아래 24곳이다**(실측).

| 파일 | 곳 | 재작성 대상인가 |
|---|---|---|
| `skills/nested-orchestration/SKILL.md` | 4 | 그렇다 |
| `skills/domain-docs/SKILL.md` | 4 | 그렇다 |
| `skills/domain-spec-review/SKILL.md` | 1 | 그렇다 |
| `skills/domain-llm-runtime/SKILL.md` | 1 | 그렇다 |
| `scripts/test_scaffold.sh` | 7 | 아니다 |
| `docs/solved_problems.md` | 2 | 아니다 |
| `docs/DESIGN-NOTES.md` | 2 | 아니다 |
| `README.md` | 2 | 아니다 |
| `.claude/workflows/self-audit.js` | 1 | 아니다 |

**`.claude/workflows/self-audit.js`는 단순 치환이 되지 않는다.** 개별 절이 아니라 범위를 쓴다 —
`절차(§가~라)`. 영문 이름에는 가나다 순서가 없으므로 네 절을 나열하거나 표현을 바꾸는 판단이 필요하다.

`scripts/test_scaffold.sh`의 일곱 곳은 주석 셋과 `check` 라벨 셋과 `echo` 라벨 하나다. 뒤의 넷은 사람이
읽는 로그에 찍히므로 `CLEAR-COMM`에 따라 여기도 이름을 쓴다.

한국어로 남는 문서(`README.md`·`docs/DESIGN-NOTES.md`·`docs/solved_problems.md`) 안에서는 "Verification
Layer 절"처럼 영문 이름을 그대로 쓴다. 번역해 부르면 이름이 두 벌이 된다.

### 오답노트 규약을 고친다

Solved Log 절에 셋을 반영한다.

**프로젝트 고유 교훈인데 `docs/solved_problems.md`가 없으면 그때 만들어 적는다.** 정본에 스코프 라우팅
지시는 이미 있다. 없는 것은 **대상 파일이 없을 때 만들라는 지시**뿐이고, 그래서 PC 전역 로그로 샌다.
파일을 미리 만들지는 않는다 — 빈 파일은 recall이 발화해도 얻는 교훈이 0이고, 자동 생성은 "자동으로는
프로젝트 폴더에 아무것도 쓰지 않는다"는 약속을 깬다.

**해결법이 바뀌면 그 항목을 고쳐 쓴다.** 지금 규약은 "절대 안 지우고 쌓기만 한다"인데, 그러면 옛 처방과 새
처방이 둘 다 남아 나중에 어느 쪽을 따를지 알 수 없게 된다. 새 문제는 아래에 추가하고, 이미 있는 항목의
해결법이 바뀌면 그 항목을 고친다. 바꾼 이유는 spec에 남긴다.

**결정과 취향은 solved가 아니라 spec에 적는다.** solved는 겪은 문제와 그 해결법만 담는다. 갈 곳이 없어지는
것은 없다 — 프로젝트 결정은 spec, 머신 전역 취향은 원칙의 환경 관례가 각각 받는다.

### 기존 로그는 git 안 파일만 손댄다

형식 변경을 적용할 실제 파일 중 **PC 전역 오답노트는 git 밖이라 복구 수단이 0이다.** 옛 처방을 덮어쓰거나
형식을 옮기다 손실이 나면 되돌릴 방법이 없고, 손실 사실조차 드러나지 않는다(오답노트는 recall될 때만
읽히므로 몇 달 뒤에야 '적어 뒀던 것 같은데'로 나타난다).

그래서 **`docs/solved_problems.md`(레포 안, git 추적)만 새 형식으로 옮긴다.** PC 전역 로그는 건드리지
않는다. 규약과 형식 문안은 정본과 템플릿에 반영되므로, 다음에 그 파일을 손댈 때 자연히 새 형식을 따르게
된다.

### 오답노트 항목 형식을 한 곳에만 둔다

형식 규칙은 solved 파일 머리말에 둔다. 파일을 여는 사람이 바로 보는 곳이다. 머리말 정본은
`scripts/_scaffold_common.sh`의 템플릿이며 언어는 한국어로 유지한다(사람이 읽는 로그의 머리말이다).

- 증상은 굵게 한 줄로 띄운다. 목록을 훑을 때 굵은 줄만 읽히게 하기 위해서다.
- 원인과 해결은 그 아래 들여쓰기로 내린다.
- 한 항목은 세 줄을 넘기지 않는다. 넘어가면 solved가 아니라 spec에 들어갈 얘기다.
- 순서는 시간순이고 아래에 추가한다.
- 묶지 않는다. 항목이 스무 개를 넘으면 그때 영역별로 묶는다.
- 안 쓰이는 항목도 지우지 않는다.

**기존 형식 서술을 반드시 지운다.** 정본의 Solved Log 절과 템플릿 머리말에 "형식은 '증상/트리거 → 교훈
— 처방이 앞'"이라는 서술이 있는데, 새 형식은 그와 순서가 반대다. 지우지 않으면 서로 반대인 두 형식 정본이
공존한다. 레포 루트 `CLAUDE.md`의 오답노트 재진술도 같이 맞춘다.

## 설계 (파일별)

- **`agent-principles.md`** — 전면 재작성한다. `CLEAR-COMM`의 문체 규범 블록만 한국어로 남기고 그 사실을
  그 자리에 밝힌다. 응답 언어 명시를 `CLEAR-COMM`에 넣는다. 절차 절 제목을 위 표의 영문 이름으로 바꾼다.
  Solved Log 절에 규약 변경 셋을 반영하고 옛 형식 서술을 지운다.

- **`domains-index.md`** — 영문으로 다시 쓴다.

- **스킬 열 개의 `SKILL.md`** — frontmatter와 본문을 모두 영문으로 다시 쓴다. 본문 안의 `§가`류 참조는
  재작성 과정에서 새 이름으로 자연히 바뀐다.

- **커맨드 다섯 개의 frontmatter** — 영문으로 다시 쓴다. **본문은 한국어로 둔다.**

- **`scripts/_scaffold_common.sh`** — solved 템플릿 머리말을 새 형식 규칙으로 바꾸고 옛 형식 서술을

## 테스트 (계약: FAIL=0, 개수는 세지 않는다)

세 스위트를 모두 통과해야 한다 — `test_scaffold.sh`, `test_hooks.sh`, `test_codex_scaffold.sh`.

### 정본 문자열에 매달린 기존 가드 (전수)

초안은 이것을 둘로 셌다. 실측하면 **정본이나 재작성 대상 스킬의 한국어 문자열에 매달린 `check`가 스무
개이고, 그 가운데 넷은 변수 추출 줄(`WF_ROW`·`PO_BLOCK`)을 통해 간접적으로 매달려 있다.** 추출 줄이 빈
문자열을 내면 그 아래 `check`들이 함께 죽으므로 반드시 같이 세어야 한다.

`test_hooks.sh`에는 정본 문자열에 매달린 가드가 없다.

`test_scaffold.sh:304`·`305`는 정본이 아니라 **`skills/nested-orchestration/SKILL.md` 본문**을 grep한다.
스킬 본문을 재작성 범위에 넣으면서 새로 깨지게 된 가드다. 스킬 본문에 매달린 다른 가드가 더 없는지는
구현 단계에서 세 스위트를 한 번 더 훑어 확인한다.

**vacuous의 원인을 특정했고, 그 일부는 이번 재작성이 만드는 것이 아니라 이미 있는 결함이다.**
`scripts/_scaffold_common.sh`의 solved 템플릿 머리말에 "일반화 가능한 항목은 디시플린(agent-principles.md)
으로 재기술해 승격한다"는 문장이 있어 `디시플린`이라는 단어를 품는다. 그리고 `scaffold.sh`는 첫 실행
stdout에 정본과 solved를 한 루프로 함께 덤프한다. 그래서 **정본이 stdout에서 통째로 빠져도
`grep -qF '디시플린'`이 solved 머리말에 걸려 초록으로 통과한다** — 긍정 검사 셋(`test_scaffold.sh:32`·`274`,
`test_codex_scaffold.sh:42`)은 지금 이미 그 상태다. 이번 재작성이 새로 무력화하는 것은 부정 검사
둘(`276`·`286`)이다. 어느 쪽이든 앞선 작업이 만든 이중 주입 회귀 가드가 믿을 수 없다는 결론은 같다.

`codex-scaffold.sh`는 solved를 첫 실행이 아니라 **매 실행** stdout으로 보내므로, Codex 경로의 vacuous
범위는 첫 세션에 국한되지 않는다. 반면 AGENTS.md 인라인에는 solved가 들어가지 않아 `41`·`136`은 vacuous
여지 없이 깨진다.

**그래서 문자열만 바꾸지 않는다.** 새 가드는 정본에만 있고 다른 주입물에는 없는 문자열을 쓴다. 정본의
영문 제목처럼 유일성이 보장되는 것을 고르고, 고른 뒤 그 문자열이 `_scaffold_common.sh` 템플릿과 토글
주입 문구에 없음을 확인한다.

### 새로 추가하는 가드

- **응답 언어 명시가 정본에 있는지 확인한다.** 재작성에서 가장 조용히 사라지기 쉽다.
- **문체 규범이 한국어로 남아 있는지 확인한다.** 예시 문자열만이 아니라 **규칙 설명 문장도 함께** 확인해
  부분 번역을 잡는다.
- **절 이름 다섯이 정본에 있고 옛 이름(`### 가.`류)이 없는지 확인한다.**
- **끊긴 참조가 없는지 확인한다.** 범위는 `git ls-files` 기준으로 한정하고 `docs/superpowers/`를 제외한다.
  `.superpowers/`는 git이 추적하지 않으므로 자동으로 빠진다.
- **정본에 한글 덩어리가 문체 규범 블록 밖에 남지 않았는지 확인한다.** '한글 원본을 남기지 않는다'를
  기계로 검증하는 유일한 방법이다.

**뮤테이션으로 검증한다.** 새 가드마다 대상을 되돌린 상태를 만들어 실제로 FAIL하는지 확인하고 원복한다.
특히 vacuous 위험이 있던 네 곳은 **정본만 stdout에서 빼는 회귀**를 심어 새 가드가 잡는지 확인한다.

## 한계 (정직하게 남긴다)

- **재작성이라 diff가 검토 수단이 되지 못한다.** 대응표가 그 자리를 대신하지만, 대응표 자체가 재작성자가
  쓰는 것이라 재작성자가 놓친 것은 대응표에서도 놓칠 수 있다. 완전한 안전망은 아니다.
- **응답 언어 드리프트를 자동으로 감지하지 못한다.** 가드는 문장의 존재만 증명한다.
- **기본 거동과 겹친다는 판정의 근거가 공개돼 있지 않다.** 잘못 지우면 조용히 원칙이 하나 약해지고
  테스트는 전부 초록이다. 대응표의 '지움' 항목이 유일한 흔적이다.
- **PC 전역 오답노트는 새 형식이 되지 않는다.** 의도적으로 뺐다. 두 로그의 형식이 한동안 다르다.
- **커맨드 본문과 사람이 읽는 문서가 한국어로 남아 영문 정본을 참조하는 혼합이 지속된다.** 이것은 시한부가
  아니라 설계된 상태다. 라우팅 정확도가 언어 불일치에 얼마나 민감한지는 이 레포에서 측정된 적이 없다.
