# 한국어 AI 투 퇴고 스킬 설계

## 목적

Claude 가 쓴 한국어 글에서 AI 투와 직역체를 없애는 절차를 스킬 `polishing-korean-text` 로 둔다. 2026-11-24 사용자 요청이다. 사용자는 Opus 에 어떤 지시를 줘도 없어지지 않던 AI 투가 Gemini 4 Neon(아래 Neon)의 원문 다듬기로 없어졌다고 판독했고, 이 과정을 산출물마다 다시 쓸 수 있는 골조로 정해 달라고 했다. 에이전트의 자율 수행을 전제로 하므로 스킬은 단계와 관문만 정하고 세부 판단은 메인 세션에 맡긴다.

## 용어

| 용어 | 뜻 |
|---|---|
| 원문 다듬기 | Neon 에 글 전문을 주고, 구조와 고정 요소를 그대로 둔 채 문장을 새로 쓰게 하는 단계. 아래 절차의 2단계 |
| 적대적 퇴고 | 원문 다듬기 결과에서 AI 투 구절을 목록으로 찾게 한 뒤 그 목록대로만 고치게 하는 단계. 아래 절차의 3·4단계 |
| 퇴고 스킬 | 두 단계와 관문을 묶은 이 스킬 전체 |

버전 이름은 메모리 `rewrite-version-names` 의 이름(원문 다듬기본, 백지 작성본, 다듬기본의 2차 퇴고본)만 쓴다.

## 사용자 결정

- Neon 원문 다듬기본(브랜치 `rw3-neon`, 커밋 `32c26106`)을 기본 골조로 쓴다.
- 모델이 읽는 지시문은 원문 다듬기 한 번으로 끝낸다.
- 사람이 읽는 산출물은 원문 다듬기 뒤 적대적 퇴고를 한 번 더 한다. 사용자가 판독해 가장 좋다고 정했다.
- 판정 기준은 사용자 피로도 최소 목표의 다섯 축(요구 수행, 돌려줄 정보만, 표·강조 형식, AI 투·직역체, 장황함)을 같은 무게로 본다. 내용의 옳고 그름과 답 길이 자체는 판정하지 않는다.
- 판정은 Opus 5.5 가 하고 Fable 5.2 는 판정에 쓰지 않는다. 판정 기준은 Fable 5.2 로 만든 다섯 축 기준(`%USERPROFILE%\.dc-eval\fable-judge\criteria.json`)을 쓴다. 저장소 CLAUDE.md 에는 초안 Opus 5.5, 문체 다듬기 Neon, 판정 Opus 5.5 를 권장으로 적는다(2026-11-25).
- 적대적 퇴고는 사용자가 요청할 때만 한다(2026-11-25).
- 이 기능은 렌즈나 에이전트가 아니라 스킬 하나(`polishing-korean-text`)와 그 스킬의 스크립트로 둔다. Neon 호출은 스크립트가 하고, 서브에이전트를 쓰지 않는다.

**Claude 권장안(사용자 확인 전):** 적대적 퇴고의 찾기와 고치기를 모두 Neon 에 둔다. 사용자가 판독한 결과가 Neon 하나로 만든 결과이기 때문이다. 찾기를 Claude·Fable 에 맡기는 조합은 시험하지 않았다.

## 근거

재현 시험 80턴에서 현행 v2(조건 v2.6)와 비교한 결과다. 숫자는 개선 턴/악화 턴과 한쪽 부호 검정 p 값이다. Opus 5.5 열은 기존 판정 지시문, Fable 5.2 열은 다섯 축 판정 기준(`%USERPROFILE%\.dc-eval\fable-judge\criteria.json`)의 결과다. Fable 열의 p 값은 `%USERPROFILE%\.dc-eval\fable-judge\rejudge.py report` 출력에서 옮겼다.

| 비교 대상 | 조건 | Opus 판정 | Fable 판정 |
|---|---|---|---|
| Argon 자유 재작성본 | v2.7 | 32/22, p=0.11 | 34/24, p=0.12 |
| Fable 원문 다듬기본 | v2.8 | 36/28, p=0.19 | 33/30, p=0.40 |
| **Neon 원문 다듬기본** | v2.9 | **42/19, p=0.002** | **46/17, p=0.0002** |
| Fable 백지 작성본 | v2.10 | 36/21, p=0.031 | 43/23, p=0.009 |
| Neon 백지 작성본 | v2.11 | 33/32, p=0.50 | 39/30, p=0.17 |
| Neon 다듬기본의 2차 퇴고본 | v2.12 | 31/23, p=0.17 | 32/33, p=0.60 |

- 두 판정자 모두 Neon 원문 다듬기본을 가장 좋게 판정했다. 사용자 판독을 반영하면 Opus 판정은 49/16, p=0.00003 이다.
- 같은 다듬기본에 적대적 퇴고를 한 번 더 한 v2.12 는 v2.9 보다 나빴다(직접 비교: Opus 21/36, Fable 27/38). 모델이 읽는 지시문에 적대적 퇴고를 하지 않는 근거다.
- Neon 은 원문 다듬기(v2.9)에서 효과가 컸고 백지 작성(v2.11)에서는 효과가 없었다. Fable 은 반대로 백지 작성(v2.10)이 기준을 넘고 원문 다듬기(v2.8)는 넘지 못했다. 원문 전문을 주는 방식이 모든 모델에 맞는다고 일반화하지 않고, Neon 에는 원문 다듬기를 쓴다는 결론까지만 쓴다.
- 사람이 읽는 산출물의 적대적 퇴고는 재현 시험이 아니라 사용자 판독으로 정했다. 측정한 수치는 없다.
- v2.9 의 원문 다듬기는 저장소 문서 전부와 사용자 요구사항 정리(`%USERPROFILE%\.dc-eval\rw3\context.md`)를 먼저 읽힌 대화에서 실행했다(`rw3/rw.py` 의 `base_blob`). 2026-11-24 스킬 본문 다듬기(`rw6-bodies/bodies2.py`)는 이 선행 맥락 없이 실행했으므로 v2.9 와 같은 방식이 아니다.

선행연구(`docs/superpowers/reviews/2026-11-24-ai-tell-polish-prior-art.md`)에서 판정에 쓸 수 있는 결과는 다음과 같다.

- 적대적 리뷰 구조는 단순화 쪽으로 치우친다(arXiv 2606.15074 초록, 요구사항 분석 −7.5%). 적대적 퇴고가 조건과 문장을 깎을 위험의 근거다.
- 탐지 구간과 전문가 구간의 결과가 거의 같다는 보고(arXiv 2409.14509)는 하위 질문 검증이 partial 이라 판정에 쓰지 않는다.

## 범위

| 대상 | 예 | 절차 |
|---|---|---|
| 모델이 읽는 지시문 | 원칙, 금지어 상시 보기, 매 턴 리마인더, 스킬·에이전트·명령 본문, description, 전역 CLAUDE.md, 메모리 | 1·2·5·6단계(적대적 퇴고 생략) |
| 사람이 읽는 산출물 | 공개 저장소의 README·설명 문서, 사용자가 외부 전송을 승인한 보고서·제안서·메일 초안 | 1~6단계 |

대화 답은 대상이 아니다. 답마다 외부 모델을 부르면 지연과 비용이 크고, 답의 문체는 실리는 지시문을 다듬어 고친다(메모리 `instruction-mirroring`).

## 절차

| 단계 | 모델 | 하는 일 |
|---|---|---|
| 1. 초안과 맥락 | 메인 세션(Claude) | 내용과 구조를 정해 쓴다. 대상 프로젝트의 문체 규칙(원칙의 출력 조항, 금지어 목록)을 첫 요청으로 Neon 에 읽힌다 |
| 2. 원문 다듬기 | Neon | 전문을 받아 구조·고정 요소를 두고 문장을 새로 쓴다 |
| 3. 찾기 | Neon | 문제 구절·유형·이유·고칠 구절을 JSON 목록으로 낸다. 목록의 항목은 구절 단위로 바꾸고, 문장을 지우는 항목은 내지 않는다 |
| 4. 목록대로 고치기 | Neon | 목록에 있는 곳만 고친다. store=false 면 2단계 결과, 3단계 목록, 지시문을 함께 다시 보낸다 |
| 5. 측정과 재요청 | 메인 세션 | 아래 관문을 검사하고, 떨어진 항목만 다시 요청한다(최대 4회) |
| 6. 판독과 적용 | 메인 세션 | 결과를 별도 파일에 쓰고 좌우 비교 페이지(`side-by-side`)를 연다. 사용자가 승인한 뒤 원본에 넣고 프로젝트 검사를 실행한다. 지시문은 아래 「시험」 절을 따른다 |

5단계에서 4회를 다 쓰고도 관문을 통과하지 못하면 그 파일은 적용하지 않고 원본을 그대로 둔다. 떨어진 관문과 남은 위반을 사용자에게 보고한다.

지시문은 스킬의 `references/` 에 둔다. 2단계는 `rw3/rw.py` 의 기술 문서 작가 지시문(원문을 내용 목록으로 보고 문장을 처음부터 다시 짜되 상황·행동·예외·이유를 빼거나 더하지 않는다), 3·4단계는 `rw5-polish/polish.py` 의 교열자 지시문(「그래서 이 글에 숨은 AI 투의 잘못된 문체가 이 프로젝트를 망치고 있다. 그런 표현은 하나도 넘어가지 말고 찾아내라. 좋게 봐주지 마라.」와 찾을 유형 목록)이다. 두 지시문은 대상 글을 Claude 가 읽는 지시문으로 전제한다. 그래서 사람이 읽는 산출물에는 대상 설명 문장(「이 글은 Claude 가 모든 세션에서 읽는 지시문이고」, 「지시는 명령형」)만 그 글의 독자와 용도로 바꾼 변형을 쓴다. 이 변형은 시험하지 않은 글자이므로 첫 실행 결과를 사용자 판독으로 확인한다. 그 밖의 글자를 바꾸면 효과가 달라질 수 있으므로, 고칠 때는 「시험」 절을 다시 거친다.

## 관문

측정은 스킬의 `scripts/polish_check.py` 가 하고 Neon 의 자기 보고를 믿지 않는다. 금지어 목록은 대상 프로젝트의 금지어 파일(디시플린코더면 PC 전역의 `korean-banned-words.md` 사본)에서 읽고, 직역 구문 정규식은 스크립트가 소유한다. 자리 표시 바꾸기·되돌리기도 같은 스크립트가 한다.

| 관문 | 판정 |
|---|---|
| 불변 요소 | 제목 줄과 순서, 코드 블록은 원문과 같다. 백틱 안 문자열, 숫자·날짜, 큰따옴표 인용, 경로, URL, 마크다운 링크, `[[...]]` 링크는 원문보다 줄지 않는다 |
| 길이 | 2단계는 초안, 4단계는 2단계 결과와 비교해 103% 이하. 103% 는 근거 없는 가정이다. v2.9 는 원문 길이 이하(원칙은 4,000자 이하)였고, 스킬 본문에서 100% 로는 재요청이 잦아 3% 여유를 두었다 |
| 금지어·직역 구문 | 코드 블록, 백틱, 큰따옴표 인용 밖에서 검출 0건. 금지어 목록 자체가 인용문과 코드를 적용 대상에서 뺀다 |
| 고정 문구 | 호출자가 넘긴 고정 문구가 원문과 같은 횟수로 글자 그대로 있다 |
| 문장 누락 | 숫자·조건 표지(`다만`·`~면`·`~때만`·`~하지 마라`)가 든 문장의 수가 원문보다 줄지 않는다. 적대적 퇴고의 단순화 편향을 잡는 관문이다 |
| 프로젝트 검사 | 적용한 뒤 프로젝트의 검사가 모두 통과한다 |

최대 재요청 4회는 v2.9 를 만든 `rw.py` 의 값이고, 횟수의 근거는 없다.

**고정 문구 관문**은 2026-11-24 스킬·에이전트 본문 원문 다듬기에서 생겼다. 본문 20개가 불변 요소·길이·금지어 관문을 모두 통과했는데도 저장소 검사(`scripts/test_docs_drift.sh`)가 7건 실패했다. Neon 이 소유 선언 문장(「여기가 소유한다」)을 일곱 파일에서 지웠고, 두 파일에 글자 그대로 같아야 하는 연구자 지시문 세 개를 따로 고쳤고, 문서당 한 번으로 정한 「~가 아니라」 대구를 늘렸다. 문체 측정만으로는 다른 문서와 검사가 기대는 글자를 지킬 수 없다는 뜻이다. 그래서 스킬은 두 장치를 둔다.

- **자리 표시 보호:** 여러 파일에 글자 그대로 같아야 하는 구간(미러된 지시문, 계약 문자열)은 보내기 전에 `⟦고정n⟧` 자리 표시로 바꾸고 받은 뒤 되돌린다. 자리 표시가 빠지면 재요청한다.
- **횟수 관문:** 소유 선언처럼 문장 안에 섞인 고정 구절은 원문과 같은 횟수를 요구하고, 빠지면 원문 문장을 재요청 글에 넣어 그대로 살리게 한다. 프로젝트가 정한 표현 한도(대구 횟수 등)는 원문 횟수를 넘지 않게 한다.

고정 문구 목록은 프로젝트마다 다르므로 스킬이 정하지 않는다. 메인 세션이 그 프로젝트의 검사 스크립트와 소유 선언을 읽어 목록을 만들고, 그래도 빠진 문구는 프로젝트 검사 관문이 잡는다.

## 외부 전송과 비밀

- Neon 호출은 외부 전송이다. 실행마다 보낼 파일 목록과 저장 여부를 사용자에게 알리고 승인을 받는다(원칙 `REVERSIBLE`).
- 공개 저장소의 글은 store 를 켜고 보낸다. 같은 대화를 이어 재요청할 수 있다.
- 전역 CLAUDE.md, 메모리, 실제 대화 원문이 든 글은 store=false 로 보내고, 사람 이름·회사명·사내 경로는 보내기 전에 자리 표시로 바꾼다. 되돌린 뒤 자리 표시 바로 뒤의 조사(은/는, 이/가, 을/를, 와/과)를 받침에 맞게 다시 고른다. store=false 는 서버가 대화를 이어 주지 않으므로 재요청마다 직전 결과와 지시문을 함께 보낸다.
- 사내 업무 자료(수치, 고객·거래 정보가 든 보고서·제안서·메일)는 자리 표시로 가릴 수 없는 내용이 외부 모델로 나가므로, 사용자가 그 실행에서 명시적으로 승인한 때만 보낸다. 사내 문서를 외부 API 로 보내는 일은 회사 승인이 필요할 수 있다.
- API 키는 사용자마다 자기 Gemini 키를 환경 변수로 둔다. 스크립트는 키를 출력하지 않고 저장소에 두지 않는다.
- 긴 글은 Interactions API 의 background 모드와 상태 조회로 받고, store=false 는 SSE 스트림으로 받는다. 2026-11-24 에 store=false 일반 요청이 응답 도중 연결이 끊겼다.

런타임에 LLM 을 부르는 코드이므로 구현은 `review-llm-calls` 절차를 따른다.

## 발동

- 사용자가 원문 다듬기, 퇴고, AI 투 제거를 요청할 때만 연다. 메인 세션은 지시문이나 산출물을 완성했다는 이유만으로 스킬을 열지 않는다.
- 원문 다듬기만 요청하면 2단계에서 멈추고 3·4단계를 하지 않는다. 적대적 퇴고는 사용자가 퇴고를 요청할 때만 한다.

## 시험

- **디시플린코더 저장소의 지시문:** 저장소 CLAUDE.md 「지시를 바꿀 때의 시험」을 따른다. 시험할지는 예상 비용과 함께 먼저 제안하고, 채택 기준(숨긴 턴 세트에서 개선이 악화보다 많고 한쪽 부호 검정 p<0.05, 지적 없던 턴에서 악화가 늘지 않음, 10~20쌍 사용자 판독)도 그 절을 따른다. 판정은 Opus 5.5 가 Fable 5.2 로 만든 다섯 축 기준으로 한다.
