# HTML 아티팩트의 금지 표현 검사 — 설계

작성일 2026-09-22. 대상은 `hooks/_banned_words.sh` 와 금지 표현 훅 셋이다. 다른 세션(`kw_install`)이
`eli5` 스킬로 설치 파이프라인 그림을 HTML 아티팩트로 발행했는데 금지 표현 훅이 한 번도 반응하지
않았고, 그 보고에서 시작한다.

## 수정 대상

사람이 읽는 산출물 가운데 HTML 로 나가는 것이 검사를 지나지 않는다.

에이전트원칙의 산출물 정의는 "사람이 읽으려고 만드는 문서"이고 확장자를 조건으로 삼지 않는다.
`eli5` 와 아티팩트 스킬이 만드는 페이지는 그 정의에 든다. 지금 `.md` 로 한정된 것은 그 형식만 만들던
시기의 잔재이며 판단의 결과가 아니다.

## 측정한 현재 상태

세 겹 모두가 구조적으로 HTML 을 못 본다. 확인한 것을 적는다.

| 훅 | 못 보는 이유 |
|---|---|
| `doc_word_pretooluse.sh:30` | `case "$FILE" in *.md) ;; *) exit 0 ;; esac` 가 확장자로 거른다 |
| `doc_word_posttooluse.sh:44` | 같은 조건이고, 대상 추출이 `sed`·`tee`·`cp`·`mv`·리다이렉션만 본다 |
| `doc_word_stop.sh:52` | 같은 조건이고, `git status` 가 내는 것만 보므로 추적되지 않는 임시 폴더의 아티팩트는 대상 밖이다 |

보고한 세션의 실측도 함께 적는다. 그 HTML 을 `banned_report` 로 직접 검사하니 `꼴` 한 건이 나왔고
출처가 `글꼴` 이라 거짓 검출이었다. 제외어 추가는 목록을 소유한 `KiwoomAX/korean-banned-words` 에
따로 요청되어 있다.

## 설계

Write 와 Edit 이 직접 쓰는 HTML 을 검사 대상에 넣고, 태그와 스크립트와 스타일을 버린 뒤 남은
텍스트만 맞춘다.

### 대상의 경계

확장자 `.html` 과 `.htm` 을 추가한다. 모든 HTML 이 아니라 Write 와 Edit 이 직접 쓰는 것만이다.
빌드 산출물과 벤더 파일은 그 도구를 지나지 않으므로 Pre 훅의 대상에 애초에 들어오지 않는다.

제외 셋은 그대로다. 이 저장소 자신의 문서와 Claude 메모리와 `docs/superpowers/` 아래다. 이 저장소
자신은 2026-09-22 결정에 따라 확장자와 무관하게 `path_in_own_repo` 가 먼저 빠져나간다.

### 마크업을 버리는 층

`banned_report` 는 지금 마크다운 하나만 안다. 코드 블록과 백틱을 지우는 정규식 둘이 그것이다.
형식이 둘이 되므로 그 층을 형식별로 나눈다.

형식은 인자로 받는다. 파일 이름에서 도출하지 않는 이유는 Pre 훅이 쓰려는 본문을 임시 파일로 꺼내
넘기기 때문이다. 그 시점에는 원래 확장자가 사라져 있다. 호출자가 `$FILE` 을 보고 정해 넘긴다.

HTML 에서 버리는 순서는 셋이다. `<script>` 와 `<style>` 을 내용째 버리고, 남은 태그를 공백으로
바꾸고, 문자 엔티티를 푼다. 속성값은 태그 안에 있으므로 두 번째 단계에서 함께 사라진다. CSS 클래스
이름과 속성값에서 거짓 검출이 생기지 않는 것이 이 순서 때문이다.

HTML 주석도 버린다. 발행되는 페이지에 남지만 사람이 읽는 산문이 아니다.

### 파서를 들이지 않는 이유

정규식 층으로 끝낸다. `html.parser` 로 텍스트 노드만 뽑으면 정확하지만, 이 훅은 매 편집에 돌고
지금은 금지어 바이트가 본문에 하나도 없으면 파이썬을 아예 호출하지 않는 빠른 거르기가 앞에 있다.
파서를 들이면 그 거르기가 무의미해진다. 값과 정확도를 견주어 값을 고른 것이고, 그래서 이 층은
완벽하지 않다 — 깨진 마크업과 태그 안에 든 `>` 는 정확히 처리하지 못한다.

### 건드리지 않는 것

`banned_scan` 은 그대로 둔다. 그 함수의 소비자는 `scripts/check_banned_words.sh` 와 대구 한도 검사이고
둘 다 `git ls-files '*.md'` 로 대상을 만든다. HTML 이 그 목록에 들어오지 않으므로 지금 고칠 근거가
없다.

Stop 훅이 추적되지 않는 임시 폴더의 아티팩트를 못 보는 것도 그대로 둔다. 그 겹은 git 이 바뀌었다고
말하는 것을 보는 것이 설계이고, 그 경계를 넓히면 임시 폴더 전체를 훑게 된다. Pre 훅이 Write 와 Edit
시점에 같은 파일을 보므로 발행 전에 한 번은 지난다.

## 작업 순서

| 단계 | 내용 | 확인 방법 |
|---|---|---|
| 1 | `banned_report` 에 형식 인자를 추가하고 마크다운 경로를 그대로 유지한다 | 검사 다섯 벌의 실패가 늘지 않는다 |
| 2 | HTML 전처리를 추가한다 | 태그와 스크립트와 스타일과 주석이 검사에서 빠지는 픽스처가 통과한다 |
| 3 | 훅 셋의 확장자 조건에 `.html` 과 `.htm` 을 추가하고 형식 인자를 넘긴다 | HTML 픽스처로 Pre 훅이 거부하고 마크다운 동작이 그대로다 |
| 4 | `scripts/test_hooks.sh` 에 HTML 픽스처 단언을 추가한다 | 그 단언이 통과한다 |

1단계를 따로 두는 이유는 인자 추가가 기존 호출자 넷(`Pre`·`Post`·`Stop`·`check_banned_words.sh`)을
지나가기 때문이다. 형식 경로를 나누기 전에 그 통과부터 확인한다.

## 성공 기준

검사 다섯 벌이 FAIL=0 을 내고 `claude plugin validate ./` 가 `version` 경고 하나만 낸다. HTML
픽스처에서 산문의 금지 표현은 검출되고, `<style>` 안의 CSS 클래스 이름과 `<script>` 안의 문자열과
태그 속성값은 검출되지 않는다. 마크다운의 기존 동작이 달라지지 않는다.

## 되돌리기

단계마다 커밋을 나눈다. 3단계만 되돌리면 HTML 이 대상에서 빠지고 마크다운 동작은 그대로 남는다.
1단계와 2단계는 새 인자와 새 경로를 추가하는 것이라 기존 호출을 바꾸지 않는다.

## 남은 위험

거짓 검출이 늘어난다. 보고된 `글꼴` 이 그 예이고 HTML 산문에는 마크다운보다 영어 음차와 기술 용어가
자주 섞인다. 제외어는 이 저장소가 아니라 목록을 소유한 저장소가 정하므로, 늘어난 거짓 검출은 그쪽에
제외어 추가를 요청해 푼다. 요청이 반영되기 전까지는 백틱이 없는 형식이라 피해 갈 방법이 없고, 편집이
거부되면 문장을 바꾸는 것 말고 수단이 없다.

## 기각 — 2026-09-22

사용자가 이 설계를 기각했다. `.html` 은 검사 대상에 넣지 않는다. 아래는 구현하지 않으며 이 문서는
그 판단의 근거로만 남는다.

기각 근거는 `lens-adversarial` 이 찾은 것이다. `.html` 은 산출물 확장자이면서 코드 확장자다. `.md` 를
확장자만으로 대상 정의에 쓸 수 있었던 것은 그 형식이 거의 언제나 산문이기 때문인데, HTML 은 웹
프로젝트의 템플릿과 컴포넌트와 정적 페이지로도 쓰이고 그것들은 Write 와 Edit 으로 직접 쓰인다. 제외
셋은 경로만 판정하므로 산출물과 코드를 구분하지 못한다.

그대로 했을 때의 실패 형태가 셋이다. 한국어 문자열이 든 HTML 템플릿을 고치는 프로젝트에서 편집이
거부된다. 거부 메시지가 안내하는 백틱 회피는 HTML 경로에 적용되지 않아 지시대로 따라도 다시
거부된다. 거짓 검출을 푸는 통로는 외부 저장소의 제외어 추가뿐이고 최소 하루가 들어, 그동안 실제로
남는 수단은 `DISCIPLINED_CODER_REPLY_CHECK=off` 인데 그 변수는 마크다운 검사까지 함께 끈다.

HTML 아티팩트는 지금대로 검사를 지나지 않는다. 그 사각은 알려진 상태로 둔다.
