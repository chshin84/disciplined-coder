# 조항 배치 재설계

> **종료(2026-11-12):** 5번과 7번 단계까지 실행하고 6·8·9·10번 단계는 진행하지 않았다. 조건 사이의 위반 차이가 판정자의 흔들림보다 작았기 때문이다. 결정과 근거는 `docs/superpowers/decisions/2026-11-11-clause-placement/08-closeout.md` 에 있다.

## 목적

Claude 는 이 설계로 에이전트원칙의 조항을 하나의 최적화 목표 아래 결정점 정책으로 다시 정의하고, 각 조항을 효과가 나는 배치 한 곳에만 둔다.

재현 시험은 실제 세션의 지적 턴을 다시 실행하는 시험이다. 2026-11-04 재현 시험에서 원칙 문구를 고친 변경안은 위반을 줄이지 못했다(현행 원칙 17건, 변경안 20건).

2026-11-11 재현 시험에서는 메시지마다 형태 지시 세 줄을 붙인 조건(이하 감독자 문구 전 조건)의 위반이 12·13건이었다. 그 셋째 줄을 감독자 문구로 바꾼 조건은 11건이었고, 이 조건이 지금 `hooks/reply_reminder_userpromptsubmit.sh` 의 문구다(이하 매 턴 리마인더). 사용자는 현행 원칙 답과 감독자 문구 전 조건 답 10쌍을 직접 판독했다.

판독에서 현행 원칙은 10쌍 모두 위반이었고 감독자 문구 전 조건은 0쌍이었다. 매 턴 리마인더의 문구는 사용자 판독을 받지 않았다.

이 결과로 Claude 는 위반의 원인을 문구보다 배치와 수단에서 찾는다. Fable 5.2 에 같은 브리프를 세 번 보낸 답(2026-11-11, `%USERPROFILE%\.dc-eval\fable-2026-11-11\`) 중 둘은 STATUS-FIRST(정할 일을 모두 먼저 적기)와 ASK-OPTIONS(한 건씩 묻기)가 부딪친다고 지적했다.

세 답 모두 표 셀 예외가 압축을 표로 옮긴다고 지적했고, 둘은 NO-ANALOGY 가 쉬운 설명을 막는다고 지적했다. 선행연구(`docs/superpowers/reviews/2026-11-11-comm-violation-methods-prior-art.md` 의 하위 질문 sq4, 보고 전용)는 규칙 수가 늘수록 모든 규칙을 지키는 비율이 급락했다고 보고한다.

완료 기준은 아래와 같다.

- 모든 조항에 결정점과, 줄이는 비용 항목이나 지키는 제약이 적혀 있다.
- 조항마다 배치 하나와 그 근거가 배치표(`docs/superpowers/decisions/2026-11-11-clause-placement/placement.md`)에 있다.
- 새 배치로 실행한 재현 시험의 위반이 현행 원칙보다 적고, 필요 정보 누락은 늘지 않으며, 사용자 판독 표본도 같은 방향이다.
- 매 세션 실리는 글자 수(원칙 파일과, 조항을 받은 스킬의 description 합계)와 매 턴 리마인더 글자 수가 현행보다 늘지 않는다. 현행은 원칙 10,055자, 매 턴 리마인더 217자(줄바꿈 제외)다.
- Fable 5.2·Opus 5.5 가이드의 지시마다 채택이나 기각과 그 근거가 「프롬프팅 가이드 반영」 표에 있다.
- 남은 브랜치와 워크트리가 반영, 보존 태그, 유지 중 하나로 처분되어 있다.

## 기준선

사용자는 2026-11-11 에 이 설계의 판단 기준선을 "지속성 및 실질가치를 보전하기 위한 하네스"로 정하고 결정을 Claude 에게 위임했다. 같은 날 사용자는 "나한테 질문을 하지 말고" 판단하라고 했고, "되돌리기 어려운것도 너 판단하에 작업해"라고 했다.

그래서 위임 기간에는 이 문서가 사용자 승인을 받으라고 정한 단계(5번·10번의 비용 승인, 7번의 삭제 승인, 10번의 2026-10-18 지시 예외, 브랜치 삭제)를 Claude 가 결정 기록으로 대신하고 아침 보고에 적는다. 원격에 없는 것은 지우기 전에 보존 태그나 커밋으로 남긴다. 위임은 사용자가 다시 지시하면 끝난다.

Claude 는 위임 중의 결정마다 아래 기준으로 점수를 매기고 결정 기록에 남긴다(`DELEGATED-SCORE`).

| 기준 | 질문 |
|---|---|
| 지속성 | 결과와 근거가 세션 종료, compact, 워크트리 정리를 지나도 남는가. 긴 대화에서도 효과가 유지되는가 |
| 실질가치 | 실제 세션에서 사용자 비용을 줄였다는 측정이 있는가 |
| 되돌리기 쉬움 | 결과가 틀렸을 때 커밋 되돌리기나 스위치로 원래대로 돌아가는가 |

지속성 기준에는 이 세션에서 실제로 손실될 뻔한 사례가 근거로 있다. `managing-docs-agent` 워크트리의 spec 은 커밋되지 않은 채 그 폴더에만 남아 있었다. 재현 시험 도구는 세션 전용 scratchpad 에만 있었다.

## 행위 모델

Claude 는 이 저장소와 사용자 작업의 오너로 일하고, 사용자는 결과를 보고 승인하거나 바로잡는 감독자다(사용자 지시 2026-11-11, 메모리 `work-mode-claude-leads`).

최적화 목표는 하나다. 사용자가 원하는 결과를 얻기까지 드는 사용자 비용을 최소로 하라. 사용자 비용은 아래 항목의 합이다.

| 비용 항목 | 내용 |
|---|---|
| 주의 | 사용자가 답을 읽고 판단하는 데 쓰는 시간 |
| 개입 | 사용자가 정정·재지시·결정을 하는 횟수 |
| 재작업 | 잘못된 전제나 결함 때문에 다시 하는 작업 |
| 대기 | 사용자가 결과를 기다리는 시간 |

토큰 비용은 사용자 비용이 같을 때만 비교하라.

제약은 최적화 대상으로 바꾸지 마라. 사용자 동의 없는 비가역 손실(삭제, 덮어쓰기, 외부 전송), 비밀 유출, 다른 세션 작업의 git 제어는 모두 0 이어야 한다.

에이전트의 작업은 사건마다 판단하는 루프다. 그래서 조항은 단계에 붙이지 말고 판단이 일어나는 결정점에 붙여라. 결정점은 아래와 같다.

| 결정점 | 예 |
|---|---|
| 전제 사용 | 상태·원인·이전 결정을 말하거나 그것에 기대 행동하기 직전 |
| 범위 결정 | 무엇을 만들고 고칠지 정할 때 |
| 실행 순서 | 도구 호출을 동시에 할지 차례로 할지 정할 때 |
| 판단 위임 | 사용자 지시의 결과를 바꾸는 갈림이 생겼을 때 |
| 비가역 행동 | 삭제·덮어쓰기·외부 전송 직전 |
| 단계 넘김 | 결과를 다음 단계나 사용자에게 넘기기 직전 |
| 대화 답 작성 | 사용자에게 답이나 보고를 쓸 때 |
| 산출물 작성 | 사용자가 읽거나 남에게 전할 문서를 쓸 때 |
| 지시문 작성 | 다른 에이전트가 따를 글을 쓸 때 |
| 쓰기 공통 | 대화 답·산출물·지시문을 쓸 때 모두 같은 행동을 요구하는 조항의 결정점 |

사용자는 2026-11-11 에 작업을 문서 업무형 순서와 개발자형 순서로 나누자고 제안했다. Claude 는 원칙을 두 순서로 나누지 않고 결정점을 공유하기로 정했다.

두 작업은 같은 결정점을 지나고, 한 세션 안에서 섞인다. 2026-11-11 세션도 훅 개발과 비교 페이지·보고 작성을 함께 했다. 그래서 원칙을 둘로 나누면 같은 조항이 중복된다.

작업 유형에 따라 달라지는 조항은 스킬 배치가 맡는다. 문서 작업의 조항은 `managing-docs` 같은 문서 스킬로, 개발 작업의 조항은 superpowers 와 `review-specs` 같은 개발 스킬로 보낸다.

조항을 정리하는 규칙은 아래와 같다.

- 조항마다 결정점 하나와 비용 항목이나 제약 하나를 배정하라.
- 결정점이나 비용 항목이 둘인 조항은 합치기·나누기 후보로 표시하라.
- 결정점과 비용 항목이 같고 행동 대상이 겹치는 조항끼리는 합치기 후보로 표시하라.
- 어느 비용 항목도 줄이지 않고 어느 제약도 지키지 않는 조항은 삭제 후보로 표시하라.
- 조항이 없는 결정점이나 제약은 빈칸으로 표시해 사용자에게 제안하라.

재현 시험에서 비용 항목을 직접 측정할 수는 없다. 그래서 Claude 는 대리 지표를 쓴다.

판정자는 지적 턴마다 같은 지적이 새 답에도 해당하는지 판정한다. 이 판정이 개입 항목의 대리 지표다.

필요 정보 누락 수는 재작업 항목의 대리 지표다. 필요 정보는 현행 원칙 답에 있고 새 답에 없는 정보 중 사용자가 그 턴에서 판단하거나 행동하는 데 쓰는 정보이며, 판정자가 두 답을 대조해 센다. 답 글자 수는 주의 항목의 대리 지표다.

## 배치

배치는 상주, 스킬, 매 턴, 기계 검사, 삭제이며 한 조항은 한 배치에만 둔다. 사용자는 상주, 매 턴, 지시 밖을 제안했다.

Claude 는 특정 작업에서만 쓰는 조항을 위해 스킬을 더했다. 그런 조항은 다른 배치에 두면 평시 컨텍스트를 차지하기 때문이다.

이 방향은 2026-10-25 경량화 설계(`docs/superpowers/specs/2026-10-25-principles-slimming-design.md`)와 같다. Claude 는 지시 밖도 수단에 따라 기계 검사와 삭제로 나눴다.

| 배치 | 두는 조항 | 실리는 방식 | 비용 |
|---|---|---|---|
| 상주 | 대화가 길어져도 지켜지는 조항, 효과 판정이 서지 않은 조항, 매 턴에서 밀려난 조항 | 세션 첫머리의 원칙 파일 | 세션당 한 번 |
| 스킬 | 특정 작업에서만 적용되는 조항 | 스킬 description 으로 열리는 스킬 본문 | 열릴 때만 |
| 매 턴 | 상주에서는 지켜지지 않고 매 턴 리마인더에 넣으면 지켜지는 조항 | 매 턴 리마인더 | 메시지마다 누적 |
| 기계 검사 | 상주와 매 턴 리마인더 모두에서 줄지 않고 출력에서 검출할 수 있는 조항 | 훅의 문자열 검사, 대화를 모르는 검사자, 콘솔 답변 교정 | 검사 실행 비용 |
| 삭제 | 비용 항목과 제약 어디에도 기여하지 않는 조항, 다른 조항과 중복인 조항 | 없음 | 없음 |

매 턴 리마인더에는 조항마다 한 줄 요약을 넣고, 줄 수는 3개 이하로 둔다. 근거는 Replit 보고다.

Replit 은 결정 시점 안내를 서너 번 넘게 주입하면 효과가 줄었다고 보고했다. 그 보고의 측정 대상은 주입 횟수와 도구 실행이며 한 리마인더 안의 줄 수가 아니다. 그래서 Claude 는 이 상한을 측정값이 아닌 출발점으로 둔다.

## 배치 근거의 출처

배치는 실제 세션의 재현 시험으로만 판정하라. 재현 시험은 지적 턴까지의 앞 대화와 원칙 전체를 싣는다.

클린룸 시험은 앞 대화 없이 질문 하나만 싣고, 2026-11-04 문구 변형 시험은 앞 대화를 실었지만 원칙 전체 대신 조항 하나만 실었다. 두 시험 모두 원칙 전체가 대화 뒤로 밀려나는 상황을 만들지 않으므로, 매 턴 배치의 효과를 검출할 수 없다(사용자 지적 2026-11-11). 두 시험의 기록(`docs/domain-*.md`, `managing-docs-agent` 워크트리의 `CLAUDE.md` 「문구 변형 비교 시험」)은 문구를 고를 때만 써라.

재현 시험에 쓸 지적 턴은 결정점마다 모아라. 사용자는 2026-11-11 에 "너가 주체니깐 나한테 뭘할지 역으로 제안해주는게 좋아"라고 지적했다. 이 지적은 판단 위임 결정점의 턴이다.

## 판정 순서

비용이 작은 판정부터 하라. 앞 단계에서 배치가 정해진 조항은 뒤 단계에 넘기지 마라. 판정마다 기준, 점수, 기각 이유를 `docs/superpowers/decisions/2026-11-11-clause-placement/` 의 결정 기록에 남겨라.

### 1. 결정점 배정

조항마다 「행위 모델」의 칸을 채우고, 합치기·나누기·삭제 후보를 표시하라. 이 단계에서는 문구를 고치지 말고 모델도 실행하지 마라. 확인 방법은 모든 조항에 행이 있고 후보마다 사유가 있는지 보는 것이다.

### 2. 지적 턴 모으기

2026-10-01 부터 2026-11-11 까지의 세션 기록에서 사용자가 Claude 의 행동을 지적한 턴을 모아라. 모은 턴은 조항과 결정점에 배정하라. 턴마다 그 시점 원칙 파일의 커밋을 기록하고, 현행 문구와 다른 문구 아래에서 나온 지적은 따로 세라.

조항을 둘 이상 배정한 턴은 표시하라. 기간은 넓히지 마라. 확인 방법은 결정점별 턴 수와 조항별 지적 횟수가 표에 있는지 보는 것이다.

### 3. 스킬 배치

적용 조건이 특정 작업인 조항을 스킬 후보로 두라. 2026-09-21 에 Claude 는 커밋 54ee432 로 문서 규칙을 `domain-docs` 스킬에서 원칙으로 옮겼다.

스킬로 두면 열지 않았을 때 누락이 조용했기 때문이다. 그 뒤 2026-10-25 에 사용자는 스킬이 설명만으로 잘 열린다고 보고, 옮기기 전에 열림 시험을 먼저 하기로 정했다.

그래서 후보마다 스킬 열림 시험을 하라. 열리면 스킬에 두고, 열리지 않으면 4번 단계로 넘겨라.

스킬로 정한 조항은 5번 단계에 넘기지 마라. 확인 방법은 후보마다 옮길 스킬 이름과 열림 시험 결과가 있는지 보는 것이다.

### 4. 상주 확정과 후보 문안 작성

지적 횟수는 현행 문구 칸과 이전 문구 칸의 합계로 세라. 재현 시험은 지적 턴을 모두 현행 원칙 아래에서 다시 실행하므로, 이전 문구 아래의 턴도 입력으로 쓸 수 있기 때문이다.

지적이 4건 미만인 조항은 상주에 두라. 다만 1번 단계의 삭제 후보는 지적 횟수와 무관하게 7번 단계의 삭제 확인으로 넘겨라. 지적이 4건 이상인 조항은 5번 단계로 넘겨라.

이 단계에서 Fable 5.2·Opus 5.5 가이드를 절 단위로 모두 읽고, 지시마다 결정점과 비용 항목에 대응시켜 「프롬프팅 가이드 반영」 표에 행을 더하라. 5번 단계에 넘길 조항이 있는 결정점의 지시는 후보 문안으로 만들어라. 확인 방법은 상주 조항마다 지적 횟수가 있고, 가이드 표에 절마다 행이 있는지 보는 것이다.

### 5. 위치 시험

시험 전에 실행 수, 예상 시간, 예상 비용을 결정 기록에 적어라.

5번 단계에 넘어온 조항마다 그 조항의 지적 턴을 재현하라. 조건은 현행 원칙만 둔 조건과, 그 조항의 한 줄 요약을 매 턴 리마인더에 넣은 조건이다.

지금의 매 턴 리마인더와 가이드 후보 문안도 시험하라. 그 입력은 해당 줄이 겨누는 조항의 지적 턴을 합친 턴이다.

판정 규칙은 아래 차례로 적용하라. 같은 조건을 다시 실행했을 때 36건 중 7건의 판정이 뒤집혔으므로 차이 기준을 둔다.

- 현행 원칙 조건의 위반이 지적 턴의 절반 미만이면, 재현이 지적을 다시 만들지 못한 것으로 보고 상주에 두라.
- 매 턴 조건의 위반이 현행 원칙 조건보다 2건 이상 적고 현행 원칙의 절반 이하이면 매 턴 후보로 두라.
- 위 두 규칙에 들지 않고 매 턴 조건의 위반도 지적 턴의 절반 이상이면 기계 검사 후보로 두라.
- 나머지는 판정이 서지 않은 것으로 보고 상주에 두라.

대조 조건으로, 사용자가 2026-11-11 에 효과를 물은 일반 상기 문구("에이전트 원칙을 잊지 마라")를 시험하라. 매 턴 리마인더 자리에 "에이전트원칙을 잊지 말고 이번 답에도 적용하라" 한 줄만 넣고, 매 턴 후보 조항의 지적 턴에 실행하라.

Claude 는 이 조건의 효과가 작다고 예상한다. Fable 5.2 가이드는 일반적인 "더 자유롭게" 지시가 효과가 없었다고 보고했고, Opus 5.5 가이드는 일반 지시보다 피할 형태를 이름으로 적은 지시가 듣는다고 보고했기 때문이다.

매 턴 후보 조항마다 대조 조건의 위반을 그 조항의 한 줄 조건과 같은 턴 묶음에서 비교하라. 차이가 1건 이내인 조항이 매 턴 후보의 절반 이상이면, 6번 단계에서 대조 조건의 한 줄도 후보로 경쟁시켜라.

판정자는 사용자보다 차이를 작게 보는 경향이 있다(메모리 `opus-judge-human-gap`). 그래서 후보를 확정하기 전에 10쌍을 골라 사용자 판독을 받아라. 표본에는 개선, 악화, 둘 다 위반인 사례와 조항을 둘 이상 배정한 턴을 섞고, 턴마다 조항 배정이 맞는지도 함께 물어라.

판독이 판정자와 다른 쌍은 사용자 판정으로 바꾸고, 그 결과 판정 규칙의 결론이 바뀐 조항은 바뀐 결론을 따르라. 위임 기간에는 판독 표본을 만들어 두고, 사용자 판독 전까지 후보를 잠정 배치로 표시하라. 확인 방법은 후보마다 두 조건의 위반 수와 판독 상태가 기록에 있는지 보는 것이다.

### 6. 매 턴 칸 채우기

매 턴 후보를 5번 단계에서 측정한 위반 감소폭 순으로 세워 위 3개를 매 턴에 두라. 줄을 합친 글자 수가 217자를 넘으면 감소폭이 작은 줄부터 빼라.

밀려난 후보는 상주에 두고 문구 시험의 우선 대상으로 표시하라. 확인 방법은 줄 수와 글자 수와 그 근거가 기록에 있는지 보는 것이다.

### 7. 기계 검사와 삭제 확인

기계 검사 후보마다 수단을 정하라. 문자열로 잡히면 훅을 쓰고, 잡히지 않으면 대화를 모르는 검사자를 써라.

화면 표시만 고쳐도 되는 위반에는 콘솔 답변 교정을 써라. 콘솔 답변 교정은 `managing-docs-agent` 워크트리의 보류된 spec `docs/superpowers/specs/2026-11-02-reply-edit-rules-design.md` 의 기능이다.

수단이 없는 후보와 1번 단계의 삭제 후보는 근거와 함께 결정 기록에 적고, 삭제할지 정하라. 지우지 않기로 한 조항은 상주에 두라. 확인 방법은 후보마다 수단이나 삭제 판단 기록이 있는지 보는 것이다.

### 8. 배치표 작성

1번부터 7번 단계의 결과를 배치표에 모아라. 배치표에는 조항마다 결정점, 비용 항목이나 제약, 배치, 근거를 적어라.

합치기 후보끼리 배치가 다르면 합치지 마라. 확인 방법은 모든 조항이 행 하나를 가지고 배치가 하나인지 보는 것이다.

### 9. 새 배치 구성

배치표대로 아래 파일을 고쳐라. 원칙 파일에서는 상주 조항만 남겨라.

상주 조항의 문구는 합친 조항만 다시 쓰고, 나머지는 그대로 둬라. 다시 쓰는 문안은 2026-11-04 사용자 결정의 표기 형식(지시, `[목적 및 기대효과]`, `{단, 조건적인 상황}` 순)을 따른다. 스킬로 옮긴 조항은 그 스킬의 SKILL.md 에 두고, 매 턴 칸은 매 턴 리마인더에 넣고, 기계 검사 중 훅은 `hooks/` 에 구현하라.

이 단계에서 「기준선」의 지속성 사례에 맞는 검사도 구현하라. 세션 시작 셋업(`scripts/scaffold.sh`)이 이미 핸드오프 잔존을 세어 알리므로, 같은 셋업에 저장소의 워크트리마다 커밋하지 않은 spec·plan·리뷰 기록이 있으면 알리는 검사를 더하라. 확인 방법은 저장소 CLAUDE.md 「변경 뒤 실행」의 검사가 모두 통과하는지 보는 것이다.

### 10. 조합 시험

시험 전에 실행 수, 예상 시간, 예상 비용을 결정 기록에 적어라.

새 배치 전체를 현행과 비교하라. 입력은 2번 단계에서 모은 지적 턴 전체이고, 같은 조건을 세 번 실행하라.

사용자 판독은 10쌍을 받아라. 지표는 위반 수, 필요 정보 누락 수, 원칙 파일과 스킬 description 글자 수의 합계, 매 턴 리마인더 글자 수다. 확인 방법은 세 실행 모두에서 새 배치의 위반이 현행보다 적고, 누락이 늘지 않으며, 판독이 같은 방향이고, 글자 수가 완료 기준을 넘지 않는지 보는 것이다.

이 단계는 저장소 CLAUDE.md 에 적힌 2026-10-18 사용자 지시와 부딪친다. 그 지시는 원칙 전체를 묶은 비교와 같은 조건의 재실행을 금지한다.

Claude 는 이 비교가 필요하다고 본다. 배치를 옮긴 효과는 조항 단위로 측정할 수 없고, 흔들림은 세 번 실행과 사용자 판독으로 다룰 수 있기 때문이다. 위임 기간에는 Claude 가 이 예외를 결정 기록에 남기고 실행한다.

이 단계가 실패하면, 5번 단계에서 지금의 매 턴 리마인더가 매 턴 기준을 넘은 경우에만 `reply-reminder` 브랜치를 main 에 병합하라.

## 시험 조건

재현 스크립트 `replay3.py` 와 입력 `turns/turns-2026-11-11.jsonl`, 결과는 `%USERPROFILE%\.dc-eval\replay\` 에 있다. 이 폴더는 저장소 밖이라, 실제 대화가 든 자료를 공개 저장소에 올리지 않으면서 다음 세션도 이어 쓸 수 있다.

저장소에는 집계와 조항별 결론만 둬라. Fable 5.2 답 세 개는 `%USERPROFILE%\.dc-eval\fable-2026-11-11\` 에 있다.

재현 설정에는 사용자 PC 전역 CLAUDE.md 의 AX 블록(`%USERPROFILE%\.claude\kw-ax\claude-md-ko.md`), 원칙, 금지어 목록, Concise 출력 스타일을 실어라. 도구는 꺼라.

그래서 대기 비용 항목은 재현에서 측정하지 못한다. 범위 결정 결정점의 턴은 답에 적힌 계획과 범위로 판정하라.

실행과 판정은 Opus 5.5 만 써라(메모리 `principle-work-opus-only`). 집계 전에 `modelUsage` 로 다른 모델이 섞였는지 확인하라. 2026-11-04 문구 변형 시험에서는 1,352건 중 21건에 다른 모델이 섞였다.

동시 실행은 3개로 둬라. 2026-11-04 문구 변형 시험에서 8개를 동시에 실행하자 메모리 부족으로 강제 종료되었다.

## 비목표

금지어 목록은 이 설계의 대상이 아니다. 목록은 이미 상주와 훅 검사를 함께 쓴다. 2026-10-18 측정에서 금지어 칸을 빼고 대체어 칸 문구만 남긴 조건은 금지어 빈도가 목록 조건의 2회에서 32회로 늘었다(`docs/domain-korean.md`).

이 설계는 콘솔 답변 교정을 구현하지 않는다. 7번 단계에서 수단으로 지정만 하고, 재개는 그 spec 의 보류 조건(사용자 지시)을 따른다.

리뷰가 지적한 주입 간격 시험은 뺐다. 매 턴 리마인더는 메시지당 217자이고, 재현의 앞 턴 답은 리마인더 없이 생성되어 간격 주입 상태를 재현할 수 없기 때문이다. 리마인더를 컨텍스트 증가량이나 compact 시점에 맞춰 붙이자는 사용자 제안도 같은 이유로 넣지 않았다.

## 남은 위험

지적 횟수는 사용자가 지적한 위반만 센다. 그래서 지적 없이 넘어간 위반이 많은 조항은 4번 단계에서 시험 없이 상주에 남는다. 이 조항들은 9번 단계에서 문구를 바꾸지 않으므로 현행과 같은 상태로 남는다.

재현은 도구를 끈 채 실행한다. 그래서 도구 호출이 많은 실제 세션에서 매 턴 리마인더가 같은 효과를 내는지는 측정하지 않는다.

지적 턴의 조항 배정은 Opus 서브에이전트 하나가 사용자 판독 없이 했다. 5번 단계의 판독 표본이 배정 확인을 겸하지만, 표본 밖의 배정 오류는 남는다.

지적 턴 원문은 `%USERPROFILE%\.dc-eval\replay\turns\` 한 곳에만 있다. 원문에 사내 정보가 있어 공개 저장소에 둘 수 없기 때문이다.

## 실행 중 확인한 사항

Claude 는 2026-11-11 에 1번과 2번 단계를 실행했다. 결과는 `docs/superpowers/decisions/2026-11-11-clause-placement/01-decision-points.md` 와 `02-correction-counts.md` 에 있다.

1번 단계에서 `ASYNC-FIRST` 에 맞는 결정점이 없어, Claude 는 「실행 순서」 결정점을 더했다. 비밀 유출 제약을 지키는 조항은 원칙에 없다. Claude 는 「행위 모델」 규칙대로 이 빈칸에 새 조항을 쓰지 않고 사용자에게 알린다.

2번 단계의 서브에이전트는 지적 턴 113건을 모았다. 기간은 2026-10-01 부터였지만, 서브에이전트는 세션 기록에 남은 가장 이른 사용자 메시지가 10-07 이라고 보고했다.

비가역 행동 결정점의 턴은 `REVERSIBLE` 의 1건이다. 그래서 `REVERSIBLE` 은 4번 단계에서 상주에 남고, 지적이 0건인 `OTHER-SESSIONS` 도 상주에 남는다.

결정점 목록과 리마인더 방식을 확정하려고 실행한 선행연구(`docs/superpowers/reviews/2026-11-11-decision-points-prior-art.md`)는 판정에 쓸 근거를 내지 못했다. 통과한 실사용 에이전트 자율성 측정 연구와 Stage-Gate 모델 개요는 방향 참고에 그쳤다. 그래서 Claude 는 이 spec 의 결정을 바꾸지 않았다.

## 리뷰 반영

1차 리뷰(`docs/superpowers/reviews/2026-11-11-clause-placement-review.md`)와 2차 리뷰(`2026-11-11-clause-placement-review-2.md`)를 반영했다. 2차 리뷰의 지적은 판정 규칙의 경계와 단계 사이 경로를 메우는 수정이고, 결정점 정책 모델과 배치 구조는 바뀌지 않았다. 남은 지적 중 설계를 틀리게 만드는 지적이 없으므로, Claude 는 3차 리뷰를 하지 않는다.
