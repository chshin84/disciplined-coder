## 수집 방법

Claude 는 `~/.claude/projects/` 아래 프로젝트 폴더의 `*.jsonl` 을 읽었고, 하위 `subagents` 폴더는 읽지 않았다. 대화형 세션(`entrypoint` 가 `cli`)만 남기고 `claude -p` 로 실행한 시험 세션은 뺐다. 메시지 시각이 기간 안에 드는 사용자 메시지 중 시스템 주입·훅 출력·도구 결과·명령 태그·압축 요약은 사용자 메시지에서 뺐다. 그 결과 남은 사용자 메시지는 903개다.

이전 수집 도구(`replay.py`)가 쓰던 후보 목록 파일이 남아 있지 않았다. 그래서 Claude 는 키워드 검색 대신 903개를 모두 읽었다. 이어서 지적으로 보이는 메시지 약 200개를 직전 assistant 답과 함께 다시 읽고, 직전 Claude 행동을 지적·정정하거나 불만을 표시한 턴만 골랐다. 사용자가 새 지시를 덧붙이거나 자기 질문을 고친 메시지, 단순 질문, 직전 답과 무관한 불만은 지적 턴에서 뺐다.

원칙 버전은 턴마다 `git log -1 --before=<메시지 시각> --format=%h -- agent-principles.md` 로 구했다. 세션의 작업 폴더가 이 저장소가 아니어도 같은 명령을 썼다. 그래서 다른 프로젝트 세션과 워크트리 세션에 실제로 실린 사본(플러그인 캐시와 작업 브랜치의 파일)은 기록한 커밋과 다를 수 있다. 문구 비교는 조항 ID 가 든 줄을 그 커밋과 지금의 `agent-principles.md` 에서 꺼내 글자 그대로 대조했다.

결정점과 조항 배정은 Claude 한 명이 판정했고, 사용자 판독이나 다른 판정자와의 대조는 하지 않았다.
