# 1번 단계 결정점 배정

이 기록은 설계 문서 `docs/superpowers/specs/2026-11-11-clause-placement-design.md` 「판정 순서」 1번 단계의 결과다. 대상은 `agent-principles.md` 의 ID 조항 46개와 절 머리 지시 14개다. 이 단계에서는 문구를 고치지 않았고 모델도 실행하지 않았다.

## 판정 기준

결정점과 비용 항목의 이름은 설계 문서 「행위 모델」의 표를 따른다. 아래 표에서 '쓰기 공통'은 대화 답 작성·산출물 작성·지시문 작성을 함께 가리킨다.

쓰기 공통에 같은 행동을 요구하는 조항은 결정점이 하나인 조항으로 보고 나누기 후보로 표시하지 않았다. 「출력」 절이 모든 글에 같은 규칙을 적용하도록 설계되었기 때문이다. 결정점마다 다른 행동을 요구하는 조항만 나누기 후보로 표시했다.

결정점과 비용 항목이 같아도 행동 대상이 겹치지 않는 조항은 합치기 후보로 표시하지 않았다. 범위 결정·재작업에 속한 조항(`CHECKABLE`·`SUB-ORCHESTRATE`·`REPORT-DEAD` 등)과 쓰기 공통·주의에 속한 조항 대부분이 이 기준으로 빠졌다. 합치기 후보는 결정점과 비용 항목이 같고 행동 대상도 겹치는 조항 묶음에만 표시했다.

결정점이나 비용 항목을 둘 적은 행은 첫째를 주된 결정점이나 비용 항목으로 본다. 결정점별 조항 수는 첫째 결정점으로 셌다.

## 빈칸

조항이 하나도 없는 결정점은 없다. 다만 아래 칸이 얇거나 비어 있다. 설계 문서의 규칙대로 이 칸을 채울 조항은 쓰지 않고 사용자에게 제안할 대상으로 남긴다.

산출물 작성 결정점에는 전용 ID 조항이 없다. 이 결정점에는 쓰기 공통 공통 조항과 `TONE-AXIS`·`BOTTOM-LINE` 의 일부, 그리고 스킬을 가리키는 절 머리 「문서 관리」·「읽기 위한 문서」만 있다.

비밀 유출 제약을 지키는 조항이 없다. 「행위 모델」은 이 제약을 0 으로 두지만 원칙 파일에는 대응하는 지시가 없다.

`ASYNC-FIRST` 는 「행위 모델」의 어느 결정점에도 맞지 않는다. 도구 호출 순서를 정하는 결정점이 모델에 없기 때문이다. 이 조항과 `작은 변경` 만 대기 비용 항목을 줄인다.

## 충돌

| 조항 쌍 | 부딪치는 지점 |
|---|---|
| `STATUS-FIRST` · `BOTTOM-LINE` | 작업 보고 첫머리에 `STATUS-FIRST` 는 정할 일과 남은 문제를 두라 하고, `BOTTOM-LINE` 은 한 일과 달라진 점을 두라 한다. |
| `STATUS-FIRST` · `ASK-OPTIONS` | 질문이 든 보고에서 `ASK-OPTIONS` 는 질문 머리에 근거·대목적·배경을 먼저 적으라 하고, `STATUS-FIRST` 는 정할 일을 먼저 짧게 두라 한다. 설계 문서가 인용한 Fable 5.2 답도 이 순서 충돌을 지적했다. |
| `ASK-OPTIONS` · `BOTTOM-LINE` | `ASK-OPTIONS` 는 질문 머리에 근거를 두라 하고, `BOTTOM-LINE` 은 결론을 먼저 두고 근거를 뒤에 두라 한다. |
| `ASK-OPTIONS` · `CONCRETE-FORM` | 제안 형식이 둘이다. `ASK-OPTIONS` 는 선택지마다 효과·부작용·권장안을, `CONCRETE-FORM` 은 현행·변경안·이유를 요구하며 둘 다 해당하는 제안에서 어느 형식을 쓸지 정해져 있지 않다. |
| `ASK-OPTIONS` · `NO-AGREE` | `ASK-OPTIONS` 는 사용자가 정한 값대로 진행하라 하고, `NO-AGREE` 는 사용자 주장을 근거와 대조하라 한다. 사용자가 정한 값이 근거와 다른 전제 위에 있을 때 둘이 구분된다. |
| `ASK-OPTIONS` · 메모리 `work-mode-claude-leads` | 원칙 밖의 충돌이다. `ASK-OPTIONS` 는 결과를 바꾸는 결정마다 물으라 하고, 메모리는 비가역·가치판단·스킬 승인만 물으라 한다. |
| `EVIDENCE-FIRST` · `DELEGATED-SCORE` | 위임 중 근거를 찾지 못하면 `EVIDENCE-FIRST` 는 값을 넣지 말고 알리라 하고, `DELEGATED-SCORE` 는 최고점 안으로 진행하라 한다. |
| `REVERSIBLE` · `REPORT-DEAD` | `REPORT-DEAD` 는 쓰이지 않게 된 코드와 문서를 같은 변경에서 지우라 하고, `REVERSIBLE` 은 지우기 전에 사용자 확인을 받으라 한다. |
| `REVERSIBLE` · `RUN-IT` | `RUN-IT` 은 명령을 직접 실행하라 하며 권한 거부만 예외로 둔다. 비가역 명령에 대한 `REVERSIBLE` 의 확인 절차와의 순서가 문안에 없다. |
| `YAGNI` · `NO-SQUEEZE` | `YAGNI` 는 같은 일을 더 짧은 글로 할 수 있으면 짧게 다시 쓰라 하고, `NO-SQUEEZE` 는 산문을 분량에 맞추려 압축하지 말라 한다. |
| `YAGNI` · `RESOLVE-NOW` | 요청 밖의 미해결 문제를 `RESOLVE-NOW` 는 지금 해결하라 하고, `YAGNI` 는 구현하지 말고 제안하라 한다. |
| `FULL-SENTENCE` · 「KO-SYNTAX」 | `FULL-SENTENCE` 는 표 셀에 명사구를 허용하지만, 「KO-SYNTAX」 머리의 예외 목록에는 개조식 항목만 있고 표 셀이 없다. 설계 문서가 인용한 '표 셀 예외' 충돌이다. |
| `NO-ANALOGY` · 「머리말」 | 「머리말」은 한 번 읽고 이해하는 글을 가장 먼저 따지라 하고, `NO-ANALOGY` 는 비유를 금지한다. '지어낸 비유'가 예시까지 포함하는지 범위가 정해져 있지 않다. |
| `작은 변경` · `NO-RAW-OUTPUT` | 줄 수가 적은 새 spec·plan 이 리뷰 면제 대상인지 문안에 없다. `docs/domain-discipline.md` 의 2026-10-21 해석(새 spec·plan 은 면제 대상이 아님)으로 해소되었으나 원칙 문안에는 반영되지 않았다. |

## 집계

ID 조항은 46개, 절 머리 지시는 14개로 행은 모두 60개다. 후보 표시는 아래와 같고, 한 행이 둘 이상의 표시를 받으면 각각 셌다.

## 이 기록 뒤의 변경

spec 은 이 기록을 보고 「실행 순서」 결정점을 더하고, 이 기록이 쓴 결정점 묶음을 「쓰기 공통」이라는 이름으로 결정점 표에 정의했다. 그래서 위 표의 `ASYNC-FIRST` 행과 결정점 이름을 spec 에 맞췄다. 103행 근처 문단은 변경 전 판단을 그대로 남긴다.
