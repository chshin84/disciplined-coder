# 선행연구 검증자 구성 결정 기록(2026-10-21)

이 파일은 기록 타입이다. 기록한 뒤 고치지 않고, 결정이 바뀌면 새 기록을 남긴다. 설계는 `docs/superpowers/specs/2026-10-20-prior-art-verifier-tiering-design.md`, 시험 절차는 `docs/superpowers/plans/2026-10-21-prior-art-verifier-tiering-selection.md`, 원자료와 보고는 `evals/prior-art-verifier/results/` 에 있다.

## 고른 구성

모든 카테고리에서 Haiku 5.5 low 를 고른다. 판정 에이전트는 수치·조건·방향·범위를 함께 맡는 하나로 묶는다.

| 에이전트 | 맡는 카테고리 | 설정 | 도구 |
|---|---|---|---|
| 추출 검증자 | 접근, 존재, 구절 | Haiku 5.5 low | WebFetch, Read |
| 판정 에이전트 | 수치·조건, 방향, 범위 | Haiku 5.5 low | Read |
| 지도 대조 에이전트 | 지도 대조 | Haiku 5.5 low | Read |

수치·조건 카테고리는 채택 규칙으로는 고르지 못했다. 그래도 Haiku low 를 제안하는 이유는 아래 「고르지 못한 카테고리」에 있다. 이 제안은 사용자 승인이 필요하다.

## 비용

비용은 `claude -p` 의 `total_cost_usd` 이고, 시험 자료 한 번(URL 11개, 지도 대조 1건)을 끝까지 판정하는 데 든 값이다.

| 구성 | cite 계열 | 지도 대조 | 합계 |
|---|---|---|---|
| 기준선(현행 Opus 5.5 medium 단일 검증자) | $2.1409 | $0.2117 | $2.3526 |
| 고른 구성 | 추출 $0.0923 + 판정 $0.0355 | $0.0054 | $0.1332 |

고른 구성은 기준선 비용의 약 5.7% 다. 이 비교는 단계별 단독 실행을 더한 값이다. 묶은 구성 전체를 다시 측정하는 일은 다음 plan 의 병합 조건이다. 이번 시험 전체(기준선 포함)에 든 비용은 $5.81 이다.

## 카테고리별 성적

기준선은 두 번 실행했고 모든 카테고리에서 오류 통과 0건, 참 기각 0건, 흔들림 0이었다. 그래서 채택 조건은 한 건도 틀리지 않는 것이다.

| 카테고리 | 단계 | Haiku low | Haiku medium | Haiku high | 고른 설정 |
|---|---|---|---|---|---|
| 접근 | 추출 | 0 / 0 | 0 / 0 | 0 / 0 | Haiku low |
| 존재 | 추출 | 0 / 0 | 0 / 0 | 0 / 0 | Haiku low |
| 구절 | 추출 | 0 / 0 | 0 / 0 | 0 / 0 | Haiku low |
| 수치·조건 | 판정 | 0 / 1 | 0 / 1 | 0 / 1 | 없음 |
| 방향 | 판정 | 0 / 0 | 0 / 0 | 0 / 0 | Haiku low |
| 범위 | 판정 | 0 / 0 | 0 / 0 | 0 / 0 | Haiku low |
| 지도 대조 | 지도 대조 | 0 / 0 | 0 / 0 | 0 / 0 | Haiku low |

칸의 값은 "오류 통과 / 참 기각" 이다. 수치·조건은 Haiku xhigh 와 Sonnet low·medium·high 도 실행했고, 모두 0 / 1 이었다. 판정 단계 비용은 Haiku 가 카테고리당 약 $0.012, Sonnet 이 약 $0.21 이었다.

## 고르지 못한 카테고리

수치·조건에서 모든 설정이 기각한 참 항목은 `num-t3` 하나다. 주장은 "Claude Code CLI 세션 1,650개를 분석한 연구는 상시 지시 파일의 크기 효과를 검출하지 못했다" 이다. 추출 단계(Haiku low)가 넘긴 구절은 "None of the four structural variables ... produces a detectable contrast" 였고, 이 구절에는 세션 수가 없다. 판정 에이전트는 Haiku·Sonnet 의 모든 수준에서 "구절에 1,650 이 없고 '다중 비교 보정 뒤' 조건이 주장에서 빠졌다" 고 판정했다. 이 판정은 인용 판정 기준("옮긴 구절이 주장의 주어와 수치와 조건을 모두 포함하면 supported")에 맞는다. 기준선 Opus 는 페이지 전체를 보고 통과시켰다.

그래서 원인은 판정 모델이 아니라 추출 단계가 고른 구절이다. 같은 입력이면 Opus low 도 같은 판정을 낼 것으로 보고 실행하지 않았다(가정). 이 가정은 Opus low 를 같은 입력으로 한 번 실행하면 확인할 수 있다.

처리 제안은 둘이다.

- **제안 1(권장):** 수치·조건도 Haiku low 로 두고, 다음 plan 에서 추출 프롬프트에 "주장의 수치·조건이 든 구절을 우선 옮겨라" 를 넣은 뒤 구성 전체 재측정에서 `num-t3` 가 통과하는지 확인한다. 이 결함은 모델을 올려도 사라지지 않았으므로 프롬프트가 고칠 곳이다.
- **제안 2:** 수치·조건만 기준선처럼 원문 전체를 보는 설정으로 둔다. 판정 에이전트가 웹을 열어야 하므로 spec 의 구조를 바꿔야 한다.

## 그 밖의 관찰

- 추출 단계(Haiku low)만으로 수치·조건·방향·범위의 오류 항목 9건 중 8건이 기각되었다. 원문에서 그 주장을 뒷받침할 구절을 찾지 못했기 때문이다. 판정 에이전트가 따로 잡아야 하는 오류는, 구절은 원문에 있는데 주장이 그 뜻을 비튼 경우다. 시험에서는 이런 경우를 짝 참 항목의 구절을 넣어 만들었고, Haiku low 가 모두 잡았다.
- 지난 실행에서 부정어가 잘렸던 arXiv 2605.10039 는 Haiku low 추출에서 "None of ..." 가 구절에 그대로 담겼다. 같은 출처에서 결말을 뒤집은 오류 항목(`dir-f1`)도 기준선과 Haiku low 가 모두 잡았다.
- 지어낸 문서 경로(`acc-f2`)는 HTTP 200 을 돌려줬지만, 기준선과 Haiku 의 모든 수준이 문서가 없다고 판정했다.

## 실행 조건

- API 키가 없어 `--bare` 대신 로그인된 CLI 에 `--setting-sources "" --strict-mcp-config --disable-slash-commands --no-session-persistence` 를 붙였다.
- 실행 폴더는 `D:/dc-eval-tmp` 아래였다. 전역 CLAUDE.md 는 실리지 않았다(확인 방법은 `evals/prior-art-verifier/README.md`).
- 실행 기록 87줄과 추가 12줄의 `models_used` 가 모두 요청 모델과 일치했고, 오류 줄은 0개였다.
- 노력 수준은 `--effort` 로 요청했다. 실제 적용 값은 CLI 출력에 없어 대조하지 못했다. 그래서 `CLAUDE_CODE_EFFORT_LEVEL` 을 지운 환경에서 실행했다.
