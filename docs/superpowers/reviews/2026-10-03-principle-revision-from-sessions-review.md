# 세션 기록 기반 원칙 퇴고 설계 리뷰

대상은 `docs/superpowers/specs/2026-10-03-principle-revision-from-sessions-design.md` 이고, 렌즈 원본은 같은 이름의
폴더에 있다. 렌즈를 한 번씩만 실행했다.

## 합친 지적

| 지적 | 잡은 렌즈 |
|---|---|
| 문구 정리와 의미 변경의 경계를 문안 작성자가 혼자 판정해 묻지 않고 반영될 수 있다 | adversarial |
| 판정 규칙이 동점을 채택과 추가 실행 양쪽으로 처리한다 | adversarial, consistency |
| 조항마다 푸시하면 사용자 확인 전에 모든 프로젝트 세션에 퍼지고, 푸시가 사용자 결정 목록에 없다 | adversarial, consistency |
| 후보를 계획 문서로 옮기면 사용자 발화가 공개 원격에 커밋되고, 비밀 제거 규칙이 참고서 인용에만 있다 | adversarial |
| 일회성 묶음을 기록도 보고도 하지 않아 사용자가 올릴 입력이 없다 | adversarial, consistency |
| 발화 네 분류를 처분 표가 쓰지 않는다 | adversarial |
| 근거 후보 처분이 목표에 없고 공개 인용과 통보를 늘린다 | adversarial |
| 과제 선택·문안·채점이 한 세션에 몰린다 | adversarial |
| 146개 파일 크기를 폴더 전체 크기 1.2GB 로 적었다 | grounding |
| '지시와 근거의 분리' 행의 사례가 CLAUDE.md 의 명령형 기준이고, 같은 이름의 기존 불릿과 다른 내용을 가리킨다 | grounding, consistency |
| 자기 적용 행의 대구 사례에 출처가 없다 | grounding |
| kw-plugins 알림 조건에 조항 문구 변경이 빠졌다 | grounding |
| 메모리 규칙의 범위를 '작업 트리'로 좁혀 인용했다 | grounding |
| 범위 밖과 메모리 쓰기가 부딪힌다 | consistency |
| 조항 후보 채택과 의미 변경을 묻는 단계가 번호 절차에 없다 | consistency |
| 새 퇴고 기준의 근거 발화를 둘 곳이 산출물 규칙과 부딪힌다 | consistency |
| 처분 표에 새 퇴고 기준으로 가는 처분이 없다 | consistency |
| 근거 후보·맥락·삭제 이력 처분의 확인 방법이 없다 | consistency |
| 기각·삭제 결과를 기록할 곳이 없다 | consistency |
| 조항 ID 가 없는 출력지시 머리말의 측정을 둘 절이 없다 | consistency |
| 퇴고 기준의 확인 방법이 검사 하나만 요구한다 | consistency |
| 조항 후보·새 조항·새로 찾은 기준과 '기준'의 여러 용법이 섞였다 | consistency |
| '참고서'와 '근거 문서'가 같은 대상의 두 이름이다 | consistency |
| plan 을 쓸 때 후보 작업을 알 수 없어 plan 크기가 정해지지 않는다 | consistency |
| 사례 열과 처분 표 열의 말끝이 맞지 않는다 | fit |
| 개수 예고('세 곳'), 개수 대명사('두 참고서'), 판단에 쓰이지 않는 개수(146개, 1,355건)가 있다 | fit |
| 다섯 문장 단락, 여러 문장 불릿, 수식어 쌓기, 문장 중간 관형절, 명사 조각 첫 줄이 있다 | fit |
| '클린룸 소거 시험'과 '빈 모델'의 풀이가 없고 시험 이름이 둘이다 | fit |
| 표 머리 '보는 것'이 '것'을 썼다 | fit |

## 커버리지 공백

모든 렌즈가 결과를 돌려주었다. Explore 서브에이전트에 전역 원칙 사본이 실리는지는 adversarial 과 consistency 가
함께 확인 필요로 남겼고 어느 렌즈도 측정하지 않았다. 원격 공개 여부는 adversarial 이 추정으로 남겼다.

## 선행연구 렌즈

붙이지 않았다. 이 spec 은 이미 하던 원칙 퇴고와 클린룸 시험을 절차로 정리하는 일이라 발동 기준에 해당하지 않는다.
