# 2026-09-22 HTML 아티팩트 금지 표현 검사 설계 — 렌즈 리뷰 기록

검토 대상은 `docs/superpowers/specs/2026-09-22-html-artifact-banned-words-design.md` 이다. 렌즈 넷을
대상 하나에 각각 하나씩 실행했다. 쓰기 도구가 없는 에이전트 종류로 실행해 읽기 전용을 구조로
강제했다.

렌즈를 한 번씩만 돌렸다.

선행연구 렌즈(`lens-prior-art`)는 붙이지 않았다. 발동 기준은 "아직 해본 적 없는 것을 해내려 하고
그것이 되는지 자체가 미지수인가"인데, 이 설계는 이미 있는 검사를 다른 형식으로 넓히는 정리
작업이라 기준에 해당하지 않는다. 검토 대상이 `docs/superpowers/specs/` 아래에 있어 spec 으로
판정했다.

## 렌즈 넷이 모두 돌아왔다

`lens-adversarial` 이 나머지 셋보다 100초 늦게 돌아왔다. 출력이 301초 멈춰 있어 중단으로 보고 이
기록을 커버리지 공백으로 먼저 적었는데, 그 뒤에 도착해 다시 썼다. 기다리기를 언제 그만둘지 판단할
근거가 이 절차에 없다는 것이 드러난 곳이다.

## 사실 오류 — `lens-grounding` 과 `lens-consistency` 가 함께 잡은 것

| 발견 | 확인 결과 |
|---|---|
| `banned_report` 호출자에 `check_banned_words.sh` 가 없다 | 사실이다. 훅 셋과 `scripts/test_hooks.sh` 의 네 자리(`293`·`294`·`296`·`312`)다 |
| `banned_scan` 소비자가 대구 한도 검사가 아니다 | 사실이다. `check_banned_words.sh:51` 과 `test_hooks.sh:298` 이다 |
| 확장자 조건이 `path_in_own_repo` 보다 앞이다 | 사실이다. `30`·`44`·`52` 가 앞이고 `36`·`48`·`56` 이 뒤다 |
| 추출기가 `git mv` 도 본다 | 사실이다. `_extract_bash_targets.sh:60,63-66` 이 그 분기다 |
| Pre 훅만 `docs/superpowers/` 의 상대경로 형태를 빠뜨렸다 | 사실이다. Post 와 Stop 은 두 형태를 받는다 |

세 번째 발견의 결론은 과장되어 있다. `lens-grounding` 은 확장자에 `.html` 을 추가하면 이 저장소
자신의 HTML 이 새로 검사 대상이 된다고 적었으나, 확장자 조건을 지난 뒤 `path_in_own_repo` 가 여전히
실행되므로 이 저장소는 계속 제외된다. 순서 서술이 틀렸다는 것만 받아들인다.

## 설계 판단이 하나 뒤집혔다

파서를 물리친 근거가 성립하지 않는다. 설계는 "파서를 들이면 빠른 거르기가 무의미해진다"고 적었는데,
그 거르기는 셸의 `grep` 이라 파이썬 프로그램 밖에 있다. 정규식을 `html.parser` 로 바꾸는 것은 이미
실행 중인 같은 파이썬 안의 일이고 표준 라이브러리라 프로세스가 늘지 않는다. 정확도를 포기할 근거가
사라졌다.

`lens-grounding` 은 Pre 훅의 거르기 서술도 부정확하다고 지적했다. 그 거르기는 본문이 아니라 훅 입력
JSON 전체를 보고, 입력에 `\u` 가 있으면 거르기 자체를 건너뛴다.

## 미정인 것

**형식 인자의 이름과 자리와 값.** `lens-consistency` 가 문서 어디에도 없다고 지적했다. `test_hooks.sh:296`
이 인자 둘로 호출하므로 자리를 `$3` 에 두면 기존 호출이 전부 어긋난다.

**HTML 픽스처의 형태.** 지금 픽스처는 `dwj()` 가 이스케이프 없이 `printf` 로 JSON 을 만든다. 따옴표가
든 HTML 을 그대로 넣으면 JSON 이 깨지는데, 성공 기준이 이름으로 부르는 `<style>` 의 클래스 이름과
`<script>` 안의 문자열이 바로 그 자리다.

## 내부 모순과 연쇄 누락

**경계와 작업 범위가 부딪친다.** 설계는 대상을 "Write 와 Edit 이 직접 쓰는 것만"으로 좁히면서 배제
근거를 Pre 훅 하나로 대는데, 3단계는 Post 와 Stop 까지 넓힌다. 그 둘은 Write 와 Edit 을 보지 않는다.

**엔티티 단계가 검출을 늘리지 못한다.** 빠른 거르기가 원시 바이트를 보므로 엔티티로만 적힌 금지어는
파이썬에 도달하지 않는다.

**연쇄 둘이 빠졌다.** `README.md` 의 네 줄(`58`·`63`·`65`·`74`)이 훅의 대상을 `.md` 로 적고,
`hooks/doc_word_pretooluse.sh:6` 이 산출물 정의를 `.md` 로 적는다. 작업 순서에 그 갱신이 없다.

## 규칙 적합성 — `lens-fit`

결정론 검증이 한 건을 냈다. 70행의 `훑` 이고 백틱 밖 산문이다. 백틱 안의 `꼴` 과 `글꼴` 둘은 다른
세션의 검사 출력과 그 거짓 검출의 출처를 인용한 것이라 정당하다.

형식 지적이 열하나다. `A가 아니라 B` 대구가 두 번(`36`·`99`)으로 한도를 한 건 넘겼고, 연결어미 뒤
쉼표가 열한 곳이며, 소제목 「건드리지 않는 것」이 명사구가 아니고, 이름이 있는 대상을 '것' 으로
가리킨 곳이 다섯이다. 「작업 순서」 표의 확인 방법 열에서 3행만 말끝이 다르고, 「마크업을 버리는 층」과
「작업 순서」 두 절이 소제목 아래 첫 문장에 결론을 두지 않았다. `banned_report` 와 `path_in_own_repo`
와 「검사 다섯 벌」이 처음 나올 때 풀리지 않았고, '겹' 과 '층' 이 같은 뜻의 다른 이름으로 쓰였다.
첫 줄 "작성일 2026-09-22." 가 명사 조각이다.

`WRITTEN-ONLY` 위반은 없다.

## 실패 모드 — `lens-adversarial`

이 렌즈가 설계의 전제를 뒤집는 지적을 냈다.

**`.html` 은 산출물 확장자이면서 코드 확장자다.** `.md` 로 대상을 정의할 수 있었던 것은 그 형식이
거의 언제나 산문이기 때문이다. HTML 은 웹 프로젝트의 템플릿과 컴포넌트와 정적 페이지로도 쓰이고,
그것들은 Write 와 Edit 으로 직접 쓰인다. 한국어 문자열이 든 템플릿을 고치는 모든 프로젝트에서 편집이
거부되는데, 그 HTML 은 사람이 읽는 산출물 문서가 아니라 코드다. 제외 셋은 경로만 판정하므로 둘을
구분하지 못한다.

**거부 메시지가 통하지 않는 회피를 안내한다.** 훅 셋의 메시지가 "그 말 자체를 문서에 적어야 하면
백틱으로 감싸라"고 적는데, HTML 경로에는 백틱 정규식이 적용되지 않는다. 지시대로 백틱을 추가해도
같은 이유로 다시 거부되고, 그 사이 발행되는 페이지에는 백틱 문자가 그대로 보인다.

**남은 수단이 문장 고치기가 아니라 스위치 끄기다.** 설계는 "편집이 거부되면 문장을 바꾸는 것 말고
수단이 없다"고 적었으나 `DISCIPLINED_CODER_REPLY_CHECK` 가 있다. 그 변수는 훅 셋 모두의 첫 줄에서
읽히므로 한 번 끄면 마크다운 검사까지 함께 사라진다. 훅 자신의 주석이 "거짓 거부가 되어 훅을 끄게
만든다"고 그 경로를 이미 적어 두었다.

**거짓 검출을 푸는 데 최소 하루가 든다.** 제외어는 외부 저장소가 소유하고 원본 수정과 하루 한 번의
cron 동기화와 PR 병합과 각 PC 의 플러그인 갱신 넷을 지난다.

**Edit 의 본문은 문서 조각이다.** 태그 제거 정규식이 조각에서 반대 방향의 오류 둘을 낸다. 여는 태그가
없는 조각에서는 속성값이 산문으로 남고, 산문의 부등호와 뒤쪽 태그의 `>` 사이가 한 태그로 지워져 그
사이의 산문이 검사에서 사라진다.

**값을 측정하지 않았다.** 금지 표현 표의 검색 글자에 한 글자가 여럿 있어 한국어 HTML 이면 빠른
거르기를 거의 언제나 통과한다. 이 저장소는 답 하나에 1,021밀리초가 든다는 실측을 근거로 훅 하나를
걷어낸 전례가 있는데, 이 설계에는 HTML 한 벌을 검사하는 값이 없고 성공 기준에도 시간 조건이 없다.

**3단계와 4단계의 차례가 뒤집혀 있다.** 3단계의 확인 방법이 4단계가 만드는 픽스처를 요구한다. 그리고
3단계만 되돌리면 4단계가 추가한 단언이 남아 검사가 실패하므로, 되돌리기 단위는 그 둘이 함께다.

## 처분

`lens-adversarial` 이 스스로 처분을 정하지 않고 사용자 결정으로 올린 것이 하나다. 확장자를 추가하되
산출물과 코드를 구분할 다른 조건을 둘 것인지, `.html` 을 Pre 훅의 거부에서 빼고 Post 와 Stop 의
통지로만 둘 것인지다. 그 결정이 나머지 지적의 처분을 바꾸므로 여기서 멈춘다.

나머지는 전부 고칠 것으로 분류한다.
