# AI 티와 사용자 피로감의 선행연구 기록

## 프로토콜

사용자는 2026-11-03 에 승인 없이 진행하라고 지시했다. 그래서 승인 단계 없이 실행한다.

- **연구 질문:** 언어 모델 출력의 'AI 티'와 코딩 에이전트 사용자의 피로감은 무엇으로 정의·측정되며, 지시문의 어떤 형식이 위반을 줄이는가.
- **상황:** 결정 근거 탐색이다. 모드는 `survey` 이다.
- **대조 대상:** 조항 변형 8종의 설계 기준과 판정 지표 후보이다.
- **용도:** 사용자가 조항을 고를 때 위반 제거를 주 목적으로, AI 티 제거와 피로감 완화를 부 목적으로 최적화한다.
- **연구자 수:** 4개이다. 하위 질문이 4개이고 묶지 않으므로 통상 값 2개를 넘긴다.
- **질의 금지 목록:** 회사·기관 이름과 저장소 이름, 사람 식별자 범주로 낱말 8개를 펼쳤다.

## 하위 질문

- **sq1:** LLM 생성 글의 특징과 'AI slop'의 정의·측정 방법이다.
- **sq2:** 한국어 LLM·기계 번역 문체의 번역투와 어색한 표현의 측정 방법이다.
- **sq3:** 코딩 에이전트와 AI 도우미 사용자의 피로(검토 부담, 승인 피로, 인지 부하, 신뢰 감소)의 정의와 측정 방법이다.
- **sq4:** 시스템 프롬프트 지시 형식(긍정·부정, 예시, 역할, 점검표)이 지시 준수에 주는 효과이다.

둘러보기는 시간을 줄이려고 생략했다. 이 생략은 스킬의 생략 조건 밖이며 오케스트레이터의 판단이다.

## 처분 전 결과

`overall_status` 는 `not-ok` 이다. 사례 34건 중 7개 참조만 통과했고, sq2 와 sq3 는 통과 0건이다. 그래서 피로감의 정의와 번역투 지표에는 검증된 근거가 없다. 원본은 같은 이름 폴더의 `prior-art-r1.json` 에 있다.

통과한 근거에서 가져온 내용은 아래와 같다.

- **평가 방식:** 숙련 사용자 5명의 다수결은 기사 300건에서 오류가 1건이었고, 이들은 어휘뿐 아니라 격식성·독창성·명료성을 근거로 들었다(arXiv 2501.15654). 일반 참가자의 정확도는 약 59% 였고, 언어 특징은 판단에 강건한 영향을 보이지 않았다(LREC 2026). 그래서 어휘 지표의 감소를 체감 감소로 단정하지 않는다.
- **지시 형식:** 지시와 예시의 결합이 예시 단독보다 큰 효과를 냈다. 다만 Gemini 2.5 Pro 의 코드 토큰 수를 측정한 결과다(arXiv 2511.13972).
- **역할 지시:** 역할 162종의 효과는 사실 정답률에서 대체로 무작위였다(arXiv 2311.10054). 문체 효과를 측정한 연구는 아니다.
- **지표 보고:** 동시 제약에서 조항별 통과율과 전체 통과율이 크게 벌어지므로 둘 다 보고한다(Constraint Saturation Evaluation, 2차 출처).

## 설계에 쓴 정의

아래 두 정의는 오케스트레이터가 정한 설계 가정이다. 통과하지 못한 후보 근거와 사용자 지적을 참고했으며, 검증된 정의가 아니다.

- **AI 티:** 사람이 쓴 업무 글에서 보기 어려운 표현(`ai_lexical`)과 틀에 박힌 구성(`ai_template`)의 1천 자당 수이다.
- **사용자 피로감:** 답 하나를 소화하는 데 사용자가 추가로 드는 일이다. 요구받은 행동(`fatigue_actions`), 앞 대화를 다시 찾는 곳(`fatigue_refetch`), 읽지 않아도 되는 문장(`fatigue_unasked`), 따로 확인해야 하는 주장(`fatigue_verify`)으로 측정한다.
