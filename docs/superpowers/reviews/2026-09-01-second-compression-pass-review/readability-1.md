# lens-readability — 1회차 원본

대상: `docs/superpowers/specs/2026-09-01-second-compression-pass-design.md`
`purpose`: 이 저장소를 이어받는 다음 세션이, 둘째 회차에서 무엇을 어떤 순서로 고칠지와 무엇이 되면 끝인지를 이 문서만 읽고 정하게 한다.
`principles_applied`: PROSE-FORM, READ-FLOW, PLAIN-KO, KO-SYNTAX, CLEAR-COMM, EXPLICIT

## 이슈 아홉

1. **wrong-job — 순서가 없다** 할 일 셋을 나열하나 어느 것을 먼저 하는지와 왜 그 차례인지가 없다. 다섯을 차례로 놓은 rewrite를 함께 받았다(추론해 새로 쓴 것이라 사실 확인이 필요하다).
2. **wrong-job — 완료 기준이 없다** 숫자가 나오는 곳이 모두 지금 상태이고 도달할 값이 아니다. 「완료 기준」 표 rewrite를 받았다.
3. **structure — 소제목 다섯이 서술문이다** 명사구가 아니라 훑어서 대상을 못 고른다. 다섯 모두의 rewrite를 받았다(제목의 주장을 첫 문장으로 내린 것이라 새로 지어낸 말이 없다).
4. **language — 표 머리 「잰 것」** 금지 어간이 인용이 아니라 실제로 쓰인 유일한 곳이다. rewrite는 「측정 항목」이다.
5. **language — 금지 낱말 여덟은 인용이다** 표 셀과 백틱 안은 세는 대상이라 고치면 안 된다. rewrite를 비웠다. 다만 훑기를 넓힐 때 이 인용을 어떻게 뺄지 정해 두지 않으면 첫 실행이 헛걸음이 된다.
6. **language — '걷는다'가 비유다** 세 곳에서 '지운다'의 자리에 쓰였고 통째로 지우는지 줄이는지 갈리지 않는다. '지운다'로 바꾸는 rewrite를 받았다.
7. **friction — '검사'가 셋을 가리킨다** 레포 전체 검사, 금지 표현 훑기, 아직 없는 두괄식 훑기다. 「안 하는 것」의 경계가 무너진다. 이름을 갈라 붙인 rewrite를 받았다.
8. **structure — 성과표가 앞에 있다** 결정에 쓰이는 것이 20줄 아래에서 시작한다. 절 순서를 바꾸고 성과표를 맨 뒤로 옮기는 rewrite를 받았다(원문을 한 글자도 안 버린다).
9. **language — 결과를 안 적은 서술어 넷** 38·56·66-67·68줄이다. 각각의 rewrite를 받았다(추론해 새로 쓴 것이라 사실 확인이 필요하다).

## 관찰 축 열 (세는 범위 — 문서 전체 69줄, 제목 11개·표 3개·목록 2개 포함, 표 셀은 길이와 수식 축에서 제외)

| 축 | 값 |
|---|---|
| 강조 | 굵힌 구간 0곳이다 |
| 끊김 | 산문과 표 사이를 여섯 번 오간다 |
| 이음 | 문단 아홉 가운데 앞 문단을 받는 것이 하나다 |
| 목록 | 목록 둘에 항목 다섯이고 문장이 둘 이상인 것이 넷이다 |
| 끼움 | 괄호 부연 둘이고 본문 열아홉 문장 대비다 |
| 이름 형태 | 제목 열하나 가운데 명사구가 아닌 것이 다섯이고, 첫 문장이 결론인 절이 넷이며 아닌 절이 셋이다 |
| 형태 섞임 | 한 표와 한 목록 안에서는 말끝이 맞다 |
| 두루뭉술한 결과 | 넷이다 |
| 길이 | 중앙값 38자이고 최장 62자라 퍼짐이 좁다 |
| 수식 | 관형절이 가운데 낀 곳 셋, 수식이 두 겹 쌓인 곳 둘, 비슷한 명사구가 겹친 곳 하나다 |

## notes
열 밖의 방해 둘을 함께 올렸다 — '검사'가 세 대상을 가리키는 것과 성과표의 배치다. 더 확인할 것 셋 — 큰 문서 셋의 목표 크기를 사용자에게 받아야 완료 기준의 마지막 행이 판정되고, 제안한 다섯의 차례는 실제 의존 관계를 확인해야 하며, `lens-readability`가 spec에 걸지 않는다고 정해 둔 것과 이 배정이 어긋난다.
