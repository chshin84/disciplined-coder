# 문서 검진 — 남은 핸드오프 넷을 처리한 회차 (2026-08-18)

## 무엇을 검진했나

`temp_handover.md`에 남아 있던 넷을 처리한 뒤, 고친 문서 전체에 렌즈를 걸었다. 처리한 넷은 이렇다.

- `surface`를 '알린다'로 바꾸는 것을 끝냈다.
- `reviewer-readability`의 굵기를 자기 처방에 맞게 줄였다.
- 정본에서 오답노트 형식 규칙의 상세를 덜어 내고 `domain-docs`를 소유자로 두었다.
- README의 「구성」 트리를 `docs/DESIGN-NOTES.md`로 옮기고 절 순서를 목적선에 맞췄다.

렌즈는 셋을 각각 한 번씩 읽기 전용 서브에이전트로 띄웠다. `reviewer-grounding`과 `reviewer-fit`은
고친 문서 전체에 걸었고, `reviewer-readability`는 README 하나에 걸었다. 셋 모두
`principles_applied`를 채워 돌려주었다.

readability에 준 목적은 이 한 줄이다 — "이 플러그인을 처음 보는 Claude Code 사용자가, 이게 자기
문제를 푸는 물건인지 훑어서 판단하고, 그다음 설치 명령을 그대로 따라 쳐서 실제로 동작하는 상태까지
이르게 한다."

## 반영한 것

### 근거 렌즈 — 문서가 코드에 대해 한 말이 틀렸다

- **스캐폴드 실패 사유를 둘로 적었으나 실제는 셋이다.** `_scaffold_common.sh:131`이
  `boundary|backup|write` 셋을 선언하고 `:190-198`이 각각 다른 문안을 낸다. 이 회차에 새로 넣은
  `domain-docs` 문단과 README가 둘만 적었다. 빠진 `write`는 권한을 풀 자리가 백업 디렉터리가 아니라
  로그가 놓인 디렉터리라 처방이 아예 다르다. 둘 다 셋으로 고쳤다.

### 계약 렌즈

- **`surface`를 지웠는데 직역만 남은 자리 둘을 놓쳤다.** `nested-orchestration`의 "표면에 표시되지
  않는다"와 DESIGN-NOTES의 "훅 표면"이다. 영어 낱말만 찾는 검색으로는 안 걸렸다. 각각 "화면에 나오지
  않는다"와 "훅을 걸 수 있는 자리"로 고쳤다.
- **DESIGN-NOTES가 항목을 "여덟 개"라고 적었는데 실제로 아홉이다.** 개수를 안 박는 표현으로 바꾸고
  왜 안 박는지를 함께 적었다(`NAME-ITEMS`).
- **리뷰어에게 정본을 알리는 규율이 네 문서에 중복되어 있었고 이미 갈라져 있었다.** DESIGN-NOTES 쪽에
  `principles_applied` 요구와 자동 재시도 금지가 빠져 있었다. 사용자가 `domain-docs`를 소유자로
  정했다. 그 스킬에 「리뷰어에게 정본을 알리는 법」 절을 세우고 나머지 셋을 포인터로 바꿨으며,
  `test_docs_drift.sh`에 소유자만 규율을 적는지 보는 검사를 더했다.
- **굵기 정리를 총량으로 보고했으나 이 렌즈의 축은 통째로 굵힌 것의 비중이다.** 「손대지 않는 것」의
  불릿 넷이 모두 문장 전체를 굵히고 있었다. 짧은 라벨만 굵히도록 바꿔 완결 문장 굵기가 열하나가 됐다.

### 가독성 렌즈 — README

- **「사용」 절이 사용자가 얻는 것보다 훅의 내부 동작을 먼저 말하고 있었다.** 결과를 첫 문단으로
  올리고 내부 동작 넷을 그 뒤로 내렸다.
- **절의 큰 순서가 목적과 어긋났다.** 설치를 막는 경고(「주의」)가 설계 근거(「무엇을·왜 자동화하나」)
  뒤에 있었고, Claude 사용자 동선 한가운데 Codex 절이 끼어 있었다. 순서를 「무엇이 좋은가 → 설치 →
  사용·검증 → 주의 → Codex → 무엇을·왜 자동화하나 → 더 읽기」로 바꿨다.
- **개발자용 내부 근거가 여섯 자리 남아 있었다.** 첫 세션 이중 전달 설명은 DESIGN-NOTES가 이미 더
  자세히 갖고 있어 README에서 뺐고, 서브에이전트 실측 한계는 「주의」로, 매니페스트 검사의 기여자용
  절반은 「더 읽기」로 옮겼다. 원문은 버리지 않았다.
- **화살표 사슬을 문장으로 풀었다.** `PREP → 렌즈 → meta-aggregate → 처분`이 `PROSE-FORM`이 나쁜
  예로 든 모양 그대로였다.
- README에서 「구성」 트리를 뺀 자리 자체는 깨끗하다고 확인됐다. 그 트리를 가리키던 곳은 「더 읽기」
  한 줄뿐이었고 함께 고쳤으며, 앵커 링크는 레포 어디에도 없다.

## 넘긴 것

이번 회차 범위 밖이라 알리고 넘겼다. 다음 회차에서 볼 것이다.

- `nested-orchestration`에 영어 낱말이 번역 없이 열두 자리 있다(`batch`·`mutate`·`findings`·`gotcha`).
  이 문서만 밀도가 높고, L2 프롬프트로 복사되는 자리라 대가가 크다.
- `domain-docs`의 표 셀이 명사 조각이다("재생성→diff 가드", "살아있음·PC-local"). `PROSE-FORM`이
  "표에서 가장 자주 무너진다"고 적어 둔 자리가 그 규칙의 상세 소유자에게서 무너져 있다.
- `domain-docs`가 자기가 금지한 서수(①②③④)를 두 곳에서 쓴다.
- `reviewer-readability`가 `purpose`를 `null`로 두는 규칙을 일곱 자리에 적는다. 그중 앞뒤 두 번만
  의도한 중복이라고 근거가 달려 있다.

## 검진이 못 본 것

- 근거 렌즈는 문서가 코드에 대해 하는 말만 봤다. 렌즈 자신이 읽은 코드가 실제로 그렇게 도는지는
  실행으로 확인하지 않았다(계약 테스트 네 스위트가 FAIL=0인 것으로 갈음했다).
- 가독성 렌즈는 README 하나에만 걸었다. DESIGN-NOTES는 참조물이라 자동으로 걸지 않는다.
- 반영한 뒤 다시 검진하지 않았다(문서 검진의 규율).
