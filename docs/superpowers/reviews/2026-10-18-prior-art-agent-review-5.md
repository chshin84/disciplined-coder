# 2026-10-18 spec 리뷰 5차 — 선행연구 에이전트 완전체 명세

대상은 완전체 명세로 고친 큰 명세 `docs/superpowers/specs/2026-10-18-prior-art-agent-design.md`의 새 절(「하부 명세」「공유 결정」「경계」「겹침 판정」, 「결정 기록」의 '선행연구 에이전트가 발동 기준에 들 때'·'런타임 확인' 문단)과, 현재 세션이 고친 두 하부 명세의 문장이다. 경로로 spec 이라고 판정했다. 렌즈를 한 번씩만 실행했다. 렌즈마다 general-purpose 서브에이전트 하나를 썼고, 읽기 전용은 프롬프트로만 지시했다. 고친 파일을 보고한 렌즈는 없다.

## 선행연구 에이전트의 제안

제안하지 않았다. 이번 차수의 새 내용은 이미 리뷰를 통과한 두 하부 명세를 `nested-orchestration` 절차로 합친 것이다.

## 합친 지적 목록

| 지적 | 잡은 렌즈 |
|---|---|
| 근거 지도 항목만 판정 범위를 좁혀, contrast 이슈 항목(전이·기준선 서술)은 계통적으로 `unsupported`가 된다 | adversarial |
| 근거 지도 항목 하나가 복합 주장이라 구절 하나 기준으로는 여전히 과소 통과가 남는다 | adversarial |
| `axes` 축 값에 선행 사례 쪽 서술과 대조 대상 쪽 판단을 나누는 형식이 없어 판정 범위를 지켰는지 확인할 기준이 없다 | adversarial, consistency |
| 판정 범위가 항목 종류마다 달라 시험의 '통과 사례 수' 비교가 같은 기준이 아니다 | adversarial |
| 큰 명세 「인용 판정 출력」에는 판정 범위가 없어 스킬로 옮기면 검증자 정의와 범위가 다르다 | consistency |
| 판정과 보고에 쓰는 '발견'이 `passed`인지 정해지지 않았다 | adversarial |
| 이 개발 도중에는 `agent-prior-art`가 적재되지 않아 '직접 실행'할 수단이 없다 | adversarial |
| 완료 조건 grep 을 통합 트리에서 실행하는 주체가 없다 | adversarial |
| 「오케스트레이터 절차」 본문이 워크플로를 옛 이름 `prior-art-search`로 적는다 | consistency |
| 「경계」의 '정한 곳'이 실제 정의가 있는 절과 다르고(「판정 함수」「용어」「목록의 행선지」), '가리키는 곳'에 포인터 문장이 없다 | consistency, grounding, fit |
| `specagents`의 「가정과 남은 위험」·「한 번 하는 확인」이 처분된 두 항목을 미결로 적는다 | consistency, fit |
| 두 하부 명세와 큰 명세 일부가 `agentType` 해석을 미확인 전제로 적는다 | consistency |
| `specworkflow` 리포트의 계약 의미 셋(사례 수 세는 목록, `synthesis: null`의 두 사정, `rule` 열거)이 경계에 없다 | consistency |
| 두 리포트의 제안 둘(엄격 모드·`label`·`model` 우선순위 확인, 리포트 대체 경로)이 처분되지 않았다 | consistency |
| 「결정 기록」 문단이 `RESTART` 예외를 빠뜨렸고, '서브 세션은 실행하지 않는다'가 228행 문안에 없다 | fit, grounding |
| 런타임 확인 문단이 등록 이름의 출처(파일 이름·`meta.name`)와 관측 범위를 밝히지 않았다 | grounding |
| 「겹침 판정」의 이유 칸이 '같은 동작'을 뒷받침하지 않고, 한 행은 출처 절이 빠졌다 | fit, grounding |
| 「공유 결정」 불릿이 여러 문장이고, 에이전트 정의를 워크플로를 부르는 주체로 적었다 | fit |

## 커버리지 공백

렌즈 네 개가 모두 실행되었다. `lens-fit`의 `doc_type`은 '설계' 행으로 채워졌다.
