# 가독성 렌즈 배선 — 문서 검진 기록

검진 대상 넷: `skills/reviewer-readability/SKILL.md`(새로 만듦), `skills/meta-aggregate/SKILL.md`,
`skills/domain-docs/SKILL.md`, `README.md`.

렌즈: `reviewer-grounding`과 `reviewer-fit`을 각각 한 번씩 읽기 전용 서브에이전트로 띄웠다.
`reviewer-readability`는 안 걸었다 — 이 넷은 필요한 절만 찾아 읽는 참조물이라 자동으로 거는 대상이
아니다. 두 렌즈 모두 `principles_applied`가 비어 있지 않았다.

지적 열일곱 건이 나왔고 **전부 고쳤다. 넘긴 것은 없다.** 사용자 결정이 필요한 것도 없었다 —
되돌리기 어려운 결정도, 방향이 갈리는 것도 아니었다.

## 근거 렌즈가 잡은 것 (열 건)

| 무엇 | 어떻게 고쳤나 |
|---|---|
| `p=0.0007`을 출처 없이 단정했다. 레포 전체에서 이 값이 나오는 곳이 이 파일 한 군데다 | 주장을 약하게 고치고 출처를 링크했다. "우리 측정이 아니라 소프트웨어 인스펙션 연구다"를 명시했다 |
| "앞쪽 쏠림과 가운데 묻힘이 측정되어 있다"를 완료된 사실로 적었으나 누가 무엇으로 쟀는지가 없다 | 출처 둘을 링크하고 "우리가 잰 것이 아니라 읽어 온 것"이라고 적었다 |
| 끼움 축의 "겪은 것: 문장당 0.1에서 0.6까지" — 기록에 남은 값은 0.43~0.82이고, 0.6은 두 회차가 재현 실패로 판정한 값이다 | 수치 범위를 뺐다. 대신 "세는 법에 따라 값이 두 배 가까이 갈린 적이 있다"와 "괄호가 많다고 늘 방해는 아니다"로 바꿨다 |
| 이음 축의 "우리가 잰 문서 대부분" — 기록에 남은 이음 측정은 문서 하나뿐이다 | "우리가 잰 몇 안 되는 문서에서"로 고치고 "표본이 적으니 문턱으로 쓰지 마라"를 더했다 |
| 강조 축의 판단 예시가 정의에 따라 뒤집히는 값 위에 서 있다(같은 문서의 통굵을 두 회차가 0개와 84개로 쟀다) | 특정 문서 예시를 빼고 "세는 범위에 따라 값이 크게 갈린다"로 바꿨다 |
| `meta-aggregate`의 고유 필드 열거에서 `search_status`가 빠졌다 | 넣었다. 그리고 그 필드와 `purpose`가 조용한 통과를 막는 값이라고 밝혔다 |
| `reviewer-prior-art`가 두 곳에서 "다섯 렌즈"라고 적는다. 렌즈 수를 세는 자리가 둘인데 하나만 고쳤다 | 개수를 안 박게 고쳤다("리뷰어 렌즈 가운데 이것만") |
| `domain-docs` 158줄이 여전히 "두 렌즈의 지적을 한 목록으로"다 | "그 회차에 돌린 렌즈 전부의 지적을"로 고쳤다 |
| 설계 문서는 여섯 축을 뺐다고 적었는데 렌즈가 되살렸고 그 기록이 없다 | 설계 문서의 「두었다가 뺀 것」을 다시 썼다. 뺀 이유 셋 중 하나(세는 순간 목표가 된다)가 뒤집히지 않았음을 밝히고, 무엇으로 눌렀는지 넷을 적었다 |
| 다섯 렌즈의 판정 기준을 짝지은 것이 `reviewer-consistency`의 자기 정의와 어긋난다 | 렌즈마다 무엇을 보는지 그 파일의 말로 다시 적었다 |

## 계약 렌즈가 잡은 것 (일곱 건)

| 무엇 | 어떻게 고쳤나 |
|---|---|
| 출력 스키마 블록에 `principles_applied`가 있는데 다섯 렌즈 어디에도 없다 | 블록에서 뺐다 |
| `read`의 뜻을 공통 계약과 다르게 썼다(절 이름을 적으라고 했다) | 절 이름은 `notes`에 적도록 고쳤다 |
| 목적을 못 받았을 때의 사정을 담을 필드가 없어, 빈 `issues`가 두 사정에서 똑같이 나온다 | `purpose` 필드를 더했다. `null`이면 판정 자체를 안 한 것이라 이 렌즈를 돌린 것으로 치지 않는다 |
| `meta-aggregate`의 고유 필드 열거에 `search_status`가 빠졌다 | 근거 렌즈와 같은 지적이다. 함께 고쳤다 |
| `domain-docs` 158줄의 "두 렌즈" | 근거 렌즈와 같은 지적이다. 함께 고쳤다 |
| "일곱째 칸"이 항목을 서수로 부른다. `CLEAR-COMM`이 금지하는 것이고, 축이 늘면 가리키는 자리가 조용히 달라진다 | "목록 밖의 방해"로 이름을 바꾸고, 항목이 늘어도 요구가 남는다고 적었다 |
| 관찰 항목 여섯 중 '길이'만 명사 조각으로 끝난다 | 완결된 물음으로 고쳤다 |

## 두 렌즈가 겹쳐 잡은 것

`search_status` 누락과 `domain-docs`의 "두 렌즈" 둘은 양쪽에서 나왔다. 나머지 열다섯은 한쪽에서만
나왔고, 한쪽에서만 나왔다는 이유로 덜 믿지 않았다.

## 검진이 확인해 준 것

기계로 강제되는 계약은 넷 다 만족한다. 렌즈 디렉터리 여섯과 README 트리 주석과 `meta-aggregate`의
`source` 열거가 같은 집합이고, `readability`가 spec 리뷰 디스패치 목록에 없으므로 README의 spec 리뷰
구성 줄과 `DESIGN-NOTES`에 이름이 없어야 하는데 실제로 없다. 새 렌즈 파일은 렌즈별 단언 다섯을 모두
만족한다. 훅은 렌즈 이름을 박지 않고 `domain-docs`에 위임하므로 렌즈가 하나 늘어난 것과 어긋나지 않는다.

"한 항목이 스물두 문장"은 근거가 확인됐다.
