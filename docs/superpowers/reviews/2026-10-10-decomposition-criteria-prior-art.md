# 분해 단위 기준과 재현성 — 선행연구 대조

2026-10-10에 사용자가 "superpowers 의 분해 정의가 소프트웨어 공학적으로 불명확하고 재현성이 낮다"는 관찰 뒤 선행연구 조사를 승인했다. 상한은 사용자가 4로 정했다. 대상은 `skills/nested-orchestration/SKILL.md` 「나누는 기준」「묶는 단위」와 `docs/superpowers/specs/2026-10-09-nested-orchestration-large-dev-design.md` 「2026-10-10 개정」이다. spec 리뷰 밖의 직접 요청이라 spec·plan 구분은 하지 않았다.

렌즈 원본은 같은 이름의 폴더에 있다. 번호는 호출 범위 순서다. 1·2번은 notes 를 줄여 옮겼고, 3·4번은 받은 그대로 옮겼다.

- **1. 모듈 분해 기준** — `search_status: ok`
- **2. 분해 절차** — `search_status: ok`
- **3. LLM 작업 분해 일관성** — `search_status: ok`
- **4. 분할 일치도 측정** — `search_status: ok`

## 발견

- **분해 전 단계의 변동이 규칙 밖에 있다** (1·2·3·4번 모두) — 「묶는 단위」는 하위 프로젝트 목록을 입력으로 받아 합치기만 하므로, 목록을 만드는 열거 단계의 변동은 그대로 남는다. Service Cutter 는 엔터티 속성 없이는 분해를 계산하지 못한다고 적고(원소는 도구 밖에서 고정), 산업 아키텍처 복원 연구는 엔터티 식별보다 관계 식별이 덜 안정적이라고 보고했다. 「묶는 단위 시험」은 목록을 고정해 이 단계를 재지 않았다.
- **설계 의존 합치기는 DSM·axiomatic design 기준선과 다르다** (1·2번) — DSM 분할과 axiomatic design 은 순환(상호 의존)만 한 블록으로 묶고 한 방향 의존은 순서로 둔다. 현재 규칙은 한 방향 설계 의존도 합쳐 사슬이 하나로 뭉칠 수 있다.
- **경로 겹침은 코드가 없는 단계에서 셀 수 없다** (1번) — 코드 수준 결합 측정은 코드가 쓰인 뒤에만 가능하다(Gall 외 1998). 새 개발에서는 pathspec 이 분해의 출력이라 판정이 순환한다.
- **재현성 측정이 기준선과 비교되지 않았다** (2·3·4번) — 반복 3회, 옛 규칙과의 같은 입력 비교 없음, 합칠 쌍 없는 입력, 우연 기준선 없음.
- **분할 일치도 지표의 전제** (4번) — ARI·AMI·MoJoFM 은 같은 원소 집합을 전제한다. MoJoFM 은 작은 군집이 많은 분할을 선호하고(원문 확인), ARI 는 원소가 적을 때 편향되며 두 분할이 모두 단원소이면 정의가 퇴화한다.

## 렌즈가 제안한 대안

아래는 렌즈들이 정리한 후보이며, 출처로 검증된 규칙이 아니다.

- **원소 고정 먼저** — 하위 프로젝트를 열거하기 전에 더 작은 원소(기능 요구, 숨길 설계 결정, 공유 자료)를 먼저 목록으로 고정하고 사용자 승인으로 묶어 둔다.
- **이진 DSM 표** — 원소×원소 표에 방향 있는 설계 의존을 적고, 강결합 요소(순환)만 합치며 한 방향 의존은 층 순서로 둔다. 같은 표에서는 결과가 결정적이다.
- **공유 자료 쓰기 기준** — 자료마다 그 자료를 쓰는 후보가 둘 이상이면 계약 코드로 올리거나 합친다.
- **사후 검증** — 통합 뒤 워크스트림끼리 교차 수정한 횟수, BLOCKED, 계약 변경 횟수로 분해가 맞았는지 확인한다.
- **측정 설계** — 열거 단계와 묶는 단계를 나눠 잰다. 주 지표는 N회 사이 완전 일치율과 N회당 서로 다른 분할 수, 보조 지표는 실행 쌍 ARI 평균과 공동 할당 행렬이다. 기준값은 원소가 적으므로 분할을 전수 열거한 우연 분포와 '무조건 분리' 분할로 둔다. 요청·조건마다 10회, 요청 5~8개, 합칠 쌍을 심은 요청을 절반 이상 넣는다.

## 인용 검증

현재 세션이 인용 URL 48개의 응답을 확인했다. 46개가 HTTP 200 이었고, 석사 논문 두 URL 은 403 이었으며 렌즈도 열지 못했다고 밝혔다. 원문에서 직접 대조한 문장은 셋이다. arXiv 2311.04643 의 "MoJoFM prefers architectures with many small clusters", arXiv 2601.23141 초록의 "inconsistent benchmark systems, incompatible metrics, and limited reproducibility", Context Mapper 문서의 "Without attributes, we cannot derive nanoentities and Service Cutter cannot calculate decompositions" 다.

## 결론에 영향을 주는 not_found·disclosures

- LLM 에 같은 개발 요청을 여러 번 분해시켜 일치도를 잰 선행 사례는 찾지 못했다.
- 사람 설계자끼리의 모듈 분해 일치도(kappa 등)를 보고한 연구도 찾지 못했다. 그래서 LLM 변동이 사람 기준선보다 큰지는 판단할 수 없다.
- Parnas(1972) 원문은 측정 절차를 제시하지 않고, CBO·LCOM·Martin 지표는 코드가 있어야 계산된다.
- ARI 해석 기준값(0.65·0.80·0.90)은 출처를 확인하지 못해 쓰지 않는다.
- 웹 페이지 내용은 요약 모델을 거쳐 읽었고, 일부 수치는 PDF 원문 표로 대조하지 않았다.
