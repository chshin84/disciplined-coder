# nested-orchestration 스킬·프로토콜 구현 검진 기록(2026-10-12)

대상은 「2026-10-12 개정 — 명세 단계와 다시 나누기」를 반영한 `skills/nested-orchestration/SKILL.md`와 `references/sub-session-protocol.md`다(커밋 e8492a8). 사용자가 구현된 스킬의 리뷰를 요청했고, 현재 세션은 `lens-consistency`와 `lens-adversarial`을 하나씩 실행했다. 렌즈를 한 번씩만 실행했다. 원본은 같은 이름의 폴더에 받은 그대로 있다. 필요할 때 렌즈는 제안하지 않았다. 대상이 남에게 전달하는 문서가 아니고, 선행연구는 같은 주제로 두 차례 실행했기 때문이다.

## 합친 지적

| 지적 | 잡은 렌즈 |
|---|---|
| 명세 서브 세션의 완료를 '하부 명세 커밋'으로 판정해 리뷰 전 초안에서 장벽을 넘는다 | adversarial |
| 끝난 명세 서브 세션에 `REVISE`를 보내게 되어 있고 프로토콜에 그 응답이 없다 | adversarial, consistency |
| "하부 명세를 직접 쓰지 않는다"와 현재 세션이 하부 명세를 고치는 겹침 판정이 부딪힌다 | adversarial |
| 통합용 워크트리에서 고친 큰 명세의 리뷰 마커를 확인하는 곳이 없다 | adversarial |
| 현재 세션이 고친 하부 명세 파일의 리뷰 범위가 없다 | adversarial |
| 「절 배정」 커밋 뒤 계약 코드 작성 중 상태가 진행 위치에 없고, 구현 디스패치에 계약 코드 조건이 없다 | adversarial |
| 가드레일이 명세 서브 세션의 `DONE`에도 `ws/` 브랜치 검사를 요구하고, `spec/` 브랜치의 수정 범위 검사가 없다 | adversarial, consistency |
| 시작 워크스트림이 하나일 때 직접 진행하는 체크아웃과 정리, 진행 위치 표지가 없다 | adversarial |
| 명세 단계 중 「결정 기록」에 들어간 답이 실행 중인 명세 서브 세션에 전해지지 않고 대조 기준에도 없다 | adversarial |
| 시험 병합 전 확인 경로에 하부 명세 파일이 없다 | adversarial |
| 재시작으로 잃은 `Spec-*` 트레일러 값을 무엇으로 적을지 없다 | adversarial |
| 구현 서브 세션 프롬프트에 HARD-GATE 예외 문장이 없다 | consistency |
| 진행 위치 표가 다른 저장소의 독립 작업을 명세 단계로 판정한다 | consistency |
| 파일 계약의 단위·의미 대조 시점이 계약 표가 생기기 전이다 | consistency |
| 「묶는 단위」의 '큰 명세 단계'가 어느 단계인지 가리키지 못한다 | consistency |
| 설계 승인 경로가 승인 전에 임시 분할을 커밋한다 | consistency |
| 임시 분할에 시작 의존이 있으면 명세 단계가 진행하지 못한다 | consistency |
| 「용어」와 경로 규칙이 다른 저장소의 독립 작업을 포괄하지 못한다 | consistency |
| 「진행 위치」가 근거 설계의 확인 방법 1·3항 grep 에 걸리지 않는다 | consistency |
