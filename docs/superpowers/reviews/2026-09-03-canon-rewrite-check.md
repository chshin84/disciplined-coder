# 정본 재작성 뒤 문서 검진 (2026-09-03)

정본을 한 줄씩 다시 쓰고 CLAUDE.md·README.md·스킬 열넷에 같은 처방을 적용한 뒤, 렌즈 둘을 한 번씩 띄워 검진했다. 발견은 스물둘이고 그 가운데 스무 개를 고쳤으며, 둘은 사용자가 정할 물음으로 남겼다. 렌즈 원본은 같은 이름의 폴더에 있다.

## 검진 범위와 렌즈 배정

- **`lens-consistency`** — 정본·CLAUDE.md·README·스킬 열넷을 한 묶음으로 서로 대조했다. 정본이 줄어들며 사라진 문장을 가리키는 참조와 "정본"의 쓰임을 특히 보게 했다.
- **`lens-readability`** — README 하나에 걸었다. 목적은 "설치해 본 적 없는 사람이 README만 보고 설치해 동작 확인까지 마치고, 세션에 무엇이 강제되는지 알게 한다"다. 스킬은 참조물이라 걸지 않았다.
- 렌즈는 한 번씩만 돌렸다. `lens-grounding`과 `lens-fit`은 걸지 않았다. 이번 변경은 문체와 참조 정리라 코드 사실 서술이 바뀌지 않았고, 형식 계약은 테스트가 기계로 확인했다.

## 기계 검사 결과

테스트 스크립트 전체가 ALL PASS이고 `claude plugin validate ./`는 version 경고 하나만 낸다. 정본의 옛 문구를 글자 그대로 찾던 단언 열여덟을 새 문구로 옮기거나, 뺀 조항의 단언은 지웠다. `writing-korean`의 금지 낱말은 살아 있는 문서에 남지 않았다.

## 발견과 처리

`lens-readability`의 여덟은 모두 README에 반영했다. 전제 조건을 설치 명령 앞으로 옮기고, "사용" 절을 "동작 확인과 복구"와 "커맨드"로 나누고, 첫 문단의 내부 경로 설명을 "프로젝트 폴더에 생기는 파일" 절로 옮기고, "세션에 강제하거나 고치는 것"을 "하드 게이트와 전역 설정 수정"으로 바꾸고 결론 문장을 앞에 두고, 결과를 안 적은 서술어 아홉을 고치고, 긴 문장 셋을 나누고, 진단 스니펫의 출력 문자열을 맞췄다. 잠금 대기 상수 포인터는 렌즈가 빼자고 했으나 테스트가 SSOT 근거로 요구해 한 문장으로 남겼다.

`lens-consistency`의 열넷 가운데 열둘을 고쳤다.

- README의 "활성 정본 보기"를 "적용 중인 원칙 보기"로, "렌즈에는 정본 경로를 넣는다"를 `domain-docs`가 정하는 원칙 파일 경로로, "갖는다"를 "소유한다"로 바꿨다.
- `project-doc-audit`에서 "정본"이 감사 대상 레포의 소유자 문서를 뜻하던 두 곳을 풀어 썼고, 실체 없는 「더 확인할 것」을 지웠고, 전달 방해 렌즈를 목적 없는 문서에 안 걸 때 감사 범위에 적게 했고, 몰아주기 규칙이 `domain-spec-review`의 규칙을 대신한다고 밝혔고, 통합 기록에 집계 결과 항목을 더했고, "넘길 것"을 정본의 미해결 처분에 맞췄고, 한 번만 띄우는 규율을 가리키게 했다.
- `domain-docs`의 백로그 처분을 정본의 「미해결의 처분」을 따르게 했고, 검사가 있다고만 적혀 있던 「렌즈에게 정본을 알리는 법」의 베끼기 금지에 실제 단언을 `test_docs_drift.sh`에 더했다.
- `domain-spec-review`의 리뷰 기록 항목에 상충과 커버리지 공백을 더했다.
- "회차"가 렌즈를 띄우는 횟수를 뜻하던 세 곳을 "띄우는 횟수"로 바꿨다.
- 정본 「검증」 절의 "어느 렌즈를 언제 어떻게 띄우는지는 그것을 부르는 스킬이 정한다"를 "언제 띄우는지는 부르는 스킬이 정하고, 띄우는 방법은 `domain-docs`가 정한다"로 고쳤다. 정본 문장을 사용자 승인 없이 고친 유일한 곳이라 보고에 따로 적었다.

## 사용자가 정할 물음

- **리스크 비례의 소유자** — `nested-orchestration`과 `meta-aggregate`가 "리스크에 비례해 렌즈를 고른다"를 전제하는데, 그 비례를 정의한 곳은 제품 런타임의 점수표뿐이다. 그 표를 코드 diff 리뷰에도 쓰게 할지, 따로 정할지는 설계 결정이라 고치지 않았다.
- **EXPLAIN-STRUCTURE의 상세** — 새 원칙의 상세를 소유하는 스킬이 없다. 필요한지 여부는 사용자가 정한다.

`lens-readability`가 남긴 "설치 절이 스코프를 어디서 고르는지 안 적는다"는 문서 안에 근거가 없어 고치지 않았고, 진단 스니펫의 `break`는 첫 유효 후보만 확인하는 것이 의도라 그대로 두었다.
