# 지시 트리거의 단순 추론 경계 선행연구

사용자가 2026-11-02 에 직접 요청했다. "여기에 경계선을 좀 더 알고 싶으니 선행연구를 통해 기준을 명확히 해봐라." 같은 날 승인 절차 없이 실행하도록 지시했다.

## 프로토콜

| 칸 | 내용 |
|---|---|
| 연구 질문 | 에이전트 지시의 트리거 중 모델이 단순 추론으로 판정할 수 있는 것과 복합 추론이 필요한 것의 경계를 무엇으로 정해야 하는가 |
| 상황·모드 | 결정 근거 탐색, `survey` |
| 대조 대상 | 글자·개수·사용자 메시지·도구 기록을 한 번 조회해 예·아니오가 나오면 단순 추론으로 보는 지시 트리거 기준 후보 |
| `intended_use` | 사용자가 에이전트원칙 트리거의 경계 기준을 정한다. 최적화 기준은 모델이 추가 전제 없이 예·아니오를 판정할 수 있는지와 판정자 사이의 일치다 |
| `constraints` | 콘솔 답변 교정은 Haiku 고정 단일 호출이고 문서 교정은 렌즈를 쓸 수 있다. '사용자 행동이 달라질 때'를 기준으로 삼는 안은 판정할 수 없어 기각했다 |
| 연구자 수 | 4명. 하위 질문이 서로 다른 분야라 묶지 않는다 |
| 질의 금지 목록 | 프로젝트 이름, 회사 이름, 사용자 계정 이름, 조항 ID. 낱말 12개 |

| ID | 범위 | 포함 | 제외 |
|---|---|---|---|
| `sq1` | LLM 지시 준수 평가에서 검증 가능한 지시를 어떻게 정의하고 분류하는가 | 지시 준수 벤치마크와 검증 가능성 분류 | 일반 답변 품질 평가 |
| `sq2` | 조건 복잡도, 암묵적 조건, 제약 개수, 추론 단계 수가 지시 준수에 어떤 영향을 주는가. 소형 모델의 결과를 포함한다 | 실측 연구 | 측정 없는 의견 |
| `sq3` | 요구사항 공학은 검증 가능한 요구사항과 모호한 표현을 어떻게 구분하는가 | 표준과 모호 표현 검출 연구 | 일반 작문 지침 |
| `sq4` | 프롬프트·콘텐츠 정책·규칙 작성에서 판정 일치를 높이는 조건 표현은 무엇이고 규칙형과 재량형의 경계는 어디인가 | 정책 명세 연구, 일치도 측정, 공식 가이드 | 특정 제품 사용법 |

## 둘러보기 뒤 바뀐 칸

둘러보기(`round` 0)는 조건 난이도와 제약 개수가 다른 변수라는 점을 보였다. 그래서 오케스트레이터가 연구자 수를 7명으로 올리고 하위 질문을 아래로 바꿔 `round` 1 을 실행했다.

| ID | 범위 |
|---|---|
| `sq1` | 프로그램으로 검사할 수 있는 지시의 정의와 경계 사례, 조건 판정으로 옮길 때의 차이 |
| `sq2` | 조건 하나의 추론 단계 수와 암묵적 조건이 판정 정확도에 주는 영향 |
| `sq3` | 동시 제약 개수와 지시 밀도가 준수에 주는 영향, 조건 난이도 효과와의 구분 |
| `sq4` | 요구사항 공학의 검증 가능성 정의와 모호 표현 검출의 정밀도·한계 |
| `sq5` | 예·아니오 원자 질문 분해가 판정 일치에 주는 효과와 한계 |
| `sq6` | 규칙형 문구가 판정 일치에 주는 효과, 불일치로 모호성을 측정한 사례, 일치도 지표의 한계 |
| `sq7` | 판정이 쉬운 규칙의 위반 사례, 판정 가능성과 실제 준수의 차이 |

## 처분 전 결과

`overall_status` 는 `ok` 이고 질의 경계 위반은 없다. 검증에 보낸 URL 은 51개이고 전체 실행은 에이전트 105개, 약 500만 토큰이었다. 통과 15건, 탈락 54건, 판정 불가(원문 접근 실패) 2건이다. 탈락 중 34건은 재판정 정보 부족, 7건은 판정 불가로 기각되었다. 이 41건은 구절이 주장을 뒷받침한다는 확인이 없어 기각되었으며 반박된 주장이 아니다. 나머지 13건에는 불일치 판정 등 그 밖의 사유가 포함된다.

단순 추론과 복합 추론의 경계를 직접 시험한 연구는 통과 항목에 없다. 원본은 같은 이름의 폴더의 `search-r1.json` 이다.
