# 스펙 검토 기능의 선행 사례 대조 — 선행연구 기록

## 발동과 승인

사용자가 2026-10-27 에 "선행연구조사를 통해, dc코더의 기능 중, 스펙 검토 기능 혁신적인지 생각해봐"라고 직접 요청했다. 직접 요청이므로 그 요청이 실행 제안의 승인이다. 오케스트레이터는 아래 프로토콜을 보였고, 사용자는 같은 날 "이대로 실행"을 골랐다.

오케스트레이터는 승인 화면에서 한계를 미리 알렸다. 이 스킬은 참신함을 채점하지 않고, 못 찾은 사례를 독창성의 근거로 쓰지 않는다. 그래서 혁신성 판단은 근거 지도를 바탕으로 오케스트레이터가 따로 적는다.

## 프로토콜

- 상황: 기존 도구 탐색. 하위 질문은 검색 경로 대신 메커니즘마다 나눴다. 혁신성 판단이 메커니즘 단위이기 때문이다.
- 모드: survey.
- 대조 대상: (1) 훅 게이트 — spec 파일 쓰기를 감지하고, 리뷰 마커가 없으면 턴 종료를 차단한다. (2) 실패 유형별 독립 렌즈 — 근거·정합성·적대·계약 적합 렌즈 네 개를 대상마다 따로 실행하고, 서브에이전트는 읽기 전용이며, 기대를 먼저 적는 PREP 단계를 둔다. (3) 처분 규칙 — 틀린 지적을 거른 뒤 비가역·가치판단·방향 분기만 사람에게 올리고 나머지는 자동으로 고치며, 재리뷰 범위를 제한한다. (4) 봉인된 리뷰 기록. (5) 선택 실행하는 선행연구 대조 — 웹 연구자와 인용 검증 파이프라인.
