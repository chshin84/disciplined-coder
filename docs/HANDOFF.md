**렌즈를 돌려 자기검증한 일** — 자기감사 워크플로(에이전트 115개)에서 확정 30건, 가독성 렌즈

## 열자마자 확인할 것

**2026-08-26 핸드오프에서 넘어온 확인 여섯은 이제 다 통과했다.** 마지막 하나였던 대화 스타일
우선순위도 2026-08-27에 사용자가 새 세션에서 직접 물어 확인했다 — 답이 '뮤테이션 검증'이라는
이름을 알려 주었다. 그러니 여기서 다시 확인할 것은 아래 둘뿐이고, 둘 다 명령 한 줄이다.

### 하나 — 알림 표시가 안 깨졌나

```bash
grep -c 'ð' scripts/_scaffold_common.sh
```
0이 나와야 한다. 0이 아니면 파란 점(🔵)이 이중 인코딩된 채 다시 들어온 것이다. 이 함정은
`scripts/test_scaffold.sh`의 `notice-encoding` 검사가 잡으므로 보통은 검사가 먼저 붉어진다.

### 둘 — 오답노트가 안 깨졌나

```bash
bash scripts/scaffold.sh 2>&1 | tail -4
```
설정 홈을 알리는 `note:` 한 줄 말고는 아무 신호도 안 떠야 한다. 짝 어긋남이나 못 고친 색인 줄이
뜨면 그 문구가 시키는 대로 한다.

## 이어서 할 것

같은 종류의 손질이라 한 번에 하는 편이 낫다.

- `skills/domain-docs/SKILL.md:79-85` — 문서 타입과 수명 표가 수명 열에서 개조식과 완결된 문장을 섞는다.
- `skills/domain-docs/SKILL.md:99-104` — 수정 규율 표가 한 열 안에서 명사구 셋과 문장 하나를 섞는다.

**손대기 전에 그 문구가 테스트 앵커인지 먼저 본다** — `grep -n '<고칠 문구>' scripts/test_*.sh`.
앵커였으면 검사의 뜻은 그대로 두고 앵커만 새 문구로 옮긴다.

### 설계 판단이 필요한 넷 — 사용자에게 물어야 한다

어느 쪽으로 가도 되는 갈림길이라 어제 정하지 않았다. 자율로 구현하지 말고 선택지를 띄워 물어라.

- **새 PC의 오답노트를 처음부터 쪼개진 형식으로 만들지** (`scripts/_scaffold_common.sh:149-154`) —
  지금은 스캐폴드가 안 쪼개진 옛 형식으로 만들어 놓고, 사용자가 첫 교훈을 적는 순간부터 매 세션
  개편을 권한다. 만드는 경로를 목표 형식에 맞추거나, 갓 만든 로그가 자라서 생긴 형식에는 권유를 걸지
  않는 두 길이 있다.
- **백업 이름표를 어느 쪽으로 맞출지** (`scripts/split_solved_log.sh:22`) — 쪼개는 스크립트는 부모
  폴더 이름을, 스캐폴드는 스코프 이름을 쓴다. 같은 백업 폴더에 두 규칙으로 쌓여 어느 로그의 사본인지
  가릴 수 없다. 특히 모든 레포의 프로젝트 로그가 `docs` 하나로 뭉친다.
- **짝 검사를 개수 비교에서 집합 비교로 올릴지** (`scripts/_scaffold_common.sh:283-327`) — 지금은
  색인 줄 수와 본문 파일 수만 맞대므로, 개수가 같은 채로 서로 어긋난 상태를 못 잡는다.
- **관리블록 락 빼앗기를 원자적으로 바꿀지** (`scripts/_managed_block.sh:94-106`) — 낡은 락을
  빼앗는 갈래가 원자적이지 않아 두 세션이 함께 임계 구역에 들어갈 수 있다.

## 손대면 안 되는 것 하나

가독성 렌즈가 **README의 잠금 문단을 줄이라고 했는데 그 지적은 반영하면 안 된다.** "그 근거가 이미
`docs/DESIGN-NOTES.md`에 있다"를 전제했는데 실제로는 없다. 지우면 근거가 사라진다. 옮기고 싶으면
`DESIGN-NOTES`의 「세션 시작 때 훅이 무엇을 하는가」 절이 자리인데, 그 절이 스스로 "README에서 옮긴
내부 동작이다"라고 규정하고 있다.

## 규율 몇 가지 — 이 레포에서 어제 실제로 밟은 것

오답노트에 다 적혀 있지만 이어받는 세션이 바로 걸릴 만한 것만 옮겨 둔다.

- **머리말의 형식 규칙 줄은 문구를 바꾸지 말고 더하기만 한다.** 문구를 바꾸면 옛 문구가 `known`에서
  빠져 본문 첫 줄로 밀려난다. 산문(규칙 블록 앞)은 바꿔도 안전하다.
- **콘솔에 찍힌 출력을 소스로 베끼지 않는다.** 이 PC 콘솔은 한글과 이모지를 깨뜨려 보여 준다.
  표시 문자는 원본 파일이나 코드포인트에서 가져온다.
- **`check`에 명령을 넣을 때는 달러 괄호를 escape 해 지연시킨다.** 안 그러면 정의 시점에 평가돼
  단언이 무조건 참이 된다. 새 검사는 고치기 전에 돌려 FAIL을 한 번 보고 나서 통과시킨다.
- **긴 것을 한 문장으로 줄일 때는 원문에 처방이 몇 개인지 먼저 센다.** 어제 82개를 다시 쓰면서
  21개에서 둘째 처방을 떨어뜨렸고, 내가 스스로는 하나도 못 잡았다. 서브에이전트에게 원문과 나란히
  대조받아야 잡힌다.
