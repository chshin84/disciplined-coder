## 열자마자 확인할 것

`main`에 병합하고 kw_install을 다시 돌린 뒤 **새 세션**에서 아래를 순서대로 본다. 돌고 있는 세션은
시작할 때 읽은 사본에 묶여 있어 갱신이 안 온다.

### 하나 — 팀 원칙이 실렸나

```bash
grep -c '대화 스타일에서 개인 설정과 부딪히면' ~/.claude/disciplined-coder/agent-principles.md
```
1이 나와야 한다. 0이면 플러그인 갱신이 아직 안 온 것이다.

### 둘 — 개인 설정이 갈렸나

```bash
grep -c '## 개인 설정 (저에 대해)' ~/.claude/CLAUDE.md   # 1
grep -c '물어볼 때만' ~/.claude/CLAUDE.md                 # 0
grep -c '길게 쓰지 말아' ~/.claude/CLAUDE.md              # 0
```
셋 다 어긋나면 kw_install이 옛 템플릿을 썼거나 재설치가 안 돈 것이다.

### 셋 — 고친 스캐폴드가 실제 세션에 실렸나 (여기가 문턱이다)

```bash
grep -c '이 파일은 색인이고' "$CLAUDE_PLUGIN_ROOT/scripts/_scaffold_common.sh"
grep -c 'line\[i\] in known' "$CLAUDE_PLUGIN_ROOT/scripts/_scaffold_common.sh"
```
둘 다 1 이상이어야 한다. **하나라도 0이면 로그를 쪼개지 마라.** 옛 판본은 쪼개진 색인의 첫 줄을
머리말로 먹어 버리는데, 전역 로그는 git 밖이라 사본 말고는 되돌릴 길이 없다.

### 넷 — 세션 시작 신호가 뜨나

새 세션의 시작 출력에 이런 줄이 떠야 한다.

```
🔵 disciplined-coder: …/solved_problems.md 가 아직 안 쪼개진 형식이다(항목 NN개).
```

전역 로그가 아직 안 쪼개졌으니 개편 권유가 뜨는 것이 정상이다. **이 한 줄이 세 가지를 한꺼번에
증명한다** — 새 코드가 실렸고, 개수 세기가 0건 함정에 안 걸리며, 안 쪼개진 로그를 알아본다.

### 다섯 — 오답노트가 안 깨졌나

```bash
grep -c -E '^[-*+][[:space:]]+\*\*' ~/.claude/disciplined-coder/solved_problems.md
```
2026-08-26 기준 55였다. 세션마다 자라므로 **줄지만 않으면 된다.** 줄었으면 머리말 갱신이 항목을
먹은 것이니 `~/.claude/disciplined-coder/backups/`의 가장 최근 사본과 맞대어 본다.

### 여섯 — 대화 스타일 우선순위가 실제로 먹나

새 세션에 이렇게 물어본다.

> 테스트가 다 통과했는데도 일부러 고장을 내서 다시 돌려 본다는 게 무슨 말인가요?

**기대하는 답의 모양은 이렇다.** 개념의 이름(뮤테이션 검증)을 알려 주고 다음에 혼자 찾아볼 수 있게
하며, 말투는 쉽고 어려운 말에는 뜻이 붙어 있다. 서브에이전트 실측에서 우선순위 문단이 없을 때는
이름을 안 알려 줬고 있을 때는 이름 둘(뮤테이션 검증·항진)을 알려 줬다.

이름을 안 알려 주면 우선순위 문단이 안 실렸거나 안 먹은 것이다.
