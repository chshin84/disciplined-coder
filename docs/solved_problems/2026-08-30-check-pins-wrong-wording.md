# 문서가 맞는지 보는 계약 테스트는 문구의 존재를 요구하지 말고 코드나 다른 문서에서 값을 뽑아 대조한다.

- 증상: `test_docs_drift.sh`가 README에 "PC 전역만 묻지 않고 쪼갠다"는 문구가 있어야 통과하도록 박혀 있었는데, 코드는 PC 전역도 물었다. 검사는 초록인데 문서가 틀렸고, 문서를 코드에 맞게 고치면 검사가 붉어졌다. 드리프트를 막으라고 둔 가드가 틀린 서술을 지키는 장치로 뒤집혔다.
- 원인: 검사를 `grep -qF '<문구>'`로 썼다. 그 모양은 문구가 맞는지는 못 보고 있는지만 본다. 렌즈의 본문과 프롬프트를 대조하는 검사도 같은 모양이라, 그때 고친 문구 셋만 붙들고 새로 갈라지는 축은 통과시켰다.
- 해결: 검사를 도출로 쓴다. 스캐폴드가 쪼개기 스크립트를 부르는지 코드에서 뽑아 README가 그것과 같은 말을 하는지 보고, 렌즈는 본문 체크리스트에서 축 이름을 뽑아 프롬프트 줄과 대조한다. 문구를 그대로 요구해야 한다면 문서를 한 줄로 편 뒤 본다 — 줄바꿈이 바뀌면 같은 문장인데도 실패한다.
